## 名称约定

本系统正式名称为：

> **爽律 Skill｜律师专业工作流系统**

在正文、说明、规则和对外介绍中，统一简称为：

> **爽律 Skill**

只有在用户实际调用时，可以进一步简称为：**爽律**

例如“调用爽律审查这份合同”“用爽律做一遍法律研究”。

---

## 一、这是什么

**爽律 Skill｜律师专业工作流系统**是一套面向律师专业工作的 Agent Skills 工作流系统。

用户在已经加载本系统的 Agent 中，可以直接说：

> **“调用爽律来做。”**

系统会根据任务自动判断应使用哪个主技能，并在必要时组合其他辅助技能完成工作。

爽律 Skill 的目标不是替律师“自动给答案”，而是把律师日常工作中应当完成的分析步骤、质量控制、对抗性审查、风险提示和交付要求，固化成可调用的专业工作流程。

---

## 二、目前包含的技能

| 技能 | 主要用途 |
|---|---|
| 法律研究与多源资料融合 | 法律、案例、观点和多源资料的检索、核验、比较与综合 |
| 刑事案件办理 | 会见、阅卷、证据、罪名、程序、辩护和阶段策略 |
| 民商事争议解决 | 请求与抗辩、争点、举证、程序、庭审、和解与执行 |
| 合同与交易工作 | 交易结构、履行流程、风险场景、合同起草、审查、修改和谈判 |
| 法律顾问与专项法律分析 | 问题重构、事实基础、法律分析、方案比较、建议和行动计划 |
| 尽职调查与专项调查 | 调查范围、资料核验、信息缺口、风险识别和交易交接 |
| 法律文书质量与格式控制 | 文书结构、论证、语言、引用、格式、版本和正式交付质量 |
| 多模态输入适配（可选） | 在当前 Agent 无法可靠读取材料时，对扫描件、音频、视频等进行输入适配 |

## 三、怎么使用

最简单的方式，是直接说明任务并调用爽律 Skill；实际调用时可以简称“爽律”，例如：

- “调用爽律审查这份合同。”
- “调用爽律分析这套刑事卷宗。”
- “调用爽律研究这个法律问题。”
- “调用爽律帮我整理会见材料并设计下一次会见提纲。”
- “调用爽律对这份法律意见做一轮对抗性审查。”

用户不需要知道内部具体有哪些技能，也不需要手工选择技能。

系统运行逻辑大致为：

```text
理解任务
→ 判断输入是否可靠
→ 选择主技能
→ 必要时组合辅助技能
→ 执行专业工作流
→ 对重要任务进行对抗性审查
→ 判断是否需要律师复核或用户明确授权
→ 按要求形成交付物
→ 复杂任务形成项目执行说明书
```

## 四、重要风险提示

### 1. 敏感案件和敏感材料应优先脱敏

真实案件材料可能包含：

- 当事人、证人、被害人等个人信息；
- 身份证号、电话号码、住址、银行卡号等敏感信息；
- 客户秘密、商业秘密；
- 未公开的侦查、诉讼或交易材料；
- 其他依法或依职业规范需要谨慎处理的信息。

在将材料提供给 AI、第三方模型、OCR、语音转写、云盘、外部 API 或其他外部服务前，应根据案件性质和使用环境进行风险判断。

**对敏感案件，原则上应先做必要脱敏，并遵循“最小必要”原则，只提供完成当前任务确实需要的内容。**

如当前任务可以使用本地、私有或用户自行控制的环境完成，应优先考虑风险更低的处理方式。

### 2. 不要因为配置了 API 或工具，就默认可以上传案件材料

API Key、账号权限或工具可用，只说明技术上能够调用，并不代表已经取得了把当前案件材料发送给第三方的授权。

涉及外部服务时，应先确认：
- 将向谁发送；
- 发送哪些材料；
- 用于什么目的；
- 是否存在日志、缓存、留存或跨境等风险；
- 是否已经取得必要授权。

### 3. 爽律 Skill 只是专业辅助工具，不能代替律师人工判断

爽律 Skill 可以帮助完成：
- 材料整理；
- 事实和证据分析；
- 法律研究；
- 工作方案比较；
- 风险提示；
- 文书起草；
- 对抗性审查；
- 质量控制。

但其输出仍可能存在：
- 事实理解错误；
- 信息遗漏；
- 法律更新不及时；
- 案例适用偏差；
- 推理偏差；
- 工具识别错误；
- AI 幻觉。

**任何拟对外使用、提交、签署或据以作出重大决定的内容，都应由具备相应专业能力的律师进行最终复核。**

### 4. 系统输出不当然构成正式法律意见

爽律 Skill 的分析、清单、草稿、风险提示和法律研究结果，原则上均属于专业工作辅助成果。

是否构成律师正式法律意见，应根据：
- 委托关系；
- 材料完整程度；
- 事实核验情况；
- 法律研究充分程度；
- 律师人工复核；
- 正式签发程序

另行判断。

### 5. 重要法律依据应核验当前有效性

法律、司法解释、规范性文件、案例和监管规则可能发生修改、废止、失效或适用范围变化。

涉及正式法律判断时，应尽量核验：
- 当前有效文本；
- 生效和失效时间；
- 过渡规则；
- 适用法域；
- 与案件行为发生时间的对应关系。

不得仅凭模型记忆作出重大法律结论。

### 6. 默认面向中国大陆法律实务

本系统目前主要围绕中国大陆法律实务工作方式设计。

涉及香港、澳门、台湾地区、外国法、国际法或其他法域时，应重新确认适用的法律体系、法律职业规则、案例效力和程序前提，不应直接套用中国大陆法律工作的默认假设。

## 五、人工判断与责任边界

爽律 Skill 可以提供分析和建议，但以下事项原则上应由律师或用户作最终决定：

- 是否认罪、认罚；
- 是否起诉、撤诉、上诉；
- 是否放弃重要权利；
- 是否接受和解及核心和解条件；
- 是否签署重大合同；
- 是否承担重大商业风险；
- 是否对外发送或提交正式法律文件；
- 是否向第三方提供敏感案件材料；
- 其他可能产生重大法律后果的决定。

系统不应冒充律师、客户或其他主体自动作出此类最终意思表示。

---

## 六、对抗性审查

对于重要任务，爽律 Skill 在形成初步结论后，应主动进行第二遍审查，例如：

- 有没有遗漏不利事实；
- 有没有反向证据；
- 有没有不同法律解释；
- 有没有更高权威或更新的来源；
- 对方最强的主张是什么；
- 哪个事实或假设变化后会使结论翻转；
- 当前风险是否只是因为信息不足而被低估。

发现重要问题后，应修正原结论，而不是仅写一句“已复核”。

---

## 七、复杂事项的续接

对于多文件、多轮或需要后续继续的事项，爽律 Skill 可以生成《项目执行说明书》，记录：

- 收到了哪些材料；
- 实际审阅了哪些材料；
- 已经做了什么；
- 形成了哪些阶段性分析；
- 产生了哪些文件；
- 哪些事项仍未解决；
- 下一步从哪里继续。

“收到材料”不等于“已经审阅”。
