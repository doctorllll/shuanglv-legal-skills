## 30 秒理解爽律

爽律 Skill 不是一组“万能提示词”，也不是法律数据库或 SaaS。它更接近一套给 AI Agent 使用的**律师专业工作流操作系统**：把材料接管、事实建模、证据审查、法律研究、策略比较、文书起草、对抗性审查、质量门控和正式交付连接成可复核的工作链。

用户不需要记住内部 Skill 名称。加载本系统后，可以直接说：

- “分析这套刑事卷宗，梳理证据问题和辩护方向。”
- “审查并直接修改这份合同。”
- “研究这个法律问题并核验案例。”
- “整理证据、提炼争点并形成代理意见。”
- “对这份文书做一轮对抗性审查。”

在支持 Agent Skills 自动激活的宿主中，上述任务**不需要先说“调用爽律”**；“调用爽律 / ShuangLaw”继续作为显式兼容入口。

系统会根据任务自动选择主技能，并在必要时组合法律研究、文书质量控制、文件处理等辅助能力。

## v0.43：从“调用一个 Skill”到“Agent 自己知道什么时候用”

v0.43 的第一项变化不是新增法律模块，而是把爽律改造成更接近 Agent Native 的能力层。`SKILL.md` 现在使用 Agent Skills 规范的 YAML frontmatter，并把“什么时候应自动使用爽律”写进 `description`。在支持 metadata 自动发现的宿主中，专业法律任务可静默激活；普通写作、日常问题或仅有法律词汇重叠的任务不应误触发。

用户可以把激活方式个性化为 `AUTO / CONFIRM / MANUAL`。默认无感不等于黑箱：需要调试时可以查看 `ActivationDecision`；宿主平台若本身不支持自动 Skill 选择，则仍需使用平台提供的绑定方式或旧“调用爽律”入口，爽律不会假装越过宿主完成了自动调用。

同时新增多 Skill 协同接口：爽律负责法律专业方法和质量控制，OCR、Web、数据库、Office 等通过 `CapabilityRequirement / SkillCollaborationRequest` 交给当前 Agent 的可用能力实现，不绑定具体厂商。

```mermaid
flowchart TD
    A[用户任务与材料] --> B[爽律入口：理解任务与自动路由]
    B --> C{主技能}
    C --> C1[刑事案件办理]
    C --> C2[民商事争议解决]
    C --> C3[合同与交易工作]
    C --> C4[法律研究与多源资料融合]
    C --> C5[法律顾问 / 尽调等]
    C1 --> D[事实 · 证据 · 法律 · 论证 · 策略]
    C2 --> D
    C3 --> D
    C4 --> D
    C5 --> D
    D --> E[对抗性审查 / 质量门 / 必要人工决定]
```

对于复杂事项，爽律还会保留来源定位、事实状态、研究轨迹和重要结论的映射，使专业判断不仅“有依据”，而且能够回到依据。

## 为什么持续升级不会把你的习惯洗掉

从 v0.42 起，爽律将 Core 与用户个性化分开。后续升级默认采用 **PRESERVE_USER**：升级核心能力，同时保留用户已经明确确认的合法工作习惯。只有发生真实冲突时才提示用户选择；事实核验、法律准确性、敏感材料风险控制和重大人工决定等 Hard Guardrails 不能被个性化关闭。

个性化可以单独查看、导出、导入、停用或重置。详见 `00_使用与调度/个性化继承与版本升级规范.md`。

### 你的模板也不会被新版洗掉

用户自己的 DOCX/Markdown 等模板属于用户资产，不属于 Core。爽律升级时系统默认模板可以改进，但**不会静默替换用户已经保存并启用的模板**。同一文种存在事项模板、用户模板和系统默认时，按“事项明确要求 → 用户长期模板 → 系统默认”解析；用户也可以在某次任务中明确改用新版默认，而不改变长期习惯。

## 从“写一个文件”到“完成一项任务”

当任务需要一整套相互关联的文书，爽律可以建立 `DeliverableBundle`，先明确哪些成果是用户要求、哪些是已经核验的必需材料、哪些只是建议或可选项；多个文件共享主体、日期、金额等信息时，使用 `SharedMatterFields`，信息发生变化后检查并回写所有受影响成果。这样做的目标不是机械“一次生成九个文件”，而是避免多文书之间事实漂移，同时不把未经核验的机构材料清单冒充当前要求。

详见 `00_使用与调度/模板资产与成套交付规范.md`。

## 法律研究：不按“数据库 / 官网 / 公众号”一刀切

爽律把“在哪里搜到”与“这个来源值不值得用”分开。数据库、官网、微信公众号、网页和知识库都可以用于发现材料；真正进入研究时，再评价**谁发布、是什么内容、是否原始、能否核验、在当前问题中承担什么 SourceRole，以及它的专业权威性、规范效力和事实证明力分别是什么**。

因此，法院、检察机关等官方公众号发布的原创典型案例、审判白皮书、司法解释解读或实务总结，不会因为“发布在公众号”就被机械降级；同样，商业数据库里的摘要也不会因为“来自数据库”就自动变成已核验原文。

重要研究采用：

```text
Issue
→ SourceRole
→ Source Discovery
→ Source Evaluation
→ Research Ladder
→ AuthorityMap / CaseMatrix
→ Search Saturation
→ Research Deliverable Profile
→ 用户模板 / 个性化表达
```

类案检索报告、法律研究备忘录、法规沿革报告和裁判趋势分析不再共用一套固定模板。若用户已经有自己的研究报告模板和写作习惯，继续由 Personalization / Template Asset Layer 优先保留。

## 一、这是什么

**爽律 Skill｜律师专业工作流系统**是一套面向律师专业工作的 Agent Skills 工作流系统。

在支持 Agent Skills 自动发现的 Agent 中，用户直接提出法律任务即可；不需要每次先说“调用爽律”。显式别名继续兼容。系统会先判断是否应激活爽律，再自动选择主技能，并在必要时组合其他能力完成工作。

爽律 Skill 的目标不是替律师“自动给答案”，而是把律师日常工作中应当完成的分析步骤、质量控制、对抗性审查、风险提示和交付要求，固化成可调用的专业工作流程。

## 三、工作流之外还有什么分析能力

爽律 Skill 不是只有流程和检查清单。每个主要业务技能同时调用一套横向分析与推理能力：

```text
事实建模
↔ 问题构造
↔ 规范定位
↔ 证据检验
↔ 规则适用
↔ 竞争解释
↔ 策略选择
↔ 论证表达
```

这是一套可回环的分析闭环，而不是固定流水线。发现新的规则、证据或反向解释后，应回到事实和问题层重新分析。详见《基础能力地图》《法律分析与推理规范》。

复杂、多文件任务还会建立通用结构化审阅记录，将材料来源、审阅状态、关键事实、反向内容、冲突、关联问题和下一步动作连接起来。它适用于刑事、民商事、合同、尽调、法律顾问和复杂研究，不限于某一种案件。

## 四、全链路可追溯

爽律 Skill 要求重要专业判断不仅“有依据”，还应**能够回到依据**。对复杂或正式任务，系统把材料、事实、证据、法律规则、案例、论证和最终交付连接起来：

```text
材料/权威来源
→ 精确来源定位
→ 事实与证据
→ 法律问题
→ 法律规则与案例
→ 可审计论证
→ 分析结论
→ 正式交付中的重要命题
```

例如，某项法律结论应能说明：依据哪条现行规则、从何处核验；关键事实来自哪份材料、哪一页或哪一组数据；引用案例与本案相似在哪里、区别在哪里；从这些依据到结论采用了什么专业推理；仍有哪些不确定性。

正式对外文书不必显示内部对象 ID，但执行记录应保留映射。详见 `00_使用与调度/全链路溯源规范.md`。

## 五、跨模块执行与回写

复杂法律任务中，爽律 Skill 不把材料审阅、法律研究、证据分析、策略比较和文书生成当成彼此独立的几次回答。上一步形成的事实、问题、来源和限制应以结构化对象向下一步交接；后一步发现的新证据、新规则、反方观点或人工决定足以改变原判断时，应回写受影响的事实、论证、结论和交付命题。

典型链条为：

```text
材料 / 来源
→ 结构化审阅
→ 事实与证据
→ 问题
→ 法律研究请求
→ 法律研究结果
→ 规则 / 案例
→ 论证
→ 分析发现
→ 策略选项 / 人工决定
→ 对抗性审查
→ 回写修正
→ 正式交付
```

需要多个行动方案时，可形成结构化选项比较；涉及用户重大处分或不可逆选择时，只形成专业建议并停在人工决定节点。详见《跨模块执行与回写规范》《策略选项与人工决定规范》。


## 六、事项工作模型与分析工具

对于复杂、多文件或跨模块任务，爽律 Skill 会把本次任务中的客户目标、材料、事实、证据、问题、法律、案例、论证、风险、策略、决定和交付命题组织为**事项工作模型**。它只是当前任务的结构化工作状态，不是长期案件数据库。

重要任务可按需形成：

- **TaskProfile**：客户目标、角色、范围、约束、优先级和完成标准；
- **IssueTree**：把笼统问题拆成可研究、可证明、可决定的子问题；
- **ReviewQuestionSet**：根据本次问题动态定义批量审阅字段，而不是机械套固定大表；
- **AuthorityMap**：整理与争点有关的法律规范、特别规则、时间效力和不同来源的作用；
- **CaseMatrix**：比较支持、反向、区别和边界案例的决定性事实与裁判理由；
- **ArgumentMap**：呈现我方与反方论证之间的支持、攻击、回应、限制和翻转点。

复杂任务通常先给出简明执行计划。只有当计划涉及重大范围选择、互斥策略、不可逆外部动作、敏感材料外发或其他需要人工决定的事项时，才要求额外确认；用户已明确要求直接执行且不存在硬性人工门控时，不应反复确认。

输入工具能够抽取实体、日期、金额、事件等信息时，可以形成“法律对象候选”辅助审阅，但 `EXTRACTED` 不等于 `VERIFIED`，重要事实仍须回到原始来源核验。

## 七、事项快速理解与核心示意图

收到合同、案件卷宗、争议材料、尽调文件等复杂材料时，爽律 Skill 原则上先形成“事项快速理解包”：一句话说明、关键主体/金额/时间、业务或事实模式、3—7 个核心关注点、重大未知和阅读导航。

存在主体关系、交易结构、资金流、时间、履行流程、证据或问题结构时，原则上至少提供一项图形化示意。图形能力不依赖模型会生图：纯文本模型也可以先生成 `DiagramSpec`；有渲染能力时优先输出 PNG，没有 PNG 能力但能创建文件时可输出自包含响应式 HTML（内嵌 SVG，可在手机浏览器打开并可选本地导出 PNG）。

图中的关键事实和关系仍受 FactStatus 和全链路溯源约束。

## 八、外部能力适配

爽律 Skill 不绑定某一家数据库、模型、知识库或 Office 工具。当前 Agent 具备专业法律数据库、官方 Web、用户知识库、OCR、文件处理或 Office 能力时，系统按统一能力契约选择和调用，并把结果转换为可溯源的公共对象。

统一逻辑为：

```text
识别任务需要什么能力
→ 检查当前运行环境实际支持什么
→ 优先选择权威、可回查、符合数据边界的能力
→ 调用并记录来源/限制
→ 能等价替代则继续
→ 只能次优完成则明示 DOWNGRADED
→ 核心要求无法满足则 BLOCKED
```

法律信源、用户知识库、文件与多模态、交付工具分别适用 `01_运行规范/` 中的能力契约。外部工具的存在不改变事实状态、法律核验、全链路溯源、敏感材料授权和人工复核要求。

## 九、怎么使用

最简单的方式，是直接说明任务并调用爽律 Skill；实际调用时可以简称“爽律”，例如：

- “调用爽律审查这份合同。”
- “调用爽律分析这套刑事卷宗。”
- “调用爽律研究这个法律问题。”
- “调用爽律帮我整理会见材料并设计下一次会见提纲。”
- “调用爽律对这份法律意见做一轮对抗性审查。”

用户不需要知道内部具体有哪些技能，也不需要手工选择技能。

系统运行逻辑大致为：

```text
理解任务
→ 判断输入是否可靠
→ 选择主技能
→ 必要时组合辅助技能
→ 执行专业工作流与分析闭环
→ 复杂任务完成跨模块交接与必要回写
→ 对重要任务进行对抗性审查并修正原分析
→ 多方案任务形成策略选项，重大事项停在人工决定节点
→ 判断是否需要律师复核或用户明确授权
→ 按要求形成交付物
→ 复杂任务形成项目执行说明书
```

## 十、工程执行增强

爽律 Skill 在专业工作流之外提供一个**可选工程执行层**，用于提高 Agent 执行的一致性。

它包括：

- **渐进式加载**：只读取当前任务真正需要的技能文件，避免无关内容占用上下文；
- **动态清单**：根据主技能、角色、阶段、任务和交付要求生成本次检查项；
- **跨模块交接与回写**：把问题、研究、论证、策略、对抗审查和人工决定连接起来，并检查后续发现是否真正更新了原分析；
- **质量门控**：在正式交付前检查现行法核验、跨模块交接、对抗审查回写、人工升级、敏感材料外部处理授权、输出契约等关键条件是否已经真实完成；
- **分析与推理约束**：重要任务检查是否真正形成问题、规则、证据、反方和可审计论证；
- **结构化审阅**：多文件、跨来源或需要横向比较的材料先进入统一审阅结构。

工程执行层不自动判断实体法律结论，不使用关键词分值冒充法律概率，也不使用本地静态数据冒充现行法核验。

支持 Python 的环境可使用 `05_工程执行层/工具/爽律 Skill执行器.py`；不支持 Python 时仍可直接按照规则文档执行。

## 十一、重要风险提示

### 1. 敏感案件和敏感材料应优先脱敏

真实案件材料可能包含：

- 当事人、证人、被害人等个人信息；
- 身份证号、电话号码、住址、银行卡号等敏感信息；
- 客户秘密、商业秘密；
- 未公开的侦查、诉讼或交易材料；
- 其他依法或依职业规范需要谨慎处理的信息。

在将材料提供给 AI、第三方模型、OCR、语音转写、云盘、外部 API 或其他外部服务前，应根据案件性质和使用环境进行风险判断。

**对敏感案件，原则上应先做必要脱敏，并遵循“最小必要”原则，只提供完成当前任务确实需要的内容。**

如当前任务可以使用本地、私有或用户自行控制的环境完成，应优先考虑风险更低的处理方式。

### 2. 不要因为配置了 API 或工具，就默认可以上传案件材料

API Key、账号权限或工具可用，只说明技术上能够调用，并不代表已经取得了把当前案件材料发送给第三方的授权。

涉及外部服务时，应先确认：
- 将向谁发送；
- 发送哪些材料；
- 用于什么目的；
- 是否存在日志、缓存、留存或跨境等风险；
- 是否已经取得必要授权。

### 3. 爽律 Skill 只是专业辅助工具，不能代替律师人工判断

爽律 Skill 可以帮助完成：
- 材料整理；
- 事实和证据分析；
- 法律研究；
- 工作方案比较；
- 风险提示；
- 文书起草；
- 对抗性审查；
- 质量控制。

但其输出仍可能存在：
- 事实理解错误；
- 信息遗漏；
- 法律更新不及时；
- 案例适用偏差；
- 推理偏差；
- 工具识别错误；
- AI 幻觉。

**任何拟对外使用、提交、签署或据以作出重大决定的内容，都应由具备相应专业能力的律师进行最终复核。**

### 4. 系统输出不当然构成正式法律意见

爽律 Skill 的分析、清单、草稿、风险提示和法律研究结果，原则上均属于专业工作辅助成果。

是否构成律师正式法律意见，应根据：
- 委托关系；
- 材料完整程度；
- 事实核验情况；
- 法律研究充分程度；
- 律师人工复核；
- 正式签发程序

另行判断。

### 5. 重要法律依据应核验当前有效性

法律、司法解释、规范性文件、案例和监管规则可能发生修改、废止、失效或适用范围变化。

涉及正式法律判断时，应尽量核验：
- 当前有效文本；
- 生效和失效时间；
- 过渡规则；
- 适用法域；
- 与案件行为发生时间的对应关系。

不得仅凭模型记忆作出重大法律结论。

### 6. 默认面向中国大陆法律实务

本系统目前主要围绕中国大陆法律实务工作方式设计。

涉及香港、澳门、台湾地区、外国法、国际法或其他法域时，应重新确认适用的法律体系、法律职业规则、案例效力和程序前提，不应直接套用中国大陆法律工作的默认假设。

## 十二、人工判断与责任边界

爽律 Skill 可以提供分析和建议，但以下事项原则上应由律师或用户作最终决定：

- 是否认罪、认罚；
- 是否起诉、撤诉、上诉；
- 是否放弃重要权利；
- 是否接受和解及核心和解条件；
- 是否签署重大合同；
- 是否承担重大商业风险；
- 是否对外发送或提交正式法律文件；
- 是否向第三方提供敏感案件材料；
- 其他可能产生重大法律后果的决定。

系统不应冒充律师、客户或其他主体自动作出此类最终意思表示。

---

## 十三、对抗性审查

对于重要任务，爽律 Skill 在形成初步结论后，应主动进行第二遍审查，例如：

- 有没有遗漏不利事实；
- 有没有反向证据；
- 有没有不同法律解释；
- 有没有更高权威或更新的来源；
- 对方最强的主张是什么；
- 哪个事实或假设变化后会使结论翻转；
- 当前风险是否只是因为信息不足而被低估。

发现重要问题后，应修正原结论，而不是仅写一句“已复核”。

## 十四、复杂事项的续接

对于多文件、多轮或需要后续继续的事项，爽律 Skill 可以生成《项目执行说明书》，记录：

- 收到了哪些材料；
- 实际审阅了哪些材料；
- 已经做了什么；
- 形成了哪些阶段性分析；
- 产生了哪些文件；
- 哪些事项仍未解决；
- 下一步从哪里继续。

“收到材料”不等于“已经审阅”。
