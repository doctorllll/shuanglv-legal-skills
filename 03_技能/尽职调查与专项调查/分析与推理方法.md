# 尽职调查与专项调查——分析与推理方法

尽调不是“收到什么就总结什么”，而是围绕交易或决策目的形成调查命题，通过多源材料验证、反证和识别缺口。

## 1. 调查问题树

从交易目的、主体、资产、权利义务、重大合同、争议、监管、人员或其他专项主题形成调查问题树。每个问题都应说明所需材料和验证路径。

## 2. 结构化审阅

多文件任务原则上使用通用结构化审阅模型，统一记录来源、时间、主体、关键事项、红旗、冲突、待核问题和来源定位，并设置业务扩展字段。

## 3. 多源核验

重要事实尽量寻找独立来源。公司提供材料、公开信息、访谈和第三方资料之间存在差异时，不通过简单多数决定事实，而是比较来源性质、时间、完整性和可验证性。

## 4. 信息缺口推理

“未发现”不等于“没有”。区分：已经充分核验后未发现、资料范围不足、对方未提供、来源受限和不可验证。对理论上应当存在却长期缺失的材料，可以形成风险提示，但不能自动推定最不利事实。

## 5. 风险形成

风险必须连接到具体事实或信息缺口，并说明触发条件、影响、可控程度、补救措施和交易后果。没有可靠数据时不生成伪精确概率。

## 6. 竞争解释与交易意义

重大红旗要检查是否存在合理替代解释；同时判断即使法律风险成立，对交易价格、交割条件、先决条件、保证、赔偿或退出权意味着什么。

## 7. 论证表达

报告应区分已核事实、待核事项、风险判断和交易建议。重大结论必须能回到原始材料或核验来源。


## 溯源要求

本技能的所有重要专业判断同时适用《全链路溯源规范》：事实应回到材料/证据和来源定位；法律规则和案例应回到权威来源及具体位置；核心分析应形成可审计的规则—事实—证据—理由链；正式交付中的重要命题应能够反向关联上游 Finding / Argument / Fact / Rule / Case 等对象。无法完成溯源时，应降低结论强度、披露限制或阻断正式交付。

## 跨模块交接与回写

- 资料审阅产生的红旗事项应连接到 `IssueRecord / RiskRecord`；需要法规、许可、案例或外部公开信息核验时再发起 `ResearchRequest`。
- 补件、新的第三方核验或管理层解释改变重大事实时，应回写原风险结论，并检查是否影响交易保护措施。
- 重大风险存在补救、先决条件、保障条款、价格调整、延期或终止等不同处置方式时，可形成 `OptionRecord`；最终交易选择仍由人工决定。

## 调查问题集与工作模型

尽调范围、重要性标准、交易目的和排除项进入 TaskProfile。资料清单不能代替调查问题：应由调查主题和风险假设生成 ReviewQuestionSet，再把结果回写 Fact / Risk / Finding。重要法律合规问题按需建立 AuthorityMap。
