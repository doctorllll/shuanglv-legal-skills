# 刑事案件办理

`skill_id: criminal-casework`

**系统版本：0.41**

> **人工核验提示：** 如果你要先理解本技能的完整方法和工作流程，请先阅读同目录《详细说明与工作流程.md》。本文件主要用于 Agent 执行。

> 本技能同时执行系统级《法律分析与推理规范》；复杂、多文件任务按《通用结构化审阅规范》建立材料工作模型。具体业务分析见同目录《分析与推理方法.md》。

当前版本以 **角色 × 阶段 × 任务** 进行业务路由，并分别处理辩护侧、被害人/控告侧及其他刑事代理事项。

> 它不是“自动写辩护词”技能；不同特殊程序仍应按照具体任务核验现行规则和材料充分程度。

---

# 1. 用途

把刑事事项从原始材料和客户需求推进为一个可管理、可追溯、分阶段迭代的案件工作系统：

> **接案/角色确认  
> → 事实与程序状态  
> → 会见/材料/阅卷  
> → 证据与法律分析  
> → 阶段目标  
> → 辩护/代理策略  
> → 程序动作  
> → 文书/沟通/庭审  
> → 结果与后续救济  
> → 结案复盘**

---

# 2. 适用场景

适用于：

- 犯罪嫌疑人/被告人辩护；
- 被害人/近亲属刑事代理；
- 刑事控告、报案及立案监督相关代理；
- 自诉/附带民事等刑事程序事项；
- 审查逮捕、羁押必要性、强制措施；
- 审查起诉、不起诉、认罪认罚；
- 一审、二审、申诉/再审、死刑复核；
- 非法证据排除；
- 涉案财物和财产性判项；
- 未成年人、涉外等特殊案件。

---

# 3. 能力边界

本技能 **负责**：

- 刑事案件角色、阶段和任务识别；
- 阶段性工作规划；
- 会见、阅卷、调查取证等律师工作流；
- 刑事证据体系和案件事实模型；
- 罪名/构成要件/出罪事由/量刑问题的组织；
- 强制措施、审查逮捕、审查起诉、庭前、庭审、二审等阶段工作；
- 程序性辩护与非法证据问题；
- 涉案财物；
- 认罪认罚；
- 业务输出需求。

本技能 **不负责**：

- 静态硬编码现行刑事法律规则；
- 在未核验法律版本时给确定法律结论；
- 把经验判断或“大数据预测”转成伪精确概率；
- 替代律师作不可自动化的价值/策略决定；
- 在材料不全时补造事实；
- 把辩护侧方法直接假定适用于被害人侧；
- 绕过 `法律文书质量与格式控制` 直接宣称正式文书已完成最终 QA。

# 4. 三维路由模型

任何刑事任务开始前，先确定：

## 4.1 律师角色（律师角色）

```text

VICTIM_REPRESENTATION
ACCUSATION_REPORTING
PRIVATE_PROSECUTION
INCIDENTAL_CIVIL
OTHER_CRIMINAL_AGENT
```


不得因为当前工作流对辩护场景覆盖较强，就把所有刑事事项强制路由为 `DEFENSE`。

---

## 4.2 阶段（案件阶段）

```text
PRE_CASE / CRISIS_RESPONSE
FILING_OR_ACCEPTANCE
INVESTIGATION
ARREST_REVIEW
POST_ARREST_DETENTION
PROSECUTION_REVIEW
PRETRIAL
TRIAL_FIRST_INSTANCE
APPEAL_SECOND_INSTANCE
RETRIAL_COMPLAINT
DEATH_PENALTY_REVIEW
EXECUTION_PROPERTY
CLOSED
```

阶段必须根据真实程序状态记录，不根据“用户想做什么”臆测。

# 6. 前置检查

任何刑事工作开始前至少检查：

1. 律师角色；
2. 案件阶段；
3. 涉案主体身份；
4. 涉嫌/指控罪名是否已知，若未知则标 UNKNOWN；
5. 强制措施状态；
6. 关键程序时间；
7. 已取得哪些法律文书；
8. 是否已会见；
9. 是否已有阅卷权/卷宗材料；
10. 是否存在紧迫期限；
11. 是否存在人身自由、证据灭失、财产处置等紧急风险；
12. 是否涉及未成年人、涉外、国家秘密等特殊情形；
13. 是否需要 现行法 核验；
14. 是否有不能读取的多模态材料；
15. 客户要求是否与律师职业规范冲突。

# 7. 端到端 工作流程

## 阶段 00 — Intake & 律师角色 界定

输出：

```text
MatterContext
CriminalMatterExtension
initial 事实记录（FactRecord）[]
initial IssueRecord[]
urgent_action_list
source_gap
engagement/risk issues
```

重点：
- 先让客户完整陈述；
- 再针对关键问题查问；
- 区分陈述事实与已核验事实；
- 明确委托角色和阶段目标；
- 不承诺结果。

详见：
《业务模块汇总.md》中的“接案与角色确认”部分

---

## 阶段 01 — 客户 Meeting / Interview

会见不是一次“问案情”。

根据阶段分别解决：

- 权利与程序；
- 基本事实；
- 指控/罪名理解；
- 权利受侵害线索；
- 证据线索；
- 阅卷后核实；
- 辩护思路沟通；
- 庭前准备；
- 认罪认罚意思与自愿性；
- 其他需求。

所有关键陈述进入：

> `事实记录（FactRecord）`，默认 `ALLEGED`，除非另有来源核验。

详见：
《业务模块汇总.md》中的“客户会见”部分

---

## 阶段 02 — File 审查 & Case Modeling

不能退化为“摘要卷宗”。

至少形成：

```text
case-file inventory
prosecution narrative
defense-relevant facts
timeline
actor/relationship map
evidence inventory
contradiction list
procedural issue list
offense/element issue list
material fact gaps
```

逻辑：

> 指控逻辑  
> → 全卷覆盖  
> → 重点突破  
> → 会见核实  
> → 比对  
> → 形成案件模型。

详见：
《业务模块汇总.md》中的“阅卷与案件建模”部分

---

## 阶段 03 — 证据 Analysis

按证明对象组织，而非仅按证据名称堆叠。

至少区分：

- 定罪事实；
- 量刑事实；
- 涉案财物事实；
- 程序性事实；
- 证据合法性/真实性事实。

每个 证据对象（EvidenceItem） 分别检查：

- authenticity；
- legality；
- relevance；
- reliability；
- 完整ness；
- chain/context；
- contradictions。

必须主动检查：
- 潜在无罪/罪轻证据；
- 单向论证；
- 循环推理；
- 仓促概括；
- 过度评价；
- 证据异常变化；
- 间接证据链缺口。

详见：
《业务模块汇总.md》中的“证据分析”部分

---

## 阶段 04 — Offense / 法律 Analysis

输入：

```text
material facts
evidence findings
charged/suspected offense
研究结果（ResearchResult）
```

输出：

```text
element matrix
factual fit / non-fit
subjective element analysis
objective element analysis
exculpatory grounds
crime-number / accomplice / unit-crime issues
temporal-law issues
interpretation issues
sentencing issues
alternative characterization
human-review points
```

原则：

> **事实建构 → 规范解释 → 构成要件/出罪事由 → 涵摄 → 反向检验**

任何现行罪名、司法解释、入罪/出罪标准必须调用：

> `法律研究与多源资料融合`

详见：
《业务模块汇总.md》中的“罪名与刑法分析”部分

---

## 阶段 05 — 调查取证 / 证据 Preservation

处理：

- 证据线索来源；
- 自行调查；
- 申请调取；
- 言词证据；
- 客观证据；
- 网络/电子材料固定；
- 新证据提交；
- 隐私/秘密/执业风险；
- 证据可能反向不利的风险。

任何调查动作先做：

> **legality + necessity + benefit/风险 + 保全 计划**

详见：
《业务模块汇总.md》中的“调查取证”部分

---

## 阶段 06 — Compulsory Measures / Arrest 审查

阶段目标不能简化为“写取保申请”。

至少同步分析：

```text
offense / criminal responsibility
evidence sufficiency
custody necessity
social-danger considerations
health/special circumstances
alternative measures
favorable materials
communication plan
post-decision follow-up
```

具体法定条件、时限和程序：

> 必须 现行法 核验，不能照抄历史资料中的固定数字。

详见：
《业务模块汇总.md》中的“强制措施与逮捕审查”部分

---

## 阶段 07 — 审查起诉

核心任务：

- 阅卷；
- 会见与核实；
- 调查取证；
- 非法证据问题；
- 事实/证据/定性分析；
- 不起诉路径；
- 罪轻/变更定性；
- 认罪认罚；
- 与检察官沟通；
- 辩护意见提交策略。

不得把“是否和盘托出全部辩点”写成固定答案，应作为 策略 Decision。

详见：
《业务模块汇总.md》中的“审查起诉”部分

---

## 阶段 08 — 庭前 & 庭审

庭前形成：

```text
trial issue map
questioning outline
cross-examination outline
defense evidence list
application list
illegal-evidence issue
case/academic research pack
defense argument architecture
client preparation record
```

庭审按：

> **发问 → 质证/举证 → 事实之辩 → 证据之辩 → 法律之辩 → 量刑/程序/财产问题**

组织。

详见：
《业务模块汇总.md》中的“庭前与庭审”部分

---

## 阶段 09 — 认罪认罚

独立进入该模式时，不以“是否签具结书”作为唯一问题。

至少分析：

- 现有案件信息和证据；
- 指控与争议点；
- 当事人真实意思；
- 自愿性；
- 认罪范围；
- 法律后果；
- 量刑协商；
- 同案平衡；
- 是否仍存在实质性辩护空间；
- 反悔/上诉等程序影响。

**2026 年认罪认罚指导意见已经修订。**
每次调用必须核验最新法源。

详见：
《业务模块汇总.md》中的“认罪认罚”部分

---

## 阶段 10 — Procedural / Illegal 证据

非法证据问题与普通证据证明力问题分开。

形成：

```text
illegal_method allegation
source/material
procedural stage
exclusion target
clue/material threshold
burden issue
recording/video issue
hearing/application plan
fallback argument
```

详见：
`业务模块汇总.md 中的“非法证据排除”部分`

---

## 阶段 11 — Property

形成独立 Property Subcase：

```text
asset
owner
relationship_to_offense
measure
procedure
third_party_interest
disposition status
criminal judgment effect
execution issue
remedy
```

不得把财产问题放到主案结尾一笔带过。

详见：
《业务模块汇总.md》中的“涉案财物”部分

---

## 阶段 12 — 二审/上诉 / 特殊程序 Procedures

二审至少重新执行：

> 卷宗 → 会见 → 新证据/新问题 → 一审判断审查 → 是否争取开庭 → 二审辩护路径。

死刑复核、未成年人、涉外等：

> 使用专用 `extensions` + 现行法 Pack

而不是用一般一审 工作流程 生硬套用。

详见：
《业务模块汇总.md》中的“二审与特殊程序”部分

---

## 阶段 13 — 被害人代理 / 刑事控告 / 立案监督

该分支采用独立工作流：

```text
role and client objective
→ harm / transaction / conduct fact model
→ criminal path + civil-criminal boundary
→ reporting proof propositions
→ structured material review + evidence package
→ evidence gaps / preservation / investigation
→ jurisdiction / filing prerequisites
→ reporting materials + attachment index
→ filing status / supplementary materials
→ supervision or remedy when necessary
→ recovery / property track
→ victim participation after filing
```

不能把辩护逻辑反过来直接当控告逻辑，也不能把委托人的犯罪定性直接当作已证实事实。

详见：
- 《业务模块汇总.md》中的“被害人代理与刑事控告”部分；
- 《被害人代理与刑事控告工作流.md》。

# 9. 决策规则

## CC-R001 角色优先
先确认律师角色，后调用业务 工作流程。

## CC-R002 阶段优先
刑事策略必须考虑所处程序阶段；同一问题在不同阶段的可用动作和目标不同。

## CC-R003 会见陈述不自动变成 VERIFIED
客户/嫌疑人陈述先作为来源明确的 事实记录（FactRecord）。

## CC-R004 阅卷不是摘要
必须同时重构指控逻辑、辩护相关事实、证据链、矛盾和程序问题。

## CC-R005 证据审查不得只做“三性打分”
真实性/合法性/关联性/可靠性/完整性及证据链分维审查。

## CC-R006 先理解控方证明结构，再选择辩护攻击面
避免看到单份有利材料就形成全案策略。

## CC-R007 不能只找无罪证据
还应分析罪轻、程序、强制措施、财产、量刑和备选方案。

## CC-R008 调查取证先做风险评估
不因证据“可能有利”就当然实施调查。

## CC-R009 现行法和程序时限动态核验
书籍中的法律规则和时间节点不得直接固化为 L0。

## CC-R010 认罪认罚不等于停止辩护
必须独立评估证据、法律、意思、自愿性和量刑协商。

## CC-R011 反向事实/证据必须入模
不利材料不得静默删除。

## CC-R012 财产问题独立建模
人身责任和财产责任/处置分开。

## CC-R013 正式文书不从原始卷宗直接生成
正确调用链：

> 原始材料 → 案件模型 → 研究/证据/法律分析 → 分析结果 → 文书。

## CC-R014 重大策略必须有人类律师确认
例如：
- 是否无罪/罪轻主次组合；
- 是否认罪认罚；
- 是否主动提交可能双刃剑证据；
- 是否披露全部辩点；
- 是否上诉；
- 是否采取高风险调查动作。

# 10. 人工升级

以下情形必须停止自动推进或至少标 人工复核（HUMAN_REVIEW）：

- 律师角色冲突；
- 当事人与委托人意见冲突；
- 关键事实严重矛盾；
- 关键卷宗缺失；
- 法律状态不确定；
- 证据可能系虚假、伪造或来源高风险；
- 调查取证可能侵犯隐私、秘密或触及执业风险；
- 认罪认罚意思与证据/法律判断明显冲突；
- 策略需要权衡泄露辩点风险；
- 当前 运行环境 无法可靠读取关键音视频/电子证据；
- 涉及死刑、重大未成年人、涉外/国家秘密等高风险特殊程序；
- 被害人/控告事项存在重大定性、程序路径、证据充分性或立案监督策略争议，需要律师进一步判断。
