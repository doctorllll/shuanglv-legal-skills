# 刑事案件办理——分析与推理方法

刑事案件分析必须随律师角色变化。辩护、被害人代理和刑事控告共享事实、证据、法律研究和推理能力，但证明目标、程序位置和策略方向不同。

## 1. 事实建模

先从材料构建可追溯的事件、主体、资金/财物流、通信、行为过程、主观事实基础和程序事实。任何一方陈述均不因立场自动成为已核验事实。

辩护侧同时重构控方指控叙事；控告/被害人侧同时重构拟主张的犯罪事实和损害事实，但不得把委托人的定性直接当作案件事实。

## 2. 问题构造

辩护侧重点形成：指控待证命题、构成要件、证据链、程序问题、出罪/罪轻路径和策略问题。

控告/被害人侧重点形成：可能犯罪事实、民刑边界、管辖与受理、证据充分性、证据保全、立案监督、追赃挽损和后续参与问题。

## 3. 规范定位

所有具体罪名、入罪/追诉标准、程序规则、司法解释和时间效力均运行时核验。刑法解释必须经过罪刑法定门控。

## 4. 证据检验

先定义待证命题，再审证据。重要分析包括：来源独立性、同源信息、印证、矛盾、陈述变化、间接证据链、预期证据缺失和替代解释。

控告侧也必须做证伪：如果客户的犯罪解释不成立，现有材料还可能支持什么民商事、行政或其他事实模型？

## 5. 规则适用

对罪名使用要件矩阵，不先定罪名后裁剪事实。允许比较多个竞争定性，但任何不利于被追诉人的解释不得越过文字可能涵义或以类推方式扩大入罪。

## 6. 竞争解释

辩护侧构建最强控方模型；控告侧构建最强“不构成犯罪/证据不足/属民事纠纷”模型；被害人代理同时评估侦控机关可能如何理解同一组事实。

每一重要方向至少记录：支持材料、反向材料、替代解释、证据缺口和结论翻转点。

## 7. 策略选择

辩护侧关注辩点披露时机、补侦风险、认罪认罚、强制措施、庭审价值等；控告侧关注报案/控告路径、证据先行保全、管辖、是否补充材料、立案监督、追赃挽损和民刑路径协调。

重大策略必须人工复核。

## 8. 论证表达

辩护意见、控告材料、被害人代理意见均应来自已形成的事实—证据—法律模型。立场不同不意味着可以删除重大不利事实或把未知事实写成确定事实。


## 溯源要求

本技能的所有重要专业判断同时适用《全链路溯源规范》：事实应回到材料/证据和来源定位；法律规则和案例应回到权威来源及具体位置；核心分析应形成可审计的规则—事实—证据—理由链；正式交付中的重要命题应能够反向关联上游 Finding / Argument / Fact / Rule / Case 等对象。无法完成溯源时，应降低结论强度、披露限制或阻断正式交付。

## 跨模块交接与回写

- 罪名、程序、证据规则或类案问题需要外部核验时，由当前 `IssueRecord` 发起 `ResearchRequest`，研究结果回填对应论证，不另起一套脱离案件事实的分析。
- 新卷宗、新笔录、新鉴定、资金或电子数据改变事实状态时，先更新 `FactRecord / EvidenceItem`，再检查受影响的罪名分析、证明体系、辩护/控告策略和正式文书。
- 对抗性审查发现控方/辩方/被害人侧的关键模型存在实质漏洞时，应修订原 `ArgumentRecord / Finding`，不能只在报告末尾追加风险提示。
- 认罪认罚、是否上诉、是否接受和解或其他重大处分等事项，分析形成选项后停在 `DecisionRecord` 人工节点。

## 事项工作模型补充

复杂刑事任务应把角色、程序阶段和客户目标写入 TaskProfile；以 IssueTree 区分实体、证据、程序和策略问题。卷宗量大时依据争点动态生成 ReviewQuestionSet，而不是固定列摘要。罪名、证明体系或控告路径存在竞争解释时，可用 ArgumentMap 明确控方/辩方/被害人侧主张、反驳和翻转点。
