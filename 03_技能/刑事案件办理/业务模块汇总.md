# 业务模块汇总

## 00-角色-阶段-任务路由

## 输入
- MatterContext
- CriminalMatterExtension
- TaskRequest

## 路由r

### Step 1 律师角色
先确定 DEFENSE / VICTIM_REPRESENTATION / ACCUSATION_REPORTING 等。

### Step 2 阶段
根据程序材料和可核验事实确定。

### 第三步：紧急程度
优先识别：
- 人身自由；
- 法定期限；
- 证据灭失；
- 涉案财物处置；
- 会见/阅卷受阻；
- 即将签署认罪认罚材料；
- 即将开庭。

### Step 4 任务 Graph
生成：
```text
must_do_now
should_do_this_stage
can_defer
depends_on
human_decision
```

## 输出
Criminal阶段State

## 规则
不允许“用户要求写一个取保申请书”直接跳过案件阶段和证据/法律基础检查。

## 01-接案与角色确认

## 工作流程
1. 让陈述人先完整陈述；
2. 再通过问题澄清；
3. 分离：
   - 亲历事实；
   - 转述；
   - 推测；
   - 律师评价；
4. 记录关键时间、主体、行为、文件和程序状态；
5. 确定律师角色；
6. 识别紧急事项；
7. 形成 Initial 问题/争点 图；
8. 给出当前可做/不可做/需补资料事项；
9. 记录委托边界和职业风险。

## 输出
- initial 事实记录（FactRecord）[]
- role/阶段
- urgent 行动 清单
- missing 材料 清单
- engagement 风险 清单

## 禁止
- 结果承诺；
- 仅根据家属转述确认罪名/案情；
- 客户情绪替代事实核验。

## 02-客户会见

## 阶段-aware design

### 调查取证
- 程序和权利；
- 基本事实；
- 被讯问情况；
- 权利受侵害线索；
- 证据线索；
- 身体/羁押状态；
- 紧急需求。

### 审查起诉
- 结合阅卷核实；
- 争议事实；
- 证据解释；
- 定性与辩点沟通；
- 认罪认罚问题。

### 庭审
- 起诉内容确认；
- 庭审流程；
- 发问和质证准备；
- 陈述/最后陈述；
- 辩护策略协调。

## 数据规则
当事人陈述：
> 事实记录（FactRecord）.fact_status = ALLEGED

只有被其他可靠材料核验后才能 VERIFIED。

## 会见记录
记录：
- 日期/时间/place
- participants
- 阶段
- questions/topics
- 材料 statements
- changes from prior statements
- rights/procedure advice
- requests
- follow-up
- 风险 问题

## 风险
传递物品、信息、案卷内容、签署文件等必须单独走职业规范检查。

## 03-阅卷与案件建模

## 不是摘要任务

至少产生六层结果：

1. **Inventory**
   - 卷宗目录
   - 文件缺失
   - 重复/版本

2. **Prosecution Narrative**
   - 指控事实
   - 罪名
   - 证明结构
   - 关键证据

3. **事实 Model**
   - timeline
   - actors
   - events
   - transactions
   - communications

4. **Defense-Relevant 分析结果**
   - 有利事实
   - 不利事实
   - 矛盾
   - 缺口

5. **证据 图**
   - 证据对象（EvidenceItem）
   - proposition links

6. **问题/争点 图**
   - 事实
   - 证据
   - 法律
   - 程序
   - 量刑
   - 财产

## 阅读顺序
先理解指控逻辑，但随后必须全卷覆盖和重点突破；不能只围绕预设辩点选择性阅读。

## 迭代
阅卷 ↔ 会见 ↔ 研究 ↔ 再阅卷。

## 04-证据分析


## 证明对象优先
先定义待证命题：
- 定罪事实
- 量刑事实
- 涉案财物
- 程序事实
- 证据性事实

再审证据。

## 单项证据
分别审：
- 来源/authenticity
- collection legality
- relevance
- reliability
- 完整ness
- custody/transfer/context
- proposition fit
- contradictions

## 全案分析
必须检查：
- 单份证据问题
- 相互印证是否真实独立
- 信息是否同源
- 间接证据链
- 是否遗漏潜在无罪证据
- 单向论证
- 循环推理
- 仓促概括
- 过度评价
- 合理怀疑

## 执行规则
当前先作为 刑事案件办理 内部模块。
等 民商事争议解决 施工后，评估是否抽取为共享：
> 共享证据推理能力

## 05-罪名与刑法分析


## 流程
1. 构建可被证据支持的案件事实；
2. 明确拟适用规范及版本；
3. 解释构成要件；
4. 建 要件矩阵；
5. 涵摄；
6. 检查出罪/阻却/不归责事由；
7. 检查共同犯罪、单位犯罪、罪数等；
8. 检查法益、刑民边界等实质争点（仅在法理上允许范围内）；
9. 对扩张解释/类推风险进行罪刑法定检查；
10. 形成主方案 + 备选方案。

## 规则
刑法解释不得以“实质合理”为由越过罪刑法定边界。

## 现行法
所有罪名、司法解释、追诉/入罪标准：
> 必须调用 法律研究与多源资料融合。

## 06-调查取证

## 主要信源
- 卷宗
- 当事人/委托人
- 专业人士
- 类案比较
- 公开资料

## Pre-行动 风险 门控
任何调查动作先判断：
```text
legality
authority/consent
necessity
expected value
risk of false evidence
risk of adverse evidence
privacy/secrets
preservation method
submission strategy
```

## 输出
- investigation 计划
- 来源 locator
- raw record
- chain/integrity information
- 证据对象（EvidenceItem） candidate
- 风险 note
- submission 决策 = 人工复核（HUMAN_REVIEW） when 材料

## 07-强制措施与逮捕审查

## 分析层次
1. 是否存在犯罪/刑事责任争议；
2. 现有证据状态；
3. 人身危险/妨害诉讼风险相关事实；
4. 是否存在不宜羁押/特殊情况；
5. 替代性措施；
6. 有利材料；
7. 与办案机关沟通；
8. 后续羁押必要性/变更措施。

## 输出
- custody issue 图
- supporting 证据 package
- 法律 研究 result
- 阶段 行动 计划
- written opinion request

## 关键
历史实务资料中的固定期限表达只能作为线索，具体期限必须核验现行法。
实际案件必须按：
> 当前法律 + 个案程序事实
实时计算期限。

## 08-审查起诉

## 必做事项
- file 审阅 refresh
- meeting/verification
- investigation if needed
- illegal 证据
- offense 分析
- sentencing
- property
- non-prosecution options
- 变更 characterization / lesser responsibility
- plea leniency
- prosecutor communication
- submission strategy

## 策略决策
是否一次性公开全部辩点不是固定 规则。

必须考虑：
- 辩点成熟度
- 证据可验证性
- 检方回应空间
- 是否可能补强控方缺口
- 阶段目标
- 后续庭审价值

该决定默认 人工复核（HUMAN_REVIEW）。

## 09-庭前与庭审


## 庭前材料包
- trial issue 图
- 客户 preparation
- questioning outline
- cross-examination outline
- 抗辩 证据
- applications
- 非法证据问题
- case 研究
- 抗辩 argument architecture
- 材料 index

## 发问
从核心辩点倒推：
> 需要证明/削弱什么事实 → 谁能回答 → 如何设计问题。

不要：
- 不知道答案却无策略地贸然问；
- 与证人/被告人争辩；
- 用法律结论代替事实问题。

## 庭审论证
按：
> 事实 → 证据 → law
建立主轴。

事实、证据、法律可以形成不同攻击面，但应服务统一 Case Theory。

## 文书
书面辩护词由 分析结果/论证结构 生成，再交 法律文书质量与格式控制。

## 10-认罪认罚

现行 L0：2026-07-17 五部门修订指导意见，必须动态核验。

## 决策矩阵
- 当前可得案件信息
- 证据 strength / gaps
- offense dispute
- accused person's true intention
- voluntariness
- 范围 of admission
- sentencing baseline and negotiation
- co-defendant balance
- 程序 consequences
- remaining 抗辩 问题
- reversal/appeal implications

## 禁止的捷径
不得：
> “认罪认罚 = 认罪 + 签具结 + 结束实质辩护”。

## Human 审查
是否认罪认罚属于重大策略决定。
Agent 可分析，不得替当事人/律师最终选择。

## 11-非法证据排除

## 分别处理的问题
1. 目标证据是什么；
2. 被指称违法方法；
3. 有哪些线索/材料；
4. 当前程序阶段；
5. 谁承担何种证明/说明责任（现行法 核验）；
6. 是否有同步录音录像/程序材料；
7. 如何申请/审理；
8. 排除失败后的证据证明力备选攻击。

## 输出
- illegal-证据 问题卡片
- 来源/证据 package
- 程序 行动
- 备选 证据 argument

## 规则
“证据不可信”和“证据应依法排除”不是同一个判断。

## 13-二审与特殊程序

## 二审

重新执行：
- 一审裁判拆解
- 全案卷宗/新增材料
- 会见
- 新事实/新证据
- 程序错误
- 法律适用
- 是否争取开庭
- 书面/开庭辩护路径

不得把二审做成：
> “把一审辩护词换成上诉状”。

## 特殊程序
- DEATH_PENALTY
- MINOR
- FOREIGN_RELATED
- RETRIAL_COMPLAINT

第一版以专用 extensions + 现行法 Pack 处理。

其中申诉/再审当前规则覆盖不足，应标 PARTIAL/LOW。
