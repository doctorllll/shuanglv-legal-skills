# 法律研究与多源资料融合

`skill_id: legal-research-and-source-fusion`

**系统版本：0.40**

> **人工核验提示：** 如果你要先理解本技能的完整方法和工作流程，请先阅读同目录《详细说明与工作流程.md》。本文件主要用于 Agent 执行。

> 本技能同时执行系统级《法律分析与推理规范》；复杂、多文件任务按《通用结构化审阅规范》建立材料工作模型。具体业务分析见同目录《分析与推理方法.md》。

---


# 用途

把一个具体法律问题从“需要搜索”推进为：

> **问题已拆解、信源已路由、检索已执行、来源已核验、正反边界已研究、结果已融合、缺口和限制已显式记录**

的 `研究结果（ResearchResult）`。

本技能 不是数据库搜索器，也不是最终业务判断器。

---

# 适用场景

在以下情形调用：

- 需要确认现行法律、历史版本、司法解释、政策或监管规则；
- 需要寻找类案、指导案例、案例库案例或裁判趋势；
- 需要研究学说、实务观点、争议和分歧；
- 需要把公开网络、专业文章、用户私域资料等多源信息融合；
- 业务技能 需要一个可追溯的法律研究包；
- 需要核验现有草稿中的法律依据或来源。

---

# 能力边界

本技能 **负责**：

- 问题/争点 界定；
- 来源 Routing；
- 检索式设计；
- 检索；
- 来源 Validation；
- 权威性与相关性分析；
- Adversarial 研究；
- Cross-来源 Synthesis；
- 研究 Trace；
- 来源缺口；
- 研究 Saturation 状态判断。

本技能 **不负责**：

- 最终定罪/无罪判断；
- 最终诉讼策略；
- 是否接受合同风险；
- 最终商业决策；
- 未经业务技能 的完整正式法律意见；
- 伪造数据库访问、文件读取或已完成的检索。

---

# 输入

最低输入：

```text
IssueRecord
MatterContext（如有）
available Source Registry
RuntimeCapabilityProfile
```

可选输入：

```text
事实记录（FactRecord）[]
证据对象（EvidenceItem）[]
existing SourceCard[]
private knowledge source references
requested_scope
time_scope
jurisdiction
```

若法律问题依赖关键事实但事实仍 UNKNOWN / DISPUTED，应在检索前标记依赖关系，不得默认为某一事实成立。

---

# 前置检查

1. 法域是否明确；
2. 行为 / 争议发生时间是否明确；
3. 研究目标是：
   - 现行规则；
   - 历史规则；
   - 类案；
   - 观点；
   - 趋势；
   - 综合法律分析；
4. 是否存在用户限定：
   - Authoritative Only；
   - Private Only；
   - Open 范围；
   - Specified 来源；
5. 当前 运行环境 实际能访问哪些来源；
6. 是否涉及高风险、强时效或正式法律意见；
7. 是否存在必须先解析的附件或案件材料。

# 工作流程

## 01 问题/争点 界定（问题识别）

把一个宽泛问题拆成独立可检索 问题/争点。

每个 问题/争点 至少记录：

```text
question
jurisdiction
material facts
time
desired answer type
dependent issues
unknown facts
```

禁止把整个案情原封不动扔进数据库后依赖“智能搜索”。

---

## 02 来源 Routing（信源路由）

默认：

> `Auto 范围`

根据 问题/争点 自动选择当前：

> **可用 + 已授权 + 相关**

的来源。

来源分为：

1. 法律 Authority 来源
2. 案例来源
3. 专业评论
4. Public / Platform 来源
5. Private 知识 来源

### 路由原则

- “法律是什么” → 官方法源优先；
- “法院怎么适用” → 案例源；
- “为什么这样解释 / 有何分歧” → 专业观点；
- “发生了什么 / 行业出现什么现象” → 公共平台；
- “本案/本项目发生了什么” → 私域和案件材料。

任何公开文章均不得自动升级成 L0。

---

## 03 检索式设计（检索工程）

至少准备：

- 核心法律概念；
- 同义词 / 旧称 / 专业术语；
- 法条号 / 规范名称；
- 主体 / 行为 / 法律关系；
- 争议焦点；
- 决定性事实；
- 类案比较点；
- 支持词；
- 反向词；
- 例外 / 排除词；
- 时间范围。

### 查询路径

优先形成多条独立路径，而不是不断修改同一个关键词：

```text
Q1 问题/概念路径
Q2 法条关联路径
Q3 案例关联路径
Q4 关键事实路径
Q5 引文/脚注滚雪球路径
Q6 反向/例外路径
```

---

## 04 Multi-来源 检索（多源检索）

对每条路径保存 `ResearchTrace`。

不得只保存“最终找到的好资料”。

同时保存：

- query；
- 来源 / adapter；
- filter；
- 结果数量；
- selected；
- rejected；
- rejection reason；
- next-search trigger。

---

## 05 来源 Validation（来源核验）

### 法律规范

建立 `Norm Package`：

```text
核心规范
定义
相关条款
例外
特别规定
配套解释
历史版本
生效/失效时间
过渡条款
冲突规则
适用范围
```

至少检查：

- 是否为真实法源；
- 是否现行；
- 行为发生时适用哪个版本；
- 位阶；
- 时间效力；
- 地域；
- 对人；
- 对事项；
- 新旧法；
- 一般/特别；
- 配套司法解释或规范。

### 案例

至少检查：

- 来源真实性；
- 裁判是否生效 / 当前状态；
- 法院 / 发布机关；
- 时间；
- 适用法律背景；
- 法律问题同一性；
- 决定性事实相似性；
- 规范背景相似性；
- 区分点；
- 拟使用目的。

### 观点 / 专业文章

至少记录：

- 作者；
- 职业 / 机构；
- 时间；
- 出版 / 发布平台；
- 是否有来源依据；
- 是否存在利益相关；
- 属于学术观点、实务观点还是个人看法。

---

## 06 Relevance & Authority Analysis（相关性与权威性）

不使用单一百分比总分。

分别判断：

```text
authority
issue_match
material_fact_match
temporal_fit
normative_background_fit
intended_use
```

案例推荐：

- STRONG
- MEDIUM
- WEAK
- NOT_RECOMMENDED

必须附理由与区分点。

---

## 07 Adversarial 研究（对抗性检索）

每个关键 问题/争点 原则上必须主动检查：

- 支持（SUPPORT）
- 反向（COUNTER）
- 边界（BOUNDARY）
- 例外（EXCEPTION）
- 分歧（DIVERGENCE） / SPLIT

如果用户明确只要求“找支持材料”，仍须在结果中标注：

> 本次 范围 为单向检索，不构成完整法律研究。

正式法律意见前不得把单向检索标为 `SATURATED`。

---

## 08 Cross-来源 Synthesis（跨源融合）

按 问题/争点 组织，而不是按数据库组织。

建议顺序：

```text
Issue
→ L0 Norm Package
→ Case Matrix
→ Viewpoint Matrix
→ Support / Counter / Exception
→ Key Differences
→ Source Gaps
→ Provisional Research Conclusion
```

不得把：

> “北大法宝找到……；微信找到……；网页找到……”

作为最终研究结构。

---

## 09 研究 Saturation（研究停止判断）

当前为 **L3 设计 Heuristic**，必须通过真实测试校准。

一个关键 问题/争点 只有在下列条件基本满足时才可标记 `SATURATED`：

1. 核心法律规范已核验；
2. 关键定义、例外、特别规则、历史版本已检查；
3. 至少存在两条独立检索路径；
4. 关键案例来源已覆盖；
5. 支持（SUPPORT） / 反向（COUNTER） / 边界（BOUNDARY） / 例外（EXCEPTION） 已主动检查；
6. 权威来源间的冲突已识别；
7. 连续扩检没有产生会改变现有法律规则或关键分析的新材料；
8. 仍存在的 来源缺口 不足以改变研究用途下的结论；
9. 高风险问题不存在未核验 L0 法源。

任何一个重大条件不满足：

> `INCOMPLETE`

来源本身不可得：

> `BLOCKED`

需要律师作价值/策略决定：

> `HUMAN_REVIEW_REQUIRED`

---

## 10 研究 交接（研究交付）

生成符合 CIS-0.1 的 `研究结果（ResearchResult）`。

业务技能 接收后必须能知道：

- 哪些是确定规则；
- 哪些是案例支持；
- 哪些是观点；
- 哪些是推断；
- 哪些存在分歧；
- 哪些没有查完；
- 哪些必须人工判断。

---

# 决策规则

## R-01 当前法优先验证

涉及法律结论时，不得仅凭论文、律师文章或其他二手资料确认现行法。

## R-02 历史行为必须做 Temporal 核验

行为时间与当前时间不同时，必须检查：

- 当时法；
- 修法时间；
- 过渡条款；
- 溯及力。

## R-03 单一数据库不等于完整检索

数据库覆盖范围有限。对重要研究，至少考虑独立来源路径。

## R-04 观点不能替代法源

观点可以解释规则，不能伪装成规则本身。

## R-05 案例相似性以“法律评价后的决定性事实”为核心

不因表面事实相似即认定为类案。

## R-06 反向案例必须进入 区分分析

与预期结论不一致的案例不得静默删除。

## R-07 Private 知识 不自动优先

用户历史文件可能过时、只代表过去观点或具体案件策略，必须标记时间与用途。

## R-08 无法核验就降级

找不到原文、有效状态或完整上下文时：

> UNVERIFIED / 不完整（INCOMPLETE）

不得自行补齐。

# 输出 Schema

主输出：

> `研究结果（ResearchResult）`

配套输出：

- 信源卡片[]
- LegalRule[]
- CaseCard[]
- ResearchTrace[]
- 来源缺口 Analysis
- 权威来源矩阵 / 类案矩阵（需要时）

---

# 失败与人工升级

触发人工升级：

1. 官方法源存在冲突且无法依位阶/时间解决；
2. 关键法律状态无法确认；
3. 关键事实条件不明导致研究结论会发生实质变化；
4. 新型问题缺少可依赖权威来源；
5. 研究结果将直接用于高风险正式法律意见但仍存在重大 缺口；
6. 案例分歧需要价值衡量或诉讼策略选择；
7. 工具声称已检索但无法提供可核验 研究 Trace；
8. 私密/受限来源超出当前授权。

---

# 质量检查

交付前至少检查：

- [ ] 问题/争点 是否明确；
- [ ] 当前法是否核验；
- [ ] 历史版本是否需要核验；
- [ ] 核心法源是否来自权威来源；
- [ ] 是否检索了案例；
- [ ] 案例是否做决定性事实比较；
- [ ] 是否主动找反向/例外；
- [ ] 观点与法源是否分开；
- [ ] 每个重要结论是否可追溯；
- [ ] 是否记录 来源缺口；
- [ ] 充分（SATURATED） 是否满足停止条件；
- [ ] 是否存在需要人工判断的内容；
- [ ] 是否把未核验信息写成确定事实。

## 外部法律信源

本技能不绑定特定法律数据库。需要现行法、案例或权威资料时，先按 `01_运行规范/外部能力适配规范.md` 和 `01_运行规范/法律信源能力契约.md` 检查当前 Agent 实际可用的官方来源、专业授权信源或其他可靠来源。工具结果必须回到 SourceCard/SourceLocator 等可追溯对象；检索摘要不能直接冒充原文核验。
