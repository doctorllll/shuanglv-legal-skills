# 核心规则汇总

## 权威性与有效性核验

## A. 法律规范

必须建立或检查：

1. 原文来源；
2. 发布机关；
3. 文号；
4. 发布/生效时间；
5. 当前状态；
6. 行为发生时状态；
7. 修订/废止；
8. 过渡；
9. 位阶；
10. 特别法；
11. 地域/主体/事项；
12. 配套司法解释/实施规范。

## B. 案例

分别记录：

- 发布/裁判机关；
- 是否官方案例；
- 是否生效；
- 审级；
- 法律问题；
- 决定性事实；
- 当时法律背景；
- 裁判规则/理由；
- 区分点；
- 使用目的。

## C. 专业观点

至少检查：

- 作者；
- 机构；
- 时间；
- 专业背景；
- 发布渠道；
- 论据；
- 引用法源；
- 潜在利益相关。

## D. 公共平台

默认只用于：

- 线索发现；
- 现象观察；
- 观点发现；
- 事实候选。

需要进入法律结论时必须再核验。

## 类案比较与区分规则

## 检索
至少考虑：
- keyword
- statute-linked
- case-linked

## 类案比较维度

```text
same legal issue
material facts
dispute focus
applicable rule
normative background
holding / rule
reasoning
authority
time / jurisdiction
intended use
```

禁止单一总分。

## 关键事实检验
对候选关键事实执行反事实：
> 如果删除/改变该事实，裁判理由或结果是否可能改变？

若是，则提高其 材料 事实 优先级。

## 规则提取
裁判规则不得：
- 只抄裁判结果；
- 只抄裁判要点；
- 脱离裁判理由；
- 剥离决定性事实；
- 抽象到高于其依托法规范的层级。

## 区分分析
对不利类案依次检查：
1. 材料 fact difference
2. 争议问题差异
3. 法律规则/背景差异
4. 案例效力/权威性缺陷
5. 推理缺陷/冲突

## 能力边界
案例服务法律论证，不证明本案事实。

## 解释与论证复核规则

## 适用场景
当 问题/争点 的结论依赖：
- 法律概念含义；
- 多种解释可能；
- 一般条款/不确定概念；
- 类推；
- 目的性限缩；
- 新型案件；
- 案例规则扩展；
时触发。

## 内部审查顺序

```text
0. Fact–Norm Iteration
1. Wording / Semantic Range
2. Context / System
3. History / Legislative Materials
4. Norm Purpose
5. Result / Consequence Check
6. Existing Cases / Doctrine
7. Higher-law Constraint
8. Is this still interpretation?
9. If law development: gap + method + burden
10. Correctness / fairness backstop
```

## 硬规则

- 文义不是唯一答案，但必须先检查；
- 不能把“我认为公平”当作独立法源；
- 超越通常文义须显式说明；
- 法律沉默不当然是漏洞；
- 类推先证明漏洞和规范理由，再比较案件；
- 目的性限缩先证明字面适用与规范目的发生计划性冲突；
- 法续造必须记录 `reasoning_burden = ELEVATED`；
- 若中国现行法存在禁止类推/严格法定边界，优先适用现行 L0。

## 输出 Extension

```text
extensions.interpretation_review = {
  wording,
  system,
  history,
  purpose,
  consequence,
  cases,
  higher_law,
  law_development,
  burden,
  unresolved
}
```

## 检索式工程规则

## 初始检索词类型

每个重要 问题/争点 从下列来源生成词：

1. 规范概念 / 法条术语
2. 同义词、近义词、旧称
3. 决定性事实
4. 行为/主体/法律关系
5. 案例裁判措辞
6. 行业术语
7. 反向结果词
8. 例外/排除词

## 独立检索路径

```text
Q1 Concept / issue
Q2 Statute-linked
Q3 Case-linked
Q4 Material-fact
Q5 Citation snowball
Q6 Counter / exception
```

关键 问题/争点 至少两条独立路径。

## 扩展与收窄

### 太少
- 删除过窄条件
- 同义词 OR
- 上位概念
- 扩大字段/来源
- 从已知高质量材料脚注滚雪球

### 太多
- 加决定性事实
- 加法条/争点
- 限制字段
- 限制法院/时间/文献类型
- 二次检索

## 规则
数据库语法必须按 适配器 记录，不能假定 AND/NEAR/通配符跨平台相同。

## 研究饱和规则

**规则等级：L3 / 未经充分测试**

## 充分（SATURATED） 候选条件

关键 问题/争点 同时满足：

- [ ] 核心 L0 已核验；
- [ ] 历史版本/时间问题已处理；
- [ ] 定义、例外、特别规定已检查；
- [ ] 至少2条相互独立的检索路径；
- [ ] 关键案例来源已检查；
- [ ] 支持（SUPPORT） 已检查；
- [ ] 反向（COUNTER） 已检查；
- [ ] 边界（BOUNDARY） 已检查；
- [ ] 例外（EXCEPTION） 已检查；
- [ ] 重要分歧已显式记录；
- [ ] 新一轮扩检没有产生会改变规则/结论的实质新信息；
- [ ] Remaining 缺口 与本次用途相容。

## 强制 不完整（INCOMPLETE）

任何以下情形：

- 现行法未核验；
- 时间适用未核验且可能改变结论；
- 只有单一低权威来源；
- 用户只要求单向检索；
- 关键案例全文不可得；
- 重大反向观点未处理；
- 私域关键材料不可读。

## 后续校准


```text
stopped_too_early
searched_too_long
missed_counter_authority
missed_exception
no_new_information_iterations
```

再决定是否需要量化阈值。

## 信源路由规则

## 1. 问题 → 第一优先来源

| 问题类型 | 第一优先 | 第二优先 | 不能替代 |
|---|---|---|---|
| 现行法律是什么 | 官方法源 | 权威法律数据库 | 律师文章不能替代法源 |
| 历史法律是什么 | 官方历史版本/公报 | 法律数据库历史版本 | 当前法不能替代旧法 |
| 法院如何适用 | 人民法院案例库/指导案例/官方案例 | 生效裁判 | 新闻摘要不能替代裁判 |
| 理论争议 | 权威专著/论文 | 专业实务文章 | 搜索排名不能替代学术权威 |
| 实务做法 | 官方业务规范/高质量实务资料 | 律师/机构文章 | 个别经验不能自动普遍化 |
| 本案事实 | 原始案件材料 | 经核验私域记录 | 公开网页不能替代本案材料 |
| 新兴行业现象 | 官方数据/报告 | 新闻/平台 | 现象不能自动转成法律规则 |

## 2. Auto 范围

默认先从“最能回答该问题的来源”开始，再根据结果触发扩检。

不是所有来源每次都搜一遍。

## 3. 适配器 Independence

来源 Registry 只记录能力：

```text
can_search_law
can_search_cases
can_search_articles
can_fetch_fulltext
can_filter_date
can_filter_jurisdiction
can_return_citation
```

不把具体平台写死在 工作流程。

## 信源筛选与原始来源核验规则

## Three 阶段s
`Screen → Collect → Deep Review`

不得一开始把所有结果全部深读。

## 专业评论
检查：
- 日期
- author / institution
- publication venue
- 来源 citations
- expertise
- interest/bias
- currentness
- original 来源 availability

## 原始来源规则
关键规则/观点优先追原始来源。

若只有二手转引：
```text
verification_state = PARTIALLY_VERIFIED / UNVERIFIED
notes = secondary citation only
```

## 未检索到规则（NOT_FOUND）
数据库无结果：
```text
SourceGap = NOT_FOUND_IN_<SOURCE>
```
不得转成：
```text
Fact = DOES_NOT_EXIST
```

## 互联网来源规则
搜索排名、推荐算法、摘要、AI摘要均不产生 权威性。
