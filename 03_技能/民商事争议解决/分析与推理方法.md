# 民商事争议解决——分析与推理方法

本技能的分析不是“把起诉与答辩流程走完”，而是围绕客户目标建立并不断修正一套**请求—事实—要件—证据—程序—策略模型**。

## 1. 事实建模

从材料中识别交易、履行、违约、通知、损害、付款、交付、意思表示和程序事件。每个重要事实保留来源与事实状态，并通过结构化审阅发现版本差异、时间冲突和不利材料。

## 2. 问题构造

原告侧至少形成：目标法律效果、可能请求权基础、积极要件、预期抗辩、反抗辩和主位/备位路径。被告侧至少区分：否认、抗辩、反请求、程序防御和替代履行方案。

争点不是“双方意见不同”的同义词，而是能够影响某一请求、抗辩、程序或执行结果的决定性分歧。

## 3. 规范定位

围绕每条法律路径核验实体规则、程序规则、时效、管辖/仲裁、保全、证明责任及特别规则。存在多个请求权基础时，不因用户最初定性而提前关闭替代路径。

## 4. 证据检验

以待证命题为单位连接证明责任和证据。内部模型同时记录：我方支持证据、对方有利证据、事实冲突、证据缺口和应出现但尚未取得的材料。

## 5. 规则适用

主要使用要件涵摄：

```text
请求/抗辩规则
→ 构成要件
→ 对应事实
→ 对应证据
→ 满足/不满足/争议/未知
→ 初步法律效果
```

类案主要用于解释要件边界和决定性事实，不得用“案情相似”替代具体可比性分析。

## 6. 竞争解释

重要问题至少构建对方最强版本：如果对方的事实和法律解释成立，当前我方哪一要件、证据或程序位置最脆弱？什么新事实会使结论翻转？是否存在合同关系之外的其他法律关系或责任基础？

## 7. 策略选择

把法律可行性与客户目标、证据成熟度、程序时点、对方资产、保全价值、时间成本、和解空间和执行可实现性一起比较。需要多方案时形成主位方案、备位方案和停止/转向条件。

## 8. 论证表达

正式文书应从内部模型生成。每一重大主张尽量保留“规则—事实—证据—推理—反方—回应”的结构；对外可以策略取舍，但不得因此让内部模型失真。


## 溯源要求

本技能的所有重要专业判断同时适用《全链路溯源规范》：事实应回到材料/证据和来源定位；法律规则和案例应回到权威来源及具体位置；核心分析应形成可审计的规则—事实—证据—理由链；正式交付中的重要命题应能够反向关联上游 Finding / Argument / Fact / Rule / Case 等对象。无法完成溯源时，应降低结论强度、披露限制或阻断正式交付。

## 跨模块交接与回写

- 请求权基础、抗辩、时效、管辖、证据规则或类案需要核验时，从争点 `IssueRecord` 发起 `ResearchRequest`；研究结果应回填请求/抗辩矩阵和论证。
- 新证据或新法律规则改变某一要件是否满足时，应重新检查争点、举证责任、主位/备位请求和策略，不得继续沿用旧结论。
- 起诉、仲裁、保全、和解、上诉、执行等存在实质路径选择时，形成可比 `OptionRecord`；涉及撤诉、和解、放弃请求等重大决定时停在人工节点。

## 事项工作模型补充

复杂争议应以客户目标和代理位置建立 TaskProfile，并把请求、否认、抗辩、举证、程序、保全和执行问题组织成 IssueTree。批量材料审阅字段应由请求权基础和争点驱动；类案对重要争点产生实质影响时使用 CaseMatrix，而不是简单堆列案例。
