# 业务模块汇总

## 00-渠道-代理位置-阶段路由

## 输入
MatterContext + CivilDisputeExtension + TaskRequest

## 路由
1. 争议解决渠道
2. 代理位置
3. 阶段
4. Urgency
5. Task Graph

## 紧急程度
优先识别：
- limitation/filing period
- 保全 need
- asset dissipation
- jurisdiction objection period
- arbitration/filing conflict
- 证据 loss
- 庭审 期限
- appeal 期限
- 执行 limitation

具体期限一律 现行法 核验。

## 输出
Civil阶段State

## 01-接案与客户目标

## 工作流程
1. 客户先完整陈述；
2. 收集其认为重要的全部材料；
3. 澄清真正希望实现的结果；
4. 区分：
   - 法律 请求目标
   - 商业目标
   - 时间/成本目标
   - 关系 goal
   - 执行 goal
5. 建 urgent 清单；
6. 初步识别 forum/position/阶段；
7. 不承诺结果。

## 输出
- 客户 目标
- initial 事实记录（FactRecord）
- 材料 清单
- preliminary 请求目标 candidates
- 紧急程序问题

## 02-材料审查与事实建模

## 输出
- 材料 Inventory
- 事实 Detail Table
- Timeline
- Actor 图
- 法律 Relationship Diagram
- 交易/履行流程
- Contradiction List
- Missing 事实 List

## 方法
先全面掌握材料，再按统一标准整理。

复杂事项优先使用：
- 时间
- 主体
- 交易环节
- 文件类型
- 款项/履行
等结构化维度。

## 规则
图表用于帮助发现关系，不得让图示简化掉有法律意义的例外和矛盾。

## 03-请求与抗辩架构

## 原告/请求方
```text
relief
→ claim basis candidates
→ auxiliary rules
→ positive elements
→ non-arising defenses
→ extinguishing defenses
→ exercise defenses
→ counter-defense
```

## 被告/相对方
```text
claimant relief
→ test each claim basis
→ denial
→ independent defense
→ defense basis/elements
→ claimant rebuttal
→ fallback position
```

## 多请求权基础
记录：
- 备选
- cumulative
- competing/exclusive
- overlapping reasons

不得因用户/诉状只写一项法律依据，就停止备选请求权基础识别。

## 04-要件与争议焦点矩阵

## 律师端适配
九步法来自法官裁判组织方法，本项目只吸收：

```text
固定请求/救济
→ 找请求权基础
→ 找抗辩基础
→ 分解要件
→ 对照当事人陈述
→ 形成真正争点
→ 确定待证事实
→ 证据/证明责任
→ 涵摄与方案
```

## 争点规则
真正事实争点通常满足：
1. 双方陈述不一致；
2. 该事实对应请求权/抗辩要件；
3. 对裁判结果有实质意义。

普通背景差异不自动升级为“争议焦点”。

## 05-证据与举证责任


## 待证命题优先
每个证据必须连接一个或多个待证命题。

## 矩阵
```text
proposition
element/defense
asserting party
burden/risk bearer
证据对象（EvidenceItem）[]
counter evidence
credibility/probative issues
gap
next action
```

## 证据组织
可按：
- factual proposition
- chronology
- actor
- 法律 element
组织。

复杂案件不得只按文件产生时间机械排序。

## 内部不利材料
与己方主张冲突的材料必须保留在内部模型。

## 现行法
自认、举证责任、鉴定、电子数据、证据保全、证明标准等运行时核验。

## 06-程序策略

## 检查清单
- jurisdiction
- arbitration agreement
- 当事人/主体资格
- 请求 framing
- filing prerequisites
- limitation/程序 period
- service
- counterclaim
- 保全
- 证据保全
- interim measure
- consolidation/separation
- appeal/审阅
- 执行 feasibility

## 仲裁法时效提示
2025修订《仲裁法》自2026-03-01施行。

历史资料中的：
- 条号
- 撤裁条件
- 不予执行
- 仲裁司法审查期限
等，不得直接写成现行规则。

## 策略
程序规则可以服务实体目标，但不得滥用程序或制造虚假事实。

## 08-诉讼文书

## 内容 输入
- 事实 Model
- ClaimDefenseMatrix
- 问题/争点 图
- 证据 矩阵
- 研究结果（ResearchResult）
- 策略 分析结果

## 输出
产生 Draft 内容 / 输出契约（OutputContract），不在本模块自行完成最终格式。

## 结构
通常：
> core position → key 事实 → 法律 basis → 分析 → 请求目标/行动

具体文种依官方 Schema 覆盖。

## 规则
二审/再审文书必须针对原裁判问题，不是复制一审文稿。

## 09-庭前与开庭

## 庭前
- 审阅 case
- identify 庭审 objectives
- issue 图
- 证据/cross 计划
- questions
- possible tribunal questions
- applications
- settlement 权威性
- team roles

## 开庭
关注：
- 法庭调查暴露的新问题；
- 对方新增事实；
- 法官/仲裁庭提问；
- 证据解释；
- 调解信号。

## 发问
仅提出：
- 与争点有关；
- 对方可回答；
- 有明确证明/削弱目的；
的问题。

不要为了“表现积极”无目的发问。

## 10-庭后与和解

## 庭审记录
记录：
- arguments
- issue changes
- judge/tribunal questions
- opponent positions
- 证据 updates
- follow-up requests

## 和解决策
至少比较：
- likely 法律 result（定性，不做伪概率）
- 证据 uncertainty
- enforceability
- 时间/cost
- 关系
- payment ability
- security
- sequence of performance/release/保全
- default consequence

## Hard 能力边界
和解条款/撤诉/解封等重大处分必须由客户授权。

## 11-二审再审与执行

## 二审/上诉
重新分析：
- judgment reasoning
- fact omissions/errors
- 证据 evaluation
- 法律 application
- 程序 问题
- new 证据
- requested appellate 请求目标

## 再审
当前成熟度：PARTIAL。
必须执行专用 现行法 研究。

## 执行
先作为大型模块：
- executable obligation
- asset clues
- 保全-to-执行 交接
- 执行 settlement
- 变更/add party
- objections/remedies
- closure/restart 状态

不单独拆顶层 技能，待真实项目验证。
