# 合同与交易工作——分析与推理方法

合同工作不是“找不利条款”，而是判断法律文本是否准确实现交易目标、履行机制是否闭环、风险是否被合理配置，并据此形成可谈判的文本方案。

## 1. 事实与交易建模

先明确客户角色、商业目标、交易标的、价款、交付、付款、审批、第三方依赖、关键时间、退出机制和不可退让条件。材料较多时使用结构化审阅比较主协议、附件、报价、技术文件、历史版本和往来沟通。

## 2. 问题构造

把交易过程拆成：进入条件、履行义务、验收、付款、变更、第三方事件、违约、终止、争议和退出。识别合同文本与真实交易之间的错位。

## 3. 规范定位

只有在法律效力、强制性规则、监管要求、特殊交易、争议解决或法律概念边界需要核验时调用法律研究，不用静态法条清单替代当前规则核验。

## 4. 风险与证据检验

每个重大风险至少说明：触发事件、谁能控制、需要什么事实证明、发生后的法律/商业后果、合同现在如何分配、是否有可执行的控制措施。

## 5. 规则与文本适用

从交易结构反推条款功能。定义、义务、权利、条件、陈述保证、赔偿、责任限制、终止等不同条款承担不同功能，不能只靠“更强硬”的措辞解决风险。

## 6. 竞争场景

至少进行正常履行、我方违约、对方违约、双方争议、第三方失败、审批失败、不可预见事件等情景压力测试。检查条款在不同场景下是否出现责任真空、循环义务或不可执行安排。

## 7. 策略选择

根据客户谈判地位、风险偏好和商业目标形成：理想文本、可接受文本、最低底线和替代安排。对不能完全消除的风险，明确“接受/换取对价/附条件接受/拒绝”的选择。

## 8. 论证表达

审查意见应说明“为什么改、改了什么、风险如何变化、对方可能如何反应”，而不是堆积风险标签。正式修订稿还要经过文书质量和版本一致性检查。


## 溯源要求

本技能的所有重要专业判断同时适用《全链路溯源规范》：事实应回到材料/证据和来源定位；法律规则和案例应回到权威来源及具体位置；核心分析应形成可审计的规则—事实—证据—理由链；正式交付中的重要命题应能够反向关联上游 Finding / Argument / Fact / Rule / Case 等对象。无法完成溯源时，应降低结论强度、披露限制或阻断正式交付。

## 跨模块交接与回写

- 强制性规则、监管要求、交易资格、效力或争议解决等需要核验时，由具体合同问题发起 `ResearchRequest`，研究结果回填风险场景和条款建议。
- 商业目标、谈判地位或客户风险偏好变化时，应回写交易模型、风险优先级和修改文本，不能只改最后的建议说明。
- 对关键条款存在接受、修改、拒绝、附条件接受或以对价换风险等选择时，形成 `OptionRecord`；需要客户承担重大商业风险时形成 `DecisionRecord`。

## 任务配置与审阅问题

合同任务应优先明确客户角色、商业目标、谈判位置、风险偏好、审查尺度、不可退让项和备选位置，并形成 TaskProfile。多合同或长合同审阅时，ReviewQuestionSet 应围绕本次交易风险和谈判目标动态生成；重大条款存在多种修改方案时进入 OptionRecord / DecisionRecord。

## 条款覆盖地图（按需）

为避免仅围绕现有条款“见招拆招”，审查时可按五类功能反向检查遗漏：身份与解释、交易与对价、履行与流程、保障与治理、异常与救济。是否需要某一类条款由具体交易决定，不因模板中常见就机械添加。
