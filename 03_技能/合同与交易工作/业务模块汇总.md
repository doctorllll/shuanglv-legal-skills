# 业务模块汇总

## 00-工作模式与运行能力路由

确定：
- TRANSACTION_ANALYSIS / DRAFT / REVIEW / REVISE / NEGOTIATION / QA
- 文书 阶段
- edit 方式
- current 版本
- 运行环境 原生修订模式 / 批注 support

如果用户要求Word原生修订而运行环境不支持：
> 立即设置 Capability Downgrade，采用 差异稿 + 清洁稿。

---

## 01-需求与代表方确认


确认：
- representing party
- negotiation leverage
- 客户 concern
- service depth
- draft/审阅 阶段
- formal opinion
- 期限
- output versions
- revision 方式

不得先改合同后问“我们代表哪一方”。

---

## 02-交易结构


输出：
```text
parties
subject matter
consideration
main obligations
transaction sequence
conditions/approvals
third-party dependencies
legal constraints
alternative structures
```

先回答：
> 交易能不能做、风险大不大、应采用什么结构。

结构有重大问题时先暂停微观修订并与客户沟通。

---

---

## 03-文件架构

分析：
- 合同类型
- 框架/订单
- 主协议/附件
- 意向/正式/履行中文件
- 多协议之间的优先和衔接
- 定义/技术附件/价格表/交割文件
- 补充/变更/终止机制

目标：
> 文档结构与交易结构一致。

---

## 04-履行流程与义务地图


建立：
```text
step
actor
obligation
right
condition
deliverable
confirmation
deadline
payment
evidence
failure consequence
```

检查：
- 是否环环相扣
- 是否单边连续投入
- 是否有确认节点
- 是否可证明履行
- 义务和责任是否对应

## 05-风险场景推演


同时模拟：
- 对方违约
- 我方违约
- 第三方失败
- 审批失败
- 市场变化
- 交易终止
- 证据/确认缺失
- 履约能力问题

风险评价：
- likelihood 用 高（HIGH）/中（MEDIUM）/低（LOW）/UNKNOWN
- 影响 用 CRITICAL/高（HIGH）/中（MEDIUM）/低（LOW）

不得生成伪精确百分比。

输出：
TransactionRiskScenario[]

## 06-条款功能工程


功能而非词汇优先：
- OBLIGATION
- RIGHT
- DISCRETION
- REPRESENTATION
- WARRANTY
- DECLARATION
- CONDITION
- DEFINITION
- PROCEDURE
- REMEDY
- RISK_ALLOCATION

检查：
1. 谁受约束
2. 做什么
3. 时间
4. 标准
5. 条件
6. 例外
7. 对方权利
8. 违约/后果
9. 证明方式
10. 风险场景

注意：
英文合同方法只用于条款功能分析，具体法律效果必须按适用法核验。

## 07-现行法核验

调用：
`法律研究与多源资料融合`

至少按交易检查：
- subject capacity/权威性
- 标的合法性
- mandatory rules
- approvals/licenses
- formation/effectiveness
- standard terms
- interpretation
- breach/remedy
- termination
- damages/liquidated damages
- security
- domain rules

当前重要基线：
- Civil Code
- 法释〔2023〕13号合同编通则解释

具体行业继续查特别法。

## 11-签署与履行交接

签署前：
- final party data
- 权威性/signature
- attachments
- conditions
- execution copies
- 版本 freeze

签署后：
- conditions precedent
- delivery/closing
- payment
- acceptance
- notice
- renewal
- termination
- 证据 retention
- obligation calendar

目标：
> 合同从“写完”进入“能履行、能证明、能管理”。

## 12-合同修改实际落稿

`REVISE` 与默认 `REVIEW` 不得停留在“修改建议”。成熟建议应进入合同正文。

推荐交付：
```text
修改后的合同（REQUIRED）
+ 差异/修订体现（能力允许时）
+ 清洁稿（正式使用时）
+ 重大修改说明（必要时）
```

需要客户决定的商业参数、不可逆风险或谈判选项，可以用占位、批注、首选/备选文本和 DecisionRecord 保留，不擅自代客户作决定。
