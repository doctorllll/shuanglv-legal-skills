# 公共接口规范

## 一、目的

公共接口用于让不同法律技能之间交换结构化信息。它只规定业务对象和最小字段，不负责长期记忆、数据库持久化，也不绑定任何特定 Office、PDF、OCR 或模型实现。

## 二、核心对象

| 中文名称 | 机器对象名 | 主要用途 |
|---|---|---|
| 事项上下文 | `MatterContext` | 当前任务可见的事项、角色、阶段和基本范围 |
| 任务请求 | `TaskRequest` | 本次要完成的具体任务 |
| 来源定位 | `SourceLocator` | 文件、页码、段落、工作表、单元格、时间戳等定位 |
| 信源卡片 | `SourceCard` | 记录一个法律、案例、网页、文件或其他来源 |
| 事实记录 | `FactRecord` | 记录事实内容、状态和来源 |
| 问题记录 | `IssueRecord` | 记录需要分析或解决的问题 |
| 证据对象 | `EvidenceItem` | 记录证据内容、来源、证明对象和审查状态 |
| 法律与方法规则 | `LegalRule` | 记录当前任务使用的法律规则或方法规则 |
| 案例卡片 | `CaseCard` | 记录案例事实、裁判要点和可比性信息 |
| 检索轨迹 | `ResearchTrace` | 记录检索路径和已检索范围 |
| 法律研究结果 | `ResearchResult` | 研究结论、来源和未解决缺口 |
| 风险记录 | `RiskRecord` | 记录风险场景、影响、控制措施和客户决策事项 |
| 分析发现 | `Finding` | 记录经过分析形成的阶段性结论 |
| 人工升级事件 | `EscalationEvent` | 记录必须由律师或用户确认的事项 |
| 输出契约 | `OutputContract` | 规定最终交付物格式、版本和质量要求 |
| 交付物元数据 | `ArtifactMetadata` | 记录文档版本、父版本和变更信息 |
| 运行能力档案 | `RuntimeCapabilityProfile` | 记录当前 Agent 或工具与本次任务有关的能力 |

## 三、事实状态

事实状态必须显式区分：

| 中文含义 | 机器值 |
|---|---|
| 已核验 | `VERIFIED` |
| 当事人或单方陈述 | `ALLEGED` |
| 存在争议 | `DISPUTED` |
| 根据已知事实推断 | `INFERRED` |
| 未知 | `UNKNOWN` |

任何技能不得把 `ALLEGED`、`INFERRED` 或 `UNKNOWN` 静默提升为 `VERIFIED`。

## 四、来源定位

需要正式引用或证据核验时，来源定位至少尽可能保留：
- PDF：文件名 + 页码；
- Word：文件名 + 标题/段落，工具可获取时保留页码；
- Excel：文件名 + 工作表 + 单元格或范围；
- PPT：文件名 + 页码；
- 图片：文件名 + 图像区域；
- 音频：文件名 + 时间戳；
- 视频：文件名 + 时间戳 + 关键帧；
- 网页：网址 + 对应位置；
- 压缩包：压缩包路径 + 内部文件路径。

如果定位能力不足，必须显式标记为部分可用，不得假装可以精确引用。

## 五、法律研究结果状态

法律研究结果可以使用：

| 中文状态 | 机器值 |
|---|---|
| 已达到当前任务需要的研究充分程度 | `SATURATED` |
| 研究尚不完整 | `INCOMPLETE` |
| 因来源、权限或工具受阻 | `BLOCKED` |
| 必须由律师进一步判断 | `HUMAN_REVIEW_REQUIRED` |

`INCOMPLETE` 或 `BLOCKED` 不得包装成无保留确定结论。

## 六、风险记录

风险记录用于尽调、合同、法律顾问等技能之间交接。至少应区分：
- 风险场景；
- 触发条件；
- 发生可能性；
- 影响；
- 可控程度；
- 支持该风险判断的事实或来源；
- 可选控制措施；
- 剩余风险；
- 是否需要客户作决定。

没有可靠数据时，不生成伪精确概率。

## 七、输出契约

输出契约只描述“最终应交付成什么样”，例如：
- 主要格式；
- 是否需要 DOCX、PDF、XLSX 等附加格式；
- 文书类型；
- 统一样式规范；
- 编辑模式；
- 是否要求原生修订、批注、清洁稿或对比稿；
- 版本和父版本；
- 引用方式；
- 是否需要交付物质量检查。

具体文件由当前 Agent 可用的文档能力生成，并按本系统的交付要求检查。

## 八、运行能力

当前任务需要特定能力时，只检查与本次任务有关的能力。例如：
- 是否能可靠读取扫描 PDF；
- 是否能保留 PDF 页码；
- 是否能进行 OCR；
- 是否能带时间戳转录音频；
- 是否能理解视频并保留时间戳；
- 是否能编辑 DOCX；
- 是否能生成真实 Word 原生修订；
- 是否能保留 Excel 公式；
- 是否能生成 PDF。

执行前应按当前 Agent 的实际能力判断可用功能。

## 九、跨技能交接

上游技能向下游技能交接时，至少保留：
- 当前任务目标；
- 已使用材料；
- 关键事实及其状态；
- 关键问题；
- 分析结果；
- 风险；
- 来源定位；
- 尚未解决的缺口；
- 需要下游完成的工作。

复杂任务同时生成《项目执行说明书》。

## 十、持久化边界

`MatterContext` 只表示**当前执行可见的事项上下文**，不是长期案件数据库。

`ArtifactMetadata` 只描述当前可见交付物之间的版本关系，不要求本技能包自己保存长期版本库。

后续继续任务时，应读取当前可访问的项目记录和相关文件。
