# 事项工作模型与分析地图规范

## 一、目的

复杂法律任务不能只依赖聊天上下文，也不能把每一步的结果留在彼此隔离的段落中。爽律 Skill 对复杂、多文件、重要或跨模块任务建立**事项工作模型**：它是当前任务范围内的结构化工作状态，用来连接客户目标、材料、事实、证据、问题、法律、案例、论证、风险、策略、决定和交付物。

事项工作模型不是长期案件数据库，也不要求爽律 Skill 自行保存跨会话记忆。当前运行环境如具备项目空间、知识库或持久化能力，可将本次工作模型作为交接对象保存；否则应通过项目执行说明书或当前任务文件继续传递。

## 二、事项工作模型

复杂任务原则上维护以下对象关系：

```text
Matter
├─ TaskProfile        任务配置与客户目标
├─ Materials          材料与来源定位
├─ ReviewRecords      结构化审阅记录
├─ Facts              事实及事实状态
├─ Evidence           证据对象
├─ IssueTree          问题树
├─ Research           法律研究请求与结果
├─ Rules              法律规则
├─ AuthorityMap       权威来源结构
├─ Cases              案例卡片
├─ CaseMatrix         类案比较矩阵
├─ Arguments          论证记录
├─ ArgumentMap        论证关系图
├─ Risks              风险记录
├─ Options            策略选项
├─ Decisions          人工决定
├─ Findings           分析发现
└─ Deliverables       交付命题与交付物
```

这些对象应尽量使用稳定 ID 关联，避免后续步骤重新猜测前一步的含义。

## 三、TaskProfile：先确定“为谁、为什么、做到什么程度”

复杂任务在实体分析前建立最小任务配置。至少明确：

- 当前客户/委托角色；
- 客户真实目标与优先级；
- 当前程序或交易阶段；
- 本次任务范围与排除项；
- 时间、成本、保密和其他约束；
- 是否存在不可退让项或备选位置；
- 需要什么交付物；
- 什么状态才算本次任务完成。

合同与交易任务可增加谈判位置、风险偏好、审查尺度、不可接受条款和 fallback position；民商事可增加回款、时效、保全、关系维持和执行优先级；刑事辩护与控告可增加人身自由、立案、挽损、证据灭失、认罪认罚或观点披露等目标；尽调可增加重要性阈值和交易目的。

TaskProfile 只记录用户已经明确的信息、可从材料可靠确定的信息以及明确标注的工作假设。不得为了“配置完整”自行替客户决定目标或风险偏好。

## 四、IssueTree：把一个问题拆成能够真正处理的问题树

重要法律任务应把笼统问题拆成可研究、可证明、可决定的子问题，而不是直接从总问题跳到结论。

问题树可以包含：

- 法律关系或法律路径问题；
- 构成要件问题；
- 事实争议；
- 证据与证明责任问题；
- 程序与期限问题；
- 救济与执行问题；
- 策略与人工决定问题。

每个重要问题至少记录：

- 为什么重要；
- 依赖哪些事实；
- 需要哪些法律或案例研究；
- 哪些问题是它的前提或子问题；
- 什么事实或规则变化会影响结论。

问题树不是一次生成后固定不变。新材料、新规则、案例区别或对抗性审查发现足以改变问题结构时，应产生回写事件并更新问题树。

## 五、ArgumentMap：把“观点列表”升级为论证关系

当同一争点存在多个竞争观点时，可以建立论证地图。论证之间至少区分：

- SUPPORTS：支持；
- ATTACKS：直接攻击；
- REBUTS：回应；
- QUALIFIES：限制或修正；
- DEPENDS_ON：依赖；
- ALTERNATIVE：替代路径。

论证地图应连接既有 ArgumentRecord，而不是生成一套脱离事实、规则和证据的新观点。重要争点应能看出：我方主张、对方最强主张、各自依据、真正冲突点和翻转点分别是什么。

## 六、事项工作模型的更新原则

事项工作模型应遵循：

1. **增量更新**：新信息进入现有对象，不重复建立语义相同的平行对象；
2. **保留历史**：重要结论发生变化时通过 supersedes / writeback 记录变化，而非静默覆盖；
3. **来源不丢失**：任何压缩、汇总和映射不得破坏上游来源定位；
4. **未知保持未知**：缺失字段不自行补齐；
5. **角色敏感**：不同代理角色可以共享事实模型，但问题、策略和交付目标可以不同；
6. **按需展开**：简单问题无需创建完整工作模型；复杂、多文件、重要或正式任务才按实际需要展开。

## 七、最低使用条件

满足以下任一情况时，原则上建立事项工作模型：

- 多文件、多来源或多版本材料；
- 需要跨模块调用法律研究、证据、策略和文书；
- 重要或高风险法律任务；
- 存在多个争点、方案或人工决定节点；
- 任务需要后续多轮继续。

事项工作模型的存在不代表任何实体结论已经正确。它只提高执行的一致性、可追溯性和后续复核能力。
