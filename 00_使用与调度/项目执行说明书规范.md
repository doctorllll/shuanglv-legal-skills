# 项目执行说明书规范

## 一、定位

《项目执行说明书》是一次复杂技能执行结束后生成的**旁车交付物**。它的作用不是长期记忆，而是让人或下一个 Agent 快速知道：这次收到了什么、实际看了什么、做了什么、形成了什么、产出了什么、还缺什么，以及下一步从哪里继续。

## 二、什么时候生成

以下情形默认生成完整说明书：
- 多文件任务；
- 案件或项目型任务；
- 多轮继续工作；
- 跨技能调用；
- 生成正式交付物；
- 存在未解决事项或来源缺口；
- 用户明确表示后续还要继续；
- 存在重要人工决策点。

简单一次性问答可以不单独生成。

## 三、材料状态

必须区分：

| 中文状态 | 机器值 | 含义 |
|---|---|---|
| 已收到 | `RECEIVED` | 已收到，但不等于已经阅读 |
| 已打开 | `OPENED` | 已打开或可访问 |
| 已审阅 | `REVIEWED` | 已完成本次任务所需审阅 |
| 部分审阅 | `PARTIAL` | 只审阅了部分 |
| 未审阅 | `NOT_REVIEWED` | 明确没有审阅 |
| 无法读取 | `UNREADABLE` | 无法可靠读取 |
| 缺失 | `MISSING` | 应有但尚未提供 |

> **已收到（RECEIVED）不等于已审阅（REVIEWED）。**

## 四、说明书应包含的内容

### 1. 本次执行
- 执行编号；
- 日期和时间；
- 主技能；
- 辅助技能；
- 任务目标；
- 本次范围；
- 完成状态。

### 2. 收到的输入
逐项记录材料或来源名称、类型、状态和必要的敏感等级。

### 3. 实际审阅的材料
逐项记录：
- 审阅状态；
- 审阅范围；
- 页码、时间戳、工作表或其他来源定位；
- 未审阅、不可读或存在疑问的部分。

### 4. 检索与外部来源
记录：
- 是否进行了外部检索；
- 现行法核验范围和日期；
- 使用的主要来源类别；
- 尚未完成的研究事项。

### 5. 已完成工作
例如：
- 会见信息整理；
- 阅卷；
- 事实时间线；
- 证据矩阵；
- 法律研究；
- 合同审查；
- 风险分析；
- 文书起草；
- 质量检查。

### 6. 当前关键分析结果
只记录关键结论、限制、重要反向材料和不确定事项，不复制整份正式报告。

### 7. 已产出
记录文件或其他产物名称、类型、版本、父版本、状态和主要内容。

### 8. 尚未解决
包括：
- 缺失材料；
- 未知事实；
- 来源缺口；
- 现行法核验缺口；
- 工具或格式问题；
- 需要人工决定的事项。

### 9. 下一步
记录下一动作、推荐技能、需要输入、优先级和阻塞事项。

### 10. 续接说明
用简短文字说明下一次从哪里开始，不重复已经完成的工作。

## 五、不得写入

- API 密钥或令牌；
- 无必要的完整身份证号、银行卡号等敏感信息；
- 未经授权的第三方凭证；
- 将推断写成已核验事实；
- 将“收到”写成“已审阅”；
- 将“计划做”写成“已完成”。

## 六、机器记录

如运行环境需要自动读取，可以同时生成 `技能执行记录.schema.json` 对应的 JSON。项目执行说明书可由用户或当前工作区保存，供后续继续使用。
