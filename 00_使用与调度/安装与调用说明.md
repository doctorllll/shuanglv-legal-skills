# 爽律 Skill｜律师专业工作流系统——安装与调用说明

## 一、安装的最低目标

安装成功不是“把 ZIP 放进某个文件夹”这么简单，而是要满足四个条件：

1. 当前 Agent 能访问完整的爽律 Skill 系统；
2. 当前 Agent 能把 `SKILL.md` 或《爽律 Skill入口》作为系统入口；
3. 用户使用调用别名“爽律”时能够路由到该入口；
4. 入口可以继续读取内部各业务技能和公共规范。

## 二、通用安装方式

不同 Agent 的技能/插件机制不同，因此爽律 Skill 不写死某个平台目录结构。通用原则是：

```text
把完整的爽律 Skill 系统交给 Agent
→ 将 SKILL.md / 爽律 Skill入口注册为入口
→ 把“爽律”设为调用别名
→ 保证入口能继续访问 00/01/02/03/04 目录
→ 完成
```

如果平台支持“项目文件”“Workspace Instructions”“Skills”“Plugins”“MCP 资源”“系统知识文件”等不同机制，应选择**能让 Agent 在任务执行时稳定读取完整的爽律 Skill 系统**的方式。

## 三、安装后用户怎么说

用户不需要说具体技能名。

推荐：

> “调用爽律来做这个。”

也可以：

> “用爽律审这个合同。”
> “用爽律帮我阅卷。”
> “这个法律问题调用爽律研究。”
> “按爽律给我做一份法律意见。”

## 四、Agent 应该怎么响应

Agent 不需要向普通用户展示内部路由细节，除非用户询问。它应在内部：

```text
识别任务
→ 选择主技能
→ 检查输入
→ 执行工作流
→ 必要时调用法律研究/文书质量/输入适配
→ 对抗性审查
→ 人工升级判断
→ 输出
```

## 五、平台能力不足怎么办

如果平台：

- 不能读取整个目录：应把入口和实际使用的技能文件作为一个可访问集合加载；
- 不支持别名调用：可以把“用户使用调用别名‘爽律’时读取 `SKILL.md`”写进平台系统指令；
- 不支持 DOCX/PDF：爽律 Skill 只输出内容和格式要求，并明确说明能力降级；
- 没有 OCR/音视频能力：按“多模态输入适配（可选）”处理；
- 没有长期记忆：不影响爽律 Skill 运行，复杂项目依赖项目执行说明书续接。

## 六、安装时不要做什么

- 不要只安装某个子技能却仍声称“已经安装完整的爽律 Skill”；
- 不要为了适配某个平台修改法律业务规则本身；平台适配应只修改入口和能力声明。
