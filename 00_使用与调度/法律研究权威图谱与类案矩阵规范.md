# 法律研究权威图谱与类案矩阵规范

## 一、权威图谱

重要法律研究不能以“搜到一条法条”作为研究终点。围绕一个重要 Issue，应按任务需要建立**权威图谱**，说明不同来源在当前问题中的层级、作用、时间状态和相互关系。

典型结构可以包括：

```text
Issue
→ 上位规范 / 基础法律规则
→ 核心实体规则
→ 程序与证据规则
→ 司法解释或其他有权解释材料
→ 特别规则、例外与过渡安排
→ 具有指导或参考意义的案例
→ 其他解释性、实务性资料
```

权威图谱不是把所有来源都视为同等权威。每个来源应根据法域和任务标明其作用，例如：规范依据、官方解释、案例指导/参考、说理辅助或信息线索。无法确认权威层级时应标记未知，不由模型自行拔高。

## 二、权威图谱至少记录

- 对应 Issue；
- 来源身份和原始出处；
- 适用法域；
- 时间效力或核验日期；
- 来源在当前问题中的作用；
- 支持的具体法律命题；
- 精确定位；
- 特别规则、冲突、例外或适用限制；
- 尚未补齐的上位或原始来源。

法律规则被标记为已核验时，仍须满足《全链路溯源规范》的权威来源与精确定位要求。

## 三、类案矩阵

案例检索不是“找到几个相似案件”。需要利用案例支持重要判断时，按任务需要形成**类案比较矩阵**，至少比较：

- 案例基本信息与来源；
- 决定性事实；
- 核心争点；
- 裁判结论和关键理由；
- 与本案相似点；
- 与本案区别点；
- 对当前命题的使用方式；
- 对我方不利的部分；
- 原文定位。

案例使用方式至少可区分：支持、反向、区别、边界、程序、量刑/责任后果参考等。

## 四、案例比较的禁止模式

- 只因案由或罪名相同就视为类案；
- 只比较裁判结论，不比较决定性事实；
- 只找支持我方的案例；
- 用普通个案替代明确的现行规范；
- 把检索不到反向案例表述成不存在反向案例；
- 未阅读裁判理由就根据摘要推断案件规则。

## 五、研究回写

权威图谱或类案矩阵发现：规则层级、特别规则、时间效力、关键区别事实或反向案例足以改变原 Issue / Argument / Finding 时，必须按《跨模块执行与回写规范》更新上游对象。
