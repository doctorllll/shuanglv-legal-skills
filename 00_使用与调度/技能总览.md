# 爽律 Skill｜律师专业工作流系统——技能总览与人工核验入口

## 两层专业结构

爽律 Skill 同时包含：

1. **纵向业务工作流**：不同律师业务怎样推进；
2. **横向分析与推理能力**：事实建模、问题构造、规范定位、证据检验、规则适用、竞争解释、策略选择和论证表达。

整体关系见 `00_使用与调度/基础能力地图.md`；公共分析要求见 `00_使用与调度/法律分析与推理规范.md`。复杂、多文件任务同时适用 `00_使用与调度/通用结构化审阅规范.md`；复杂、重要或需要跨技能交接的任务同时适用 `00_使用与调度/跨模块执行与回写规范.md` 和 `00_使用与调度/全链路溯源规范.md`。

当前完整支持范围、部分支持范围和运行环境依赖见 `00_使用与调度/测试基线与能力边界.md`。

系统中的每个技能现在都分成两种阅读层：

- **人工核验层**：先读《详细说明与工作流程》，完整理解这个技能是什么流程、用了什么方法、什么时候转人工、产出什么。
- **Agent 执行层**：再读《技能定义》《业务模块汇总》《核心规则汇总》《检查清单汇总》和必要数据结构。

## 方法成果到底在哪里

技能方法分别固化在：

1. **《详细说明与工作流程》**：给人看的完整方法地图；
2. **《技能定义》**：Agent 的调用条件、边界、输入输出和总流程；
3. **《业务模块汇总》**：每一步具体如何执行；
4. **《核心规则汇总》**：必须遵守的规则、门控和禁止事项；
5. **《检查清单汇总》**：执行完成前的质量控制；
6. **数据结构**：稳定传递材料、事实、证据、研究、论证、风险和交付状态；
7. **《分析与推理方法》**：说明该业务如何形成专业判断，而不只是怎样走流程；
8. **公共跨模块对象**：`ResearchRequest / ResearchResult / OptionRecord / DecisionRecord / AdversarialReviewRecord / WriteBackEvent` 用于把研究、分析、策略和人工决定真正串起来。
