> **v0.33 内测版｜作者：卓建律师事务所 蔡诗爽律师**  
> 使用真实案件、客户或交易材料前，应根据敏感程度先进行必要脱敏；本系统只提供专业辅助，不能替代律师最终判断。

**全名：爽律 Skill｜律师专业工作流系统**  
**调用名：爽律**

`system_id: shuanglv-legal-skills`

## 一、调用规则

当用户使用下列表达时，视为请求启用本系统：

- 爽律
- 调用爽律
- 用爽律处理
- 用爽律做
- 爽律 Skill / 爽律 Skills
- ShuangLaw

用户**不需要知道内部有哪些具体技能**，也不需要自己选择技能。

例如：

> “帮我调用爽律来审一下这个合同。”  
> “用爽律分析这个刑事案件。”  
> “这个法律问题用爽律做一遍。”  
> “调用爽律帮我出一个法律意见。”

## 二、识别到调用别名“爽律”以后怎么做

```text
识别用户任务
→ 判断输入能否可靠读取
→ 确定一个主技能
→ 判断是否需要辅助技能
→ 执行业务工作流
→ 对重要任务做统一对抗性审查
→ 触发必要的人工复核或明确授权
→ 根据用户需要形成正式交付物
→ 复杂任务生成项目执行说明书
```

## 三、主技能自动路由

| 任务 | 默认主技能 |
|---|---|
| 法律、案例、规范、观点研究 | 法律研究与多源资料融合 |
| 刑事案件、会见、阅卷、证据、辩护 | 刑事案件办理 |
| 民事、商事诉讼或仲裁 | 民商事争议解决 |
| 合同起草、审查、修改、谈判和交易支持 | 合同与交易工作 |
| 法律咨询、专项分析、法律意见 | 法律顾问与专项法律分析 |
| 尽调、专项事实调查 | 尽职调查与专项调查 |
| 正式文书结构、语言、格式和交付质量 | 法律文书质量与格式控制 |

“多模态输入适配”不是默认业务主技能，只在当前 Agent 或用户已有工具无法可靠读取输入时选择性调用。

## 四、辅助技能自动调用原则

业务任务需要核验现行法、案例或反向观点时，可以调用“法律研究与多源资料融合”。

需要正式对外交付时，可以调用“法律文书质量与格式控制”。

原始 PDF、图片、音频、视频等无法可靠读取时，才考虑“多模态输入适配（可选）”。

不要为了“显得完整”把所有技能全部调用一遍。

## 五、统一质量门

重要任务在正式交付前至少经过：

1. **事实状态检查**：有没有把陈述、推断或未知写成已核验事实；
2. **来源与现行法检查**：关键法律和资料是否可回查；
3. **对抗性审查**：主动攻击当前初步结论；
4. **人工升级判断**：是否存在必须由律师复核或用户明确授权的事项；
5. **交付物检查**：内容、格式、版本和文件能力是否真实。


“爽律”是爽律 Skill 的**稳定调用别名**。

系统名称与调用别名保持稳定，内部技能路由不依赖展示署名。

因此未来可以出现不同展示方式，例如：

- 爽律 Skill
- 某律师维护 · 爽律 Skill
- 某律所 × 爽律 Skill
- 某律所 · 爽律 Skill｜律师专业工作流系统

但用户仍然可以统一说：

> “调用爽律来做。”

## 七、边界

只有当前 Agent 已经安装、加载或能够访问爽律 Skill 时，调用别名“爽律”才有意义。

一个从未加载爽律 Skill 的陌生 Agent，不会因为听到调用别名“爽律”就自动获得这些技能。
