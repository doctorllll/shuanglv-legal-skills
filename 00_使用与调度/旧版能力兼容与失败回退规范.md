# 旧版能力兼容与失败回退规范｜Legacy Compatibility Contract

## 一、目的

v0.43 以后新增的 Agent Native 能力只能增强爽律 Skill，不得成为 v0.42 已验证核心能力正常运行的前置依赖。

> **硬规则：新功能不可用、宿主不支持、判断失败、配置损坏或执行异常时，必须优先回退到 v0.42 已验证工作路径；不得因为增强层失败而让原本能完成的法律任务变成不可完成。**

本规范属于发布硬门。任何版本如果无法证明“关闭或故障新增能力后，旧任务仍可按旧路径完成”，不得升级为 Beta / Stable。

## 二、兼容优先级

```text
用户明确禁用本次爽律
        ↓
用户显式调用“爽律 / 调用爽律 / ShuangLaw”
        ↓
v0.43 新增增强能力（AutoActivation / Router v2 / 多Skill协同 / 主动建议）
        ↓ 失败、关闭或宿主不支持
Legacy Fallback
        ↓
v0.42 已验证入口、主技能路由、法律工作流与质量门
```

### 1. 显式调用是永久保底入口

用户明确说“调用爽律”“用爽律处理”“ShuangLaw”等时，必须绕过 AutoActivation 的自动判断。除非用户同一句明确要求不要使用爽律，或任务触发更高层安全/法律边界，否则不得因自动激活模块异常而拒绝进入爽律。

### 2. AutoActivation 失败只允许损失“无感体验”

宿主不支持 Skill metadata 自动发现、自动判断模块异常、配置文件缺失或 Feature Flag 关闭时：

- 不得破坏显式调用；
- 已经进入 Skill 的任务继续按 v0.42 路由执行；
- 必要时提示用户可继续使用“调用爽律”作为保底入口；
- 不得声称自动调用已成功。

### 3. Skill Router 新版失败回退 v0.42 路由

新版路由器无法唯一解析、配置错误或发生异常时，应调用 v0.42 的既有路由规则。若 v0.42 路由本身也无法确定唯一主技能，再进入原有 `UNRESOLVED` 处理，而不是把 Router v2 的错误冒充法律任务失败。

### 4. 主动建议失败不影响主任务

`ProactiveSuggestion` 永远是可选增强。生成失败、被关闭或不适用时，应直接跳过建议并完成用户原任务。不得把主动建议作为任何既有法律工作流的完成前置条件。

### 5. 多 Skill 协同失败先尝试旧能力路径

OCR、Web、数据库、Office 或其他 Skill 协同不可用时，按照《能力降级与失败处理规范》判断是否存在等价能力或旧版路径。能够退回现有文件读取、法律研究、文本交付等旧能力时应继续；只有核心专业要求确实无法满足时才 `BLOCKED`。

## 三、Feature Flags

v0.43 的新增能力必须通过 `05_工程执行层/配置/功能开关.json` 独立控制。至少包括：

- `auto_activation`
- `skill_router_v2`
- `multi_skill_collaboration`
- `proactive_suggestion`

关闭任一增强功能不得删除 v0.42 Core 文件、用户模板、用户个性化或旧显式调用入口。

## 四、失败回退记录

当增强能力发生故障并触发回退时，应记录 `FailureFallbackRecord`，至少说明：

- 哪个增强能力失败；
- 失败原因；
- 采用哪个旧路径；
- 回退是否成功；
- 是否影响最终任务范围或质量；
- 是否需要向用户披露降级。

**成功回退属于可接受降级，不应把整个任务判为失败。** 但如回退后丢失用户要求的核心能力，必须明示 `DOWNGRADED` 或 `BLOCKED`。

## 五、个性化与模板保护

回退机制不得以“恢复旧版”为名覆盖用户个性化。任何回退均继续遵守：

```text
Hard Guardrails
> Matter / Client Override
> User Personalization & User Template Assets
> Version Defaults
```

“回退 v0.42 路径”指回退**工作流和路由行为**，不是把用户空间恢复成 v0.42 默认状态。

## 六、发布硬门：Legacy Regression Gate

每次 v0.43+ 发布至少验证：

1. 显式调用在 `auto_activation=OFF` 时仍可进入爽律；
2. Router v2 关闭或模拟故障时，v0.42 典型刑事、民商事、合同、研究、顾问、尽调任务仍能得到相同主技能；
3. 主动建议关闭时主任务执行计划不受阻；
4. 多 Skill 协同增强关闭时，旧能力降级规则仍可加载；
5. 用户 MANUAL / CONFIRM / AUTO 与模板个性化仍被保留；
6. 新功能故障成功回退时质量门不应误判整个任务失败；
7. 新功能故障且没有可行旧路径时必须明确阻断，不得静默伪装成功。

## 七、版本纪律

以后每一个新增模块在进入 Core 前必须回答两个问题：

1. **它失败时爽律还能不能完成旧版本来能完成的任务？**
2. **如果不能，是否明确标记为 Breaking Change，并提供迁移方案？**

未回答这两个问题，不得进入正式版本。
