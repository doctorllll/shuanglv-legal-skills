# 自动激活与 Agent 原生调度规范

## 一、目标

爽律 Skill v0.43 开始把“用户主动喊出 Skill 名称”从默认入口降为兼容入口。安装在支持 Agent Skills 自动发现/自动激活的 Agent 后，用户可以直接提出法律任务，Agent 应根据 `SKILL.md` frontmatter 的 `name + description` 判断是否加载爽律 Skill。

> **目标体验：用户说“帮我审一下这个合同”，而不是“调用爽律帮我审一下这个合同”。**

自动激活只改变“什么时候进入爽律”，不改变事实核验、法律准确性、人工决定、个性化继承、模板资产保护等既有规则。

## 二、激活优先级

```text
用户明确禁用 / MANUAL偏好
        ↓
显式调用别名（强制入口）
        ↓
明确法律专业任务（AUTO）
        ↓
边界法律任务（结合偏好与语境）
        ↓
普通非法律任务（不激活）
```

### 1. 显式调用

用户说“调用爽律”“用爽律处理”“ShuangLaw”等，视为强制请求；除非任务本身违法、越权或超出硬边界，不再询问是否启用。

### 2. 明确法律专业任务

以下任务原则上可无感自动激活：

- 中国法法律研究、现行法核验、类案检索、裁判趋势分析；
- 刑事辩护、阅卷、会见、证据、控告、被害人代理等；
- 民商事诉讼/仲裁、请求抗辩、举证、保全、执行策略；
- 合同起草、审查、实际修订、谈判与交易支持；
- 法律意见书、专项法律分析、律师函、起诉状、答辩状、辩护词等专业法律文书；
- 尽职调查、专项事实调查；
- 多文书成套交付、共享事实字段和法律项目工作流。

### 3. 边界任务

“公司有什么风险”“这段话是否合适”“帮我看一下这个文件”等可能是法律任务，也可能只是普通咨询。不得因为出现“公司、协议、法院、风险”等单词就自动进入重型法律流程。应综合：

- 用户真实目标是否是法律判断/法律行动；
- 是否存在正式权利义务、争议、监管、证据或法律后果；
- 是否需要法律来源核验；
- 是否需要专业法律交付物；
- 当前用户的 `activation.mode`。

默认 `AUTO` 模式下，边界任务仅在法律专业性达到中高强度时自动进入；低强度时保持普通 Agent 工作方式，必要时再建议切换，不制造“每句话都弹一次确认”。

### 4. 明确不触发

- 日常聊天、生活建议、天气、普通知识问答；
- 非法律写作、普通宣传文案、一般翻译；
- 仅因文本出现“合同、法院、律师”等词但用户没有法律处理目标的任务；
- 用户明确要求本次不要使用爽律。

## 三、个性化激活模式

激活偏好进入 Personalization Layer，不写死在 Core：

- `AUTO`：法律专业任务自动激活，默认推荐；
- `CONFIRM`：识别到法律专业任务后，在真正进入完整工作流前询问一次；
- `MANUAL`：只有显式别名或用户明确选择爽律时激活。

相关设置：

- `activation.mode`
- `activation.show_notice`
- `activation.auto_threshold`
- `proactive_suggestion.enabled`
- `proactive_suggestion.max_per_turn`

升级仍遵守 `PRESERVE_USER`。用户原有写作、模板、交付、研究习惯不因激活机制升级被清空；用户以后明确选择 `MANUAL` 后，新版本也不得静默改回 `AUTO`。

## 四、透明但不打扰

默认 `activation.show_notice=false`。自动进入爽律时不需要每次输出“正在调用爽律”。

但系统应保留最小 `ActivationDecision`，在用户询问“为什么这样处理”“这次有没有用爽律”或调试时，可以说明：触发方式、任务类型、命中理由、是否受用户偏好影响。

## 五、宿主边界

自动激活能否真正发生取决于宿主 Agent 是否支持 Skill metadata 发现和自动选择。爽律负责提供规范的 `SKILL.md` metadata、触发描述、评测集和内部回退判断；若宿主平台只支持手动选择 Skill，爽律不能伪称已经自动激活。

## 六、触发质量

自动激活必须同时关注：

- `Trigger Recall`：该触发的法律任务不要漏掉；
- `Trigger Precision`：普通任务不要误触发；
- `Silent UX`：明确任务不重复询问；
- `Preference Compliance`：MANUAL/CONFIRM/AUTO 必须被尊重；
- `Legacy Alias Compatibility`：旧“调用爽律”方式继续有效。

开发评测见 `05_工程执行层/配置/技能触发评测集.json`。本地规则测试只作为工程代理指标，不冒充具体宿主模型的真实触发率。
## 七、失败回退

AutoActivation 是增强入口，不是爽律 Core 的生存依赖。

- 用户显式调用别名时应先识别显式入口，再依赖自动激活配置；
- `auto_activation` Feature Flag 关闭时，仅关闭无感触发，不关闭爽律；
- 自动激活配置缺失、损坏或判断异常时，已经进入 Skill 的任务继续走 v0.42 兼容路由；
- 宿主不支持 metadata 自动选择时，继续支持用户显式调用或宿主自身的手动绑定方式；
- 不得把“自动激活未发生”误报为“爽律无法处理该法律任务”。

详细规则见《旧版能力兼容与失败回退规范》。
