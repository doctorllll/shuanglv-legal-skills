# 爽律 Skill 基础能力地图

爽律 Skill 以律师业务工作流为纵向主线，同时在各业务阶段反复调用一组横向基础能力。横向能力不是独立产品功能，也不要求用户逐项调用，而是根据任务自动嵌入当前主技能。

## 一、两条主线

### 业务工作流：律师怎么推进事项

```text
目标与角色
→ 材料与事实
→ 法律路径与争点
→ 证据与研究
→ 程序与策略
→ 文书与沟通
→ 庭审/谈判/交易动作
→ 救济、执行或后续行动
```

不同业务会形成不同分支，不能把民商事、刑事、合同或尽调强行套进同一条流程。

### 分析与推理：律师怎么形成判断

```text
事实建模
↔ 问题构造
↔ 规范定位
↔ 证据检验
↔ 规则适用
↔ 竞争解释
↔ 策略选择
↔ 论证表达
```

## 二、横向基础能力

| 能力组 | 主要内容 |
|---|---|
| 材料理解 | 文件识别、结构化审阅、版本和来源定位、跨文件比较 |
| 事实分析 | 事实要素、时间线、主体关系、事实状态、冲突和缺口 |
| 问题分析 | 法律关系、请求抗辩、指控辩护、要件、争点和程序问题 |
| 证据分析 | 待证命题、单项证据、印证独立性、反向证据、证明责任和证据缺口 |
| 法律研究 | 规范定位、效力核验、特别规则、案例检索、类案比较和反向检索 |
| 法律推理 | 涵摄、演绎、类比与区别、归纳、解释、竞争模型和反事实检验 |
| 风险与策略 | 方案比较、时点选择、选项树、程序与商业约束、人工决策点 |
| 论证与交付 | 论证链、反方回应、剩余不确定性、文书生成基础和质量控制 |

## 三、公共执行控制

所有重要任务还受到以下公共机制约束：
- 渐进式加载；
- 动态检查清单；
- 通用结构化审阅；
- 跨模块交接与回写；
- 全链路溯源；
- 统一对抗性审查与结论回写；
- 策略选项比较、人工决策与升级；
- 正式交付质量门控；
- 项目执行说明书。

这些机制的作用是让 Agent 更稳定地执行专业方法，而不是替代实体法律判断。

## 事项工作模型与分析工具

复杂任务的横向分析能力通过事项工作模型连接：

```text
TaskProfile
→ IssueTree
→ ReviewQuestionSet / StructuredReview
→ Fact / Evidence
→ AuthorityMap / CaseMatrix
→ ArgumentRecord / ArgumentMap
→ Finding
→ Option / Decision
→ DeliverableClaim
```

这些结构不是新的独立业务 Skill，而是刑事、民商事、合同、尽调、法律顾问和法律研究可以按需调用的公共工作方法。简单任务不要求机械展开完整对象集合。
