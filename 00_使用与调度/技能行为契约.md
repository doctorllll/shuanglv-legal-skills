# 技能行为契约

## 一、作用

技能行为契约规定爽律 Skill 在关键场景中**必须做什么、不得做什么**。它不是评分表，也不是正式测试用例，而是 Agent 执行时应持续满足的最低行为约束。

## 二、核心行为契约

| ID | 场景 | 必须行为 |
|---|---|---|
| BC-FACT-01 | 用户陈述或未核实信息 | 不得静默提升为 VERIFIED |
| BC-MAT-01 | 收到文件 | RECEIVED 不得冒充 REVIEWED |
| BC-LOC-01 | 重要事实/法律/案例 | 保留足以回查的来源定位 |
| BC-LAW-01 | 需要现行法 | 必须实际核验权威来源；模型记忆不得冒充核验 |
| BC-CASE-01 | 用案例支持结论 | 至少说明决定性相似点、区别点和使用目的 |
| BC-ISSUE-01 | 复杂问题 | 先形成可处理的问题结构，不从笼统问题直接跳结论 |
| BC-REVIEW-01 | 多文件比较 | 先确定任务驱动的审阅问题，不机械套固定大表 |
| BC-ARG-01 | 重要专业结论 | 保留规则—事实—证据—推理—结论的可审计连接 |
| BC-COUNTER-01 | 重要结论 | 构建能够真实施压的竞争解释/最强反方 |
| BC-ADV-01 | 对抗性审查发现重要问题 | 必须修订原分析或明确维持理由 |
| BC-OPTION-01 | 存在多个重大行动方案 | 使用一致维度比较，重大处分留给人工决定 |
| BC-EXT-01 | 敏感材料外部处理 | 供应方、目的、范围变化时必须重新取得相应授权 |
| BC-CAP-01 | 工具能力不足 | 不得假装已实现；应降级、披露或阻断 |
| BC-PLAN-01 | 复杂/跨模块任务 | 形成可见执行计划；只有出现实质决策或风险动作时才要求额外确认 |
| BC-WRITEBACK-01 | 新事实/规则改变原判断 | 必须回写受影响对象，不把旧结论继续作为最新结论 |

## 三、业务技能可以增加更具体的行为契约

例如刑事案件可增加“不能只分析有罪路径”“证据印证必须检查同源问题”“控告侧不得把客户法律评价直接写成犯罪事实”；合同可增加“审查必须绑定客户立场和交易目标”；尽调可增加“未发现不得自动表述为不存在风险”。

业务契约不得降低本文件的公共底线。

## 四、执行状态

重要或正式任务结束前，应检查是否存在关键行为契约违反。发现违反时，应先修正对应步骤；无法修正的，应说明限制并阻断无保留正式交付。
