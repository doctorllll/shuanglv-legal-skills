# 测试基线与能力边界

> 当前版本：v0.41 公开共创版｜第一轮实测候选基线

## 一、基线定位

本版本作为第一轮真实律师使用测试的固定基线。核心目标不是覆盖所有法律业务，而是验证：在相同模型、材料和外部数据条件下，爽律 Skill 是否能够稳定提高事实建模、问题识别、证据分析、法律研究、推理、对抗审查、策略和正式交付质量。

## 二、当前重点支持范围

- 法律研究与多源资料融合：法律规范、案例、反向观点、权威图谱、类案矩阵和来源核验；
- 刑事案件办理：辩护、被害人代理、刑事控告/报案、阅卷、证据、罪名/刑事路径、程序和阶段策略；
- 民商事争议解决：请求与抗辩、要件争点、举证、程序、庭审、和解及执行衔接；
- 合同与交易工作：交易结构、履行、风险、起草、审查、修改和谈判；
- 法律顾问与专项法律分析：问题重构、研究、方案比较、建议与行动计划；
- 尽职调查：交易/目标尽调、资料核验、信息缺口、风险和交易交接；
- 法律文书质量与格式控制：结构、论证、语言、引用、格式、版本和交付；
- 多模态输入适配：仅在当前 Agent 或外部工具具备相应能力时使用。

## 三、当前部分支持范围

### 民商事再审专项

提供通用的问题识别、裁判理由复核、事实/证据/法律/程序检查和专项研究入口；具体再审事由、程序条件、期限和最新规则必须运行时核验。当前不将其表述为独立完整的再审专项工作流。

### 专项事实调查

提供范围、来源、访谈、证据保全、交叉核验、问题整理和报告等通用事实调查框架。涉及员工调查、举报保护、劳动、个人信息/隐私、纪律处分等专项规则时，必须补充现行法研究并由律师复核。

## 四、运行环境依赖

爽律 Skill 不自带法律数据库、用户知识库、OCR、Office 或持久化案件系统。外部能力是否可用，以当前 Agent 的实际能力和用户授权为准。不能真实调用的能力不得在结果中写成已经完成。

## 五、格式基线

正式中文法律文书默认适用《法律文书统一样式规范》。正文自然段及正文内结构层次小标题原则上首行缩进 2 个中文字符；主标题居中；固定栏目和特定文种标签优先服从官方样式、受理机关要求或用户指定模板。

## 六、基线冻结原则

进入第一轮实测后，不因主观设想继续增加大模块。后续版本优先依据真实使用中的失败、遗漏、误触发、过度流程化和交付问题进行修正。

## 本基线新增重点

- 复杂材料默认增加事项快速理解包与 DiagramSpec；
- 普通用户图形优先 PNG，纯文本模型可用自包含 HTML + 内嵌 SVG 保底；
- 合同 REVIEW/REVISE 强制区分“意见报告”和“实际修改文本”，修改任务不得只出报告；
- 合同新增履约可证明性、权利义务边界、争议解释压力测试和条款覆盖地图。

## v0.43 正式版累计增量

v0.43 正式版在 v0.41 基线上累计增加文书成文策略/结构性重写、个性化安全升级、模板资产/成套交付，以及法律研究的渠道中立信源评价、递进检索、充分性判断和研究交付物配置。个性化迁移专项自动断言 21/21 通过；运行包 JSON、Schema、Python、Manifest Path、来源泄漏和执行器冒烟验证均通过。

这些结果属于工程验证，不等同于外部第三方律师对所有文书质量的盲评。真实任务中的新 Failure 继续进入后续版本。


### RC3 发布层说明

RC3 仅调整贡献者署名与致谢范围，不改变 RC2 已验证的业务工作流、质量门、个性化继承机制或能力边界。


## v0.43 Agent Native 能力边界

本版新增的本地激活规则与触发评测集只能验证规则/metadata设计，不等同于任何具体 Agent 宿主的真实自动触发率。真实宿主仍需分别测 Trigger Recall / Precision。
