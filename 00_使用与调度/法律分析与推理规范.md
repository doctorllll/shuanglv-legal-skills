# 法律分析与推理规范

## 一、目的

爽律 Skill 不把法律工作理解为“按固定步骤生成答案”。任何重要法律任务，都应同时具备两条主线：

- **业务工作流**：律师在当前业务场景下应当做什么；
- **分析与推理闭环**：律师如何从材料、事实、规则和证据逐步形成可检验的专业判断。

分析与推理闭环不是独立 Skill，也不是要求模型展示隐藏思维过程。它要求 Agent 形成**可审计的中间成果、判断依据、竞争观点和未解决问题**。

所有重要分析同时适用《全链路溯源规范》：重要结论应能够回到事实、证据、法律/案例来源及其精确定位。

## 二、八类分析动作

```text
事实建模
↔ 问题构造
↔ 规范定位
↔ 证据检验
↔ 规则适用
↔ 竞争解释
↔ 策略选择
↔ 论证表达
```

箭头是双向的。发现新规则、新证据或新解释后，允许并且经常需要回到前面的事实、问题或研究环节重新分析；如已存在上游论证或结论，应记录回写对象和修订结果。

### 1. 事实建模

从材料中提取并组织具有法律意义的事实，而不是把材料全文改写成摘要。

至少关注：
- 主体及其身份、角色、关系；
- 行为、事件和交易；
- 时间、地点、金额、标的；
- 主观认识、目的、意思表示及其事实基础；
- 因果、履行、损害、结果；
- 程序事实；
- 关键事实之间的先后、依赖和冲突。

所有重要事实必须保留事实状态：`VERIFIED / ALLEGED / DISPUTED / INFERRED / UNKNOWN`。事实的重要性取决于其是否会影响法律路径、证据评价、程序选择或策略，而不取决于叙述篇幅。

### 2. 问题构造

Agent 不能只回答用户已经准确提出的问题。应当从客户目标、事实模型和程序位置中主动发现需要解决的问题，例如：
- 法律关系和法律效果；
- 请求、否认、抗辩、反抗辩；
- 指控、出罪、罪轻或其他刑事评价路径；
- 构成要件和争议焦点；
- 证明责任和证据问题；
- 管辖、时效、程序和救济；
- 交易、履行、风险与谈判问题；
- 需要客户或律师作决定的策略问题。

每个重要问题都应说明：为什么重要、什么事实会影响它、需要什么法律或证据进一步解决。

### 3. 规范定位

围绕已经构造的问题定位法律规则和解释材料，而不是先堆积法条再寻找适用场景。

至少检查：
- 规范层级和权威性；
- 当前有效文本与时间效力；
- 一般规则和特别规则；
- 实体、程序和证据规则；
- 例外、限制、过渡安排；
- 需要案例说明的概念边界或适用差异。

需要现行法、案例或权威资料时，调用“法律研究与多源资料融合”。未真实核验的规则不得标记为已核验。

### 4. 证据检验

把“法律上需要成立的命题”与“材料实际上能够证明的内容”连接起来。

至少回答：
- 当前待证命题是什么；
- 每项证据能够证明到什么程度；
- 来源、真实性、合法性、关联性、可靠性、完整性如何；
- 证据是否真正独立，还是同源重复；
- 有什么反向材料或矛盾；
- 如果某一叙事为真，通常还应出现什么材料；
- 缺失材料能说明什么，又不能说明什么；
- 是否存在其他能够解释现有证据的事实模型。

证据分析不得用一个总分替代分维评价。

### 5. 规则适用

把已核验或明确标示状态的规则用于案件事实。根据任务需要组合使用：
- 要件涵摄和演绎推理；
- 类比与区别；
- 从多份案例或材料中归纳共性与差异；
- 文义、体系、目的等解释方法；
- 多规则之间的协调；
- 主位与备位法律路径比较。

必须展示可审计的“规则—事实—证据—结论”关系，并保留对应对象 ID 或同等可回查关系。不得用“综合判断”“显然”“因此”替代中间论证。

### 6. 竞争解释

重要结论至少检查一个能够对当前结论形成真实压力的竞争模型。

可以使用：
- 对方最强事实模型；
- 对方最强法律解释；
- 替代因果或行为解释；
- 竞争性定性；
- 反事实测试；
- “如果我方判断错误，最可能出现什么材料”的证伪测试；
- 结论翻转点分析。

竞争解释不是为了形式上的“两边都说”，而是为了发现当前结论最脆弱的前提。

### 7. 策略选择

法律上可能成立的方案，不当然是律师应当立即采取的方案。策略应同时考虑：
- 客户真实目标；
- 事实和证据成熟度；
- 程序时点；
- 对方可能反应；
- 补证、披露或行动可能造成的二次影响；
- 时间、成本、履行和执行；
- 商业关系、声誉和其他非法律约束；
- 是否存在主位、备位、替代或延期方案。

需要比较多个方案时形成 `OptionRecord` 或同等选项树/方案比较表；重大处分或不可逆决定形成 `DecisionRecord`，按人工升级规则停在用户/律师决定节点。

### 8. 论证表达

最终交付必须来自前面的分析，而不是直接从原始材料生成。正式交付中的重要命题应建立 `DeliverableClaim` 或同等映射，使文书结论能够反向回到上游分析。

重要结论尽量形成：

```text
结论
← 适用规则
← 关键事实
← 证据与来源
← 推理连接
← 主要反方观点
← 回应
← 剩余不确定性与行动建议
```

对外文书可以根据策略取舍信息，但内部分析不得因此删除重大不利事实、反向证据或未解决缺口。

## 三、分析闭环的触发强度

### 简单任务

可以缩减步骤，但不得牺牲事实状态、法律来源和结论边界。

### 重要任务

至少形成：事实模型、问题结构、规范依据、证据状态、规则适用、竞争解释、策略或行动建议，并执行对抗性审查。

### 多文件或复杂案件

原则上先执行《通用结构化审阅规范》，再进入实体分析。材料数量不大但存在版本、冲突、证据或跨来源比较需求时，也应使用结构化审阅。

## 四、禁止模式

- 从用户叙述直接跳到法律结论；
- 从法条名称直接跳到适用结论；
- 只寻找支持已有结论的材料；
- 把案例相似当成结论相同；
- 用未核验的模型记忆冒充现行法；
- 用“可能性百分比”替代证据和推理；
- 为了流程完整机械执行不必要步骤；
- 把可审计论证要求理解为要求模型公开隐藏思维过程。

## 五、问题树与论证地图

复杂任务的问题构造应尽量形成可回写的问题树；存在多个竞争观点时，可使用论证地图把 ArgumentRecord 之间的支持、攻击、回应、限制和依赖关系显式化。问题树和论证地图只组织可审计的专业理由，不要求模型披露隐藏思维过程。
