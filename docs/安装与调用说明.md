# 爽律 Skill v0.48｜安装与调用说明

## 安装成功的最低条件

1. Host 能读取 `runtime/shuanglv-legal-skills/SKILL.md`；
2. `SKILL.md` 能按需访问同目录 `references/` 中的 Load Units；
3. Host 具备的 Web、法律数据库、OCR、Office/PDF、文件读写等能力按其自身机制提供，爽律只声明专业需求、质量边界和授权边界；
4. `docs/`、开发测试材料和用户空间示例不得当作 Runtime 常驻指令加载。

## Agent Skills Discovery

`runtime/shuanglv-legal-skills/SKILL.md` 顶部包含 Agent Skills 规范 YAML frontmatter：

- `name: shuanglv-legal-skills`，与父目录名称一致；
- `description` 同时说明爽律能做什么、在什么任务下应使用；
- `license / compatibility / metadata` 提供许可、宿主兼容和项目元数据。

在支持 Agent Skills discovery 的 Host 中，宿主通常只需先读取 `name + description` 即可决定是否加载完整 Skill。实质性的中国法律专业任务可以按语义触发，不要求用户每次显式说“调用爽律”。

同时兼容显式调用：

- 调用爽律
- 用爽律做
- 用爽律处理
- 爽律 Skill
- ShuangLaw

普通写作、日常问题，或者正文/附件中仅出现“法律、合同、证据、案例”等词，不应仅凭关键词误触发。

> 历史说明：该 discovery 入口问题最早由社区贡献者 `doctorllll` 在 GitHub PR #1 中明确提出，v0.43 主线曾吸收并扩展。v0.48 维护修复恢复该能力，详细记录见 `ACKNOWLEDGEMENTS.md` 与《v0.48维护修复说明》。

## 不支持自动发现的 Host

Host 不支持 Agent Skills discovery 时，不得声称已经自动激活。应采用平台自身的 Skill 注册、项目规则、绑定或显式入口机制，使其能够读取：

`runtime/shuanglv-legal-skills/SKILL.md`

之后再按需访问 `references/`。

## 调用逻辑

用户不需要指定内部模块。例如：

- “审这份合同，我们代表甲方，先做风险分析再实际修改。”
- “完整阅卷并形成辩护方案，先不要直接写辩护词。”
- “研究这个法律问题，核验现行法、地方规则和反向案例。”
- “只统一这份法律意见书格式，不改变实体内容。”

系统应依据真实目标和交付要求选择最低充分能力集合，而不是按材料中的法律关键词扩大任务。

## 平台能力不足

- 没有 OCR / 音视频识别：说明输入能力缺口，不得假装已经读完；
- 没有 Word/PDF 原生渲染：输出内容与确定性格式要求，并真实说明降级；
- 不支持原生 Track Changes：不得伪造修订模式；
- 没有持久化状态：可以使用当前会话的 Minimal Matter State，但不得宣称已经长期保存；
- 外部处理敏感材料：API Key、连接器存在或能力可用均不等于用户已授权外发。

## 升级原则

Core 与用户资产分离。用户模板、明确确认的合法偏好、Matter 资料不应因升级被静默覆盖；历史偏好也不能关闭事实真实性、现行法核验、授权、来源保真等硬约束。

任何后续 Runtime 压缩、迁移或重构，都必须保留有效的 `SKILL.md` discovery metadata；如果 frontmatter 缺失、不可解析、`name` 与目录不一致或 `description` 为空，应直接阻断发布。
