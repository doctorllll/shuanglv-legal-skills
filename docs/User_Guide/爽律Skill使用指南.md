# 爽律 Skill 使用指南

> 面向律师用户的使用说明。本文只解释“有什么能力、什么时候用、怎么用”，不复制内部 Runtime 规则。实际能力边界以同版本 Runtime 为准。

## 一、爽律 Skill 是什么

爽律 Skill 是一套面向中国律师工作的专业工作流系统。它的作用不是替代律师作最终专业决定，而是把法律任务拆成事实、证据、研究、论证、策略、写作、复核等必要环节，并根据具体任务按需调用已有领域方法，使 AI 的工作过程更接近律师办案和交付逻辑。

它重点解决四类问题：

- **材料很多但抓不住问题**：先建立材料、事实、时间线、争点和缺口，再进入法律判断；
- **AI 容易把推测写成事实**：区分已核验事实、当事人陈述、推断、争议和未知；
- **法律检索和类案容易“搜到就算”**：要求关注权威来源、现行效力、反向来源、案例可比性和检索充分性；
- **文书容易模板化或把内部工作语言直接写进成品**：先完成内部分析，再根据受众、文种和立场形成对外交付文本，并在正式交付前复核。

### 与普通 ChatGPT 使用方式的区别

普通对话通常只围绕当前提示直接生成答案；爽律 Skill 更强调：

1. 先识别真实任务目标和交付物，而不是只看文件名或关键词；
2. 只加载完成任务所需的专业能力，不为“显得全面”无限扩展；
3. 重要事实、证据、法律和案例尽量保持来源与状态；
4. 对高影响结论进行反向审查，寻找可能翻转结论的事实、证据或规则；
5. 把内部分析与对外交付分开，避免工作底稿、红队意见、未核实假设或工具过程泄漏到正式文书；
6. 当前平台没有 OCR、数据库、Word 原生修订等能力时，如实说明并降级，不假装已经执行。

## 二、适合哪些法律工作场景

当前 v0.48 能力范围内，适合：

- 刑事案件材料梳理、会见/阅卷辅助、证据与罪名分析、阶段策略、辩护文书辅助；
- 民商事争议的请求与抗辩分析、证据与举证责任、程序策略、诉讼/仲裁文书辅助；
- 合同起草、审查、修改、交易结构、履约风险和谈判支持；
- 法律尽调和有明确边界的专项事实调查；
- 法律研究、现行法核验、类案比较和反向检索；
- 日常法律咨询、专项法律分析、方案比较和行动建议；
- 法律文书的结构、论证、语言、引用、格式与交付质量审查；
- 大量 PDF、扫描件、表格、图片、音视频等材料的结构化处理——前提是当前 Host 具备相应读取能力。

## 三、不适合或不能直接承担的场景

- 不能替律师、当事人或客户作认罪、放弃权利、上诉、和解、重大交易立场等最终决定；
- 不是法律数据库本身，也不是 OCR、Office、PDF、长期项目管理或持久记忆引擎；
- 未实际读取、检索、核验、发送、提交、签署或修改外部系统时，不能声称已经完成；
- 需要现行法律依据但当前无法访问可靠来源时，只能给出明确标注的初步/待核验分析，不能冒充已核验结论；
- 不应把高度敏感材料仅因为“存在 API Key 或连接器”就自动发给第三方处理；
- 不应要求 AI 根据明显缺失的关键事实直接“给确定结论”。

## 四、怎么调用

用户不需要记住内部模块名。可以直接说：

- “调用爽律审这份合同，站在甲方立场，给我修改稿和重大风险清单。”
- “用爽律完整梳理这组刑事卷宗，先做事实与证据分析，再形成辩护思路。”
- “用爽律研究这个法律问题，重点核验现行法、相反案例和裁判分歧。”
- “调用爽律把这份内部案件分析转成提交法院的代理词，正式交付前做一次对外交付检查。”

如果当前 Host 支持自动 Skill 发现，直接描述法律任务即可；不支持时，可使用“爽律 / ShuangLaw”作为显式调用词。

## 五、推荐的任务描述方式

一个高质量任务至少说明五件事：

**1. 角色/立场**：代表谁、站在哪一方。  
**2. 目标**：要解决什么问题，而不是笼统说“看看”。  
**3. 材料范围**：哪些文件必须审、哪些只是背景。  
**4. 交付物**：要分析报告、清单、修改稿、正式文书还是其他成果。  
**5. 特别约束**：是否必须检索现行法、是否只改格式、是否不得改变实体内容、是否需要引用定位等。

示例：

> 调用爽律。我们代表被告。请审阅我上传的起诉状、合同、付款记录和聊天记录：先建立争点和证据缺口，再分析请求权基础与抗辩路径；需要现行法的地方请实际核验。最后先给内部分析版，不要直接生成答辩状。

## 六、内部分析和正式交付最好分两步

对于诉讼、刑事、合同重大修改、法律意见等重要任务，推荐：

1. **内部分析阶段**：允许充分暴露风险、弱点、反方观点、假设和策略选项；
2. **对外交付阶段**：明确文书读者、立场和目的，再要求将有价值的分析转换为可对外使用的命题；
3. **最终检查**：要求核查事实状态、法律来源、内部分析泄漏、模板化表达和格式/版本问题。

详见《输出质量控制指南》。

## 七、第一次使用建议

第一次使用不要从“帮我写一份很专业的文书”开始。更稳定的方式是：**先让爽律理解材料和任务，再做分析，再决定是否生成正式文书。**

可直接从《快速开始指南》开始。
