# civil-commercial-dispute-resolution（民商事争议解决）

## 一、用途

用于民事、商事诉讼和仲裁中的请求/抗辩、事实证据、程序、策略、庭审和执行分析。核心是把客户目标转成可证明、可程序化、可执行的争议解决路径。

## 二、适用场景

- 起诉前评估请求权基础、管辖、时效和保全；
- 被告侧拆解请求、否认、抗辩和反诉路径；
- 合同履行、付款、股权、公司或其他民商事争议材料整理；
- 举证责任、待证命题、证据缺口和证据组织；
- 仲裁条款、程序期限、保全、上诉/再审/执行等问题辅助；
- 起诉状、答辩状、代理意见和庭前准备。

## 三、输入材料要求

说明代表方、客户目标、当前阶段、对方请求/主张、主要合同或交易材料、往来记录、付款/履行证据和已经发生的程序行为。时间节点和送达信息对程序判断尤其重要。

## 四、输出结果

可生成事实模型、请求/抗辩矩阵、要件—主张—争点矩阵、证据与举证责任表、程序问题清单、诉讼/仲裁策略、和解/执行考虑、庭前准备材料和诉讼文书草稿。

## 五、推荐使用方式

先明确“客户想达到什么”，再决定请求和程序动作；把实体与程序并行审查；每一个重要主张都尽量对应待证命题和证据。正式文书前先做内部案件分析和对抗性复核。

## 六、常见错误

- 只按对方起诉状的章节顺序分析；
- 只讨论实体法，不看管辖、时效、保全、仲裁等程序问题；
- 有证据就默认承担的待证命题已经证明；
- 把“可能和解”当作自动建议，不结合执行、成本和客户目标；
- 尚未建立请求/抗辩结构就直接生成答辩状。

## 七、示例任务

1. “我们代表被告。请把起诉状 4 项请求拆成请求权基础、构成要件、我方否认/抗辩、举证责任和现有证据五列，先不要写答辩状。”
2. “评估这个买卖合同纠纷是否需要财产保全：结合债权证据、对方资产线索、时间成本和错误保全风险给出路径。”
3. “庭前新增了对方一组微信记录。请只更新争点和证据矩阵，判断是否需要调整质证、发问和代理意见。”
