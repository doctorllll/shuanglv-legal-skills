# legal-research-and-source-fusion（法律研究与多源资料融合）

## 一、用途

用于现行法律规范、案例、官方解释、司法实践资料和专业观点的检索、核验、比较与整合。重点不是“多搜几个结果”，而是回答：什么来源能支持什么命题、现在是否有效、有没有相反路径、案例是否真正可比、什么时候可以停止检索。

## 二、适用场景

- 查询某一争点的现行法和配套规则；
- 类案检索、裁判分歧和边界案例研究；
- 刑事、民商事、合同、尽调或专项意见中的法律依据核验；
- 对已有法律意见做反向检索，寻找遗漏的上位规范、例外或不利案例；
- 核验网页、公众号、数据库摘要中的法条或案例是否能回到原始来源。

## 三、输入材料要求

最好提供：明确法律问题、适用法域/辖区、关键时间点、与问题有关的基本事实，以及希望核验的来源或已有检索结果。若事实尚不完整，应明确哪些是已确认、哪些只是工作假设。

## 四、输出结果

可生成研究问题图、权威来源包、现行效力状态、类案比较矩阵、支持/反向/边界来源、重大分歧、检索缺口和阶段性研究结论。实际可访问哪些数据库或网页取决于当前 Host 的连接能力。

## 五、推荐使用方式

先把法律问题拆成可检索命题，再指定时间和法域；重要结论要求实际核验原始/权威来源；类案要求比较决定性事实和裁判理由；最后要求检查反向来源和是否达到研究充分性。不要以“搜到数量”代替研究质量。

## 六、常见错误

- 只给一个宽泛关键词，要求“找所有案例”；
- 把搜索摘要、二手文章或数据库标签直接当作权威结论；
- 只找支持我方的案例；
- 只因罪名/案由相同就认为是类案；
- 没有实际核验就要求写“现行法律明确规定”；
- 用案例数量而不是信息覆盖决定停止检索。

## 七、示例任务

1. “研究电子大麻烟入境相关刑事责任：先核验现行规范和管制物质属性，再找支持、反向和边界案例，区分携带数量、主观目的和入境环节。”
2. “请核验这份法律意见中的 8 个法条和 5 个案例，确认现行效力、原文定位和是否真的支持对应命题；发现反向来源一并列出。”
3. “围绕‘被骗时所在地’与刑事管辖问题做类案研究，不要只按关键词相似，比较决定性事实和裁判/处理理由。”
