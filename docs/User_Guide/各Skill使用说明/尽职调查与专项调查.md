# due-diligence-and-investigation（尽职调查与专项调查）

## 一、用途

用于交易型法律尽调及有明确范围的专项事实调查。核心不是“把材料做摘要”，而是围绕客户决策确定要查什么、来源是否可靠、缺什么、哪些问题会改变交易，以及风险怎样进入合同或后续行动。

## 二、适用场景

- 股权/资产交易、投资、融资、合作等法律尽调；
- 数据室材料整理和缺件追踪；
- 公开资料、访谈、现场和第三方信息交叉核验；
- 重大风险事项（Red Flag）识别；
- 有边界的专项事实调查；
- 尽调结果向交易合同、专项意见或后续整改交接。

## 三、输入材料要求

说明尽调服务的交易/决策、基准日、范围和排除项、客户重点、已有资料清单和数据室材料。专项调查还应明确调查问题、允许的来源和合规边界。

## 四、输出结果

可生成尽调范围、动态资料清单、材料台账、事实核验表、信息缺口、补件清单、Red Flag、风险影响、补救/交易措施、尽调报告内容和向合同/法律顾问工作流的交接事项。

## 五、推荐使用方式

先定目的和重要性再发资料清单；区分“已收到”“已读取”“已核验”；重要事实尽量多源交叉；把“未提供/未找到”与“不存在”分开；每个重大风险尽量对应下一步动作。

## 六、常见错误

- 直接套一份固定尽调清单，不问交易目的；
- 缺材料就默认最坏事实成立；
- 公开查询无结果就写“不存在”；
- 只做文件摘要，不做来源核验和交易影响；
- 把所有问题都升级成“重大风险”；
- 尽调报告写完后没有把风险传给合同、价格、交割条件或整改动作。

## 七、示例任务

1. “这是投资项目数据室。先按投资决策建立尽调范围和动态资料清单，再标出 Expected-but-Missing，不要因为缺件直接认定风险事实成立。”
2. “请交叉核验工商登记、客户提供公司章程和股东访谈三类来源，区分一致、冲突、未核验事实。”
3. “把已经确认的 6 个 Red Flag 转成交易措施：哪些需要交割前解决、先决条件、陈述保证、赔偿、价格调整或退出机制。”
