# contract-and-transaction-work（合同与交易工作）

## 一、用途

用于合同起草、审查、修改、交易结构、履行流程、风险分配和谈判支持。它不是“挑错字”，而是检查交易能否按预期发生、风险由谁承担、履约是否可操作和争议时是否可证明。

## 二、适用场景

- 从零起草合同或在模板基础上重构；
- 站在某一方立场审查并实际修改合同；
- 多协议、附件、订单、框架协议之间的文件架构；
- 履约流程、付款、验收、交付、通知、终止等机制检查；
- 违约、第三方失败、审批失败、市场变化等风险场景；
- 谈判方案、让步条件和替代条款；
- 签署、交割和履约交接。

## 三、输入材料要求

说明代表方、交易目标、对方和谈判地位、合同当前阶段、不可接受/可接受风险、商业条件和已有模板/附件。若要求修改，应提供可编辑文本或当前 Host 可可靠读取的文件。

## 四、输出结果

可生成交易结构分析、风险清单、条款审查意见、实际修改稿、清洁稿/差异稿要求、谈判表、修改说明、履约义务地图和签署/履行检查清单。原生 Track Changes、DOCX/PDF 等取决于 Host 的真实文件能力。

## 五、推荐使用方式

先确认代表方和交易目标，再审结构、履约和风险，最后进入文字条款。REVIEW/REVISE 任务应要求“实际落稿”，而不是只给建议。重大法律问题再调用法律研究；格式要求与实体修改分开。

## 六、常见错误

- 不说明代表哪一方；
- 只要求“找风险”，却不说客户目标和可接受底线；
- 逐条挑错但不检查交易结构和履约依赖；
- 提了修改意见却不要求实际改进合同；
- 把红字文本冒充 Word 原生修订；
- 用户明确“只调格式”时仍擅自改实体条款。

## 七、示例任务

1. “我们代表采购方。重点不能接受预付款无保障、无限责任和单方变更价格。请先做交易和履约风险图，再直接修改合同并给修改说明。”
2. “这是主协议+三个附件+订单模板。请检查文件之间的定义、优先顺序、付款/验收和违约责任是否互相冲突。”
3. “对方拒绝删除自动续期条款。请给 3 个可谈判替代方案，说明每个方案交换了什么风险，但不要替客户决定最终接受哪一个。”
