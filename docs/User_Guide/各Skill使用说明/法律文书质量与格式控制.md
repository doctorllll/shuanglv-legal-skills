# legal-document-quality-control（法律文书质量与格式控制）

## 一、用途

用于把已有事实、法律研究、分析和草稿转化为可以交付的法律文书，并对结构、论证、语言、引用、受众、版本和格式进行质量控制。它不替代刑事、民商事、合同等业务分析本身。

## 二、适用场景

- 起诉状、答辩状、代理词、辩护词、律师函、法律意见书等成稿；
- 对已有文书做结构和论证重构；
- 去除模板化、AI 问答式和同构表达；
- 事实、法条、案例、证据引用和附件一致性检查；
- 清洁稿、差异稿、批注/修订、格式统一；
- 只调格式且不得改变实体内容的 FORMAT_ONLY；
- 正式发出前的对抗性和对外交付卫生检查。

## 三、输入材料要求

至少提供目标文书/上游分析、作者与主要读者、文书目的、代表立场、强制格式或用户模板。若要求核验事实/法律，还应提供来源材料或允许调用相应能力。

## 四、输出结果

可生成文书结构、正式草稿/清洁稿、质量审查意见、差异稿/原生修订要求、批注意见、修改说明、版本记录、最终 QA 结果和格式/渲染要求。真实 DOCX/PDF/Track Changes 能力取决于当前宿主。

## 五、推荐使用方式

先确认文书“谁写给谁、为了什么”；不要让 AI 从原始卷宗直接跳到成品。先完成业务分析，再做 文书成文计划 和论证排序；重要文书先内部审查，最后做 内部分析 → 对外交付 转换和 正式交付检查。

## 六、常见错误

- 只说“写专业一点”，不给受众、立场和目标；
- 把原始材料顺序直接变成文书结构；
- 所有争点平均展开，导致重点不突出；
- 一句话一段、大量小标题、机械“首先其次最后”；
- 直接把内部弱点、红队语言、TODO 或未核实假设写进对外文书；
- 当前宿主 不支持原生修订却声称已经做 Track Changes；
- 用户只要求格式调整时擅自改实体内容。

## 七、示例任务

1. “这是已完成的案件分析。请形成提交法院的代理词：观点前置，按决定性争点排序，不按内部 IssueTree 机械展开；正式输出前做 正式交付检查。”
2. “这份律师函内容已定，只做语气、结构和可执行性优化，不增加未经材料支持的事实或威胁性表述。”
3. “只统一这份法律意见书的标题层级、正文缩进、编号和页码，不改变任何实体内容；发现实体错误单独提示，不静默修改。”
