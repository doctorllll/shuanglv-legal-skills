# 运行能力契约 V0.2

## 1. 不假设所有 Agent 相同

爽律 Skill 必须以**当前运行环境实际具备的能力**为准，不把某个平台、模型、插件或历史版本的能力自动外推到其他环境。

## 2. 能力档案

运行环境可使用 `RuntimeCapabilityProfile` 记录当前已验证能力。除传统文件能力外，当前还记录：

- 法律权威信源；
- 案例信源；
- 用户私有知识库；
- 公开 Web；
- OCR/音视频；
- DOCX/XLSX/PDF 等交付能力；
- 原生修订模式等特殊能力。

每项能力应尽量记录：能力类型、提供方式、当前状态、可信等级、是否保留来源定位、数据边界、限制和核验时间。

## 3. 状态

```text
VERIFIED_SUPPORTED
SUPPORTED_BUT_UNVERIFIED
PARTIAL
UNSUPPORTED
DOWNGRADED
BLOCKED
```

未经实际验证的“理论支持”不得写成 `VERIFIED_SUPPORTED`。

## 4. 通用选择顺序

```text
任务能力需求
→ 当前 Agent 原生能力
→ 用户已接入的插件/连接器/Skill
→ 本地工具
→ 用户控制基础设施
→ 第三方云服务
```

法律信源另按权威性和可回查性排序；第三方云处理敏感资料另受《外部处理风险门控》约束。

## 5. 核心规则

- API Key 存在 ≠ 用户授权当前文件外发；
- 连接器已安装 ≠ 当前账号一定有访问权限；
- 数据库能搜索 ≠ 搜索摘要已经核验原文；
- 用户知识库有答案 ≠ 该答案是现行法或已核验事实；
- 某一 Agent 支持 ≠ 其他 Agent 自动支持；
- 某一版本支持 ≠ 永久支持；
- 能力不满足但有可接受替代方案 → 明示 `DOWNGRADED`；
- 核心交付要求无替代且无法满足 → `BLOCKED`。

## 6. 能力调用记录

重要任务可用 `CapabilityInvocationRecord` 记录：调用了什么能力、目的、输入范围、输出来源、是否涉及外部传输、限制以及是否需要用户授权。该记录服务于审计和后续复核，不用于评价实体法律结论正确性。
