# runtime-capability-contract（运行能力契约） V0.1

## 1. 不假设所有 Agent 相同

在需要特定文件能力时，当前 运行环境 只需声明与任务有关的能力，例如：

```text
can_read_scanned_pdf
can_preserve_pdf_page_locator
can_ocr
can_transcribe_audio_with_timestamp
can_analyze_video_with_timestamp
can_edit_docx
can_native_track_changes
can_write_comments
can_edit_xlsx_preserve_formulas
can_generate_pdf
```

## 2. 能力来源

优先：
1. 当前 Agent 的原生能力；
2. User-provided 技能 / Plugin；
3. Local adapter；
4. User-controlled infrastructure；
5. 第三方云服务。

## 3. 状态

```text
VERIFIED_SUPPORTED
SUPPORTED_BUT_UNVERIFIED
PARTIAL
UNSUPPORTED
DOWNGRADED
BLOCKED
```

不得将未经验证的“理论支持”写成 VERIFIED_支持（SUPPORT）ED。

## 4. 核心规则

- API Key存在 ≠ 用户授权当前文件外发；
- 某一Agent支持 ≠ 其他Agent自动支持；
- 某一版本支持 ≠ 永久支持；
- 能力不满足但有可接受替代方案 → 明示DOWNGRADED；
- 核心交付要求无替代且无法满足 → BLOCKED。
