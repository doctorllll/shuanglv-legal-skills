# input-quality-specification（输入质量规范） V0.1

## 1. 原则

业务技能 不关心文件由哪个 OCR / PDF / 音频 / 视频 工具处理，但输入结果必须满足法律工作需要的可追溯性和不确定性表达。

## 2. 所有输入的最低要求

每个来源至少保留：

```text
asset_id
original_filename
mime_type / source_type
processing_method
processing_provider
processing_mode
source_locator
quality_state
unreadable_or_uncertain_regions
warnings
```

`processing_mode`：

```text
NATIVE
LOCAL
USER_CONTROLLED
THIRD_PARTY_CLOUD
USER_PROVIDED_SKILL
```

## 3. 定位要求

- PDF：文件名 + page；
- DOCX：文件名 + heading/paragraph/page（工具可获得时）；
- XLSX：文件名 + sheet + cell/range；
- PPTX：文件名 + slide；
- Image：文件名 + region/bounding reference；
- 音频：文件名 + timestamp；
- 视频：文件名 + timestamp + frame/keyframe；
- Email：thread/message/attachment；
- Web：URL + section/location；
- ZIP：archive path + inner file path。

## 4. OCR / Transcript

OCR或转录结果必须显式标记：

```text
recognition_state:
  NATIVE_TEXT
  OCR
  TRANSCRIBED
  PARTIAL
  UNCLEAR
```

禁止：
- 把OCR结果自动提升为原始事实；
- 对模糊字符、听不清内容、画面不明处静默补全；
- 转换后只保留一坨纯文本而丢失页码/时间戳。

## 5. 表格

表格转换至少尽量保留：
- 表头；
- 行列关系；
- 合并单元格语义；
- 单位；
- 公式/计算值（如有）；
- 原始 Sheet / Page / Range。

无法保留结构时：
> `quality_state = PARTIAL`

## 6. 输入质量门控

```text
PASS
PARTIAL
UNREADABLE
UNSUPPORTED
NEEDS_OCR
NEEDS_TRANSCRIPTION
NEEDS_VISUAL_REVIEW
NEEDS_HUMAN_REVIEW
```

需要精确引用而 来源定位 不可靠时，业务技能 不得假装输入已完整可引用。
