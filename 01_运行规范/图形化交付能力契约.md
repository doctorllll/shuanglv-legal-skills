# 图形化交付能力契约

## 一、原则

图形化交付是“结构化法律信息 → 可视表达”的渲染能力，不要求底层模型具有图像生成能力。爽律 Skill 只规定 `DiagramSpec`、事实状态、溯源、移动端可读性和最终格式要求；具体渲染由当前 Agent、浏览器、本地工具或用户已有能力完成。

## 二、能力识别

按实际验证记录：
- `can_create_text_file`
- `can_generate_html`
- `can_render_html`
- `can_render_svg`
- `can_render_mermaid`
- `can_render_graphviz`
- `can_render_plantuml`
- `can_export_png`
- `can_embed_images_docx`
- `can_embed_images_pdf`

理论上“模型会写 HTML”不等于运行环境已经能把 HTML 渲染成 PNG。

## 三、渲染选择

```text
需要示意图
→ 有可靠本地 PNG 渲染能力：输出 PNG
→ 无 PNG，但可创建/打开 HTML：输出自包含响应式 HTML（内嵌 SVG）
→ 有 Mermaid / Graphviz / PlantUML：先生成图源并渲染为 PNG/PDF
→ 只能文本：交付 DiagramSpec + 可渲染图源 + 最简 Unicode 示意，并明确没有真实图片文件
```

## 四、隐私与第三方渲染

不得因本地无渲染器而静默调用第三方在线 Mermaid、PlantUML 或其他图形服务处理案件信息。外部处理敏感材料必须说明提供商、发送内容、目的、范围和风险，并取得明确授权。

## 五、质量要求

- 图中主体、金额、日期和关系不得超出上游材料/分析；
- 重要节点保留 `source_refs / locator_refs`；
- 一图一主题；
- 手机可读；
- 关键关系不只依赖颜色；
- 图片模糊、文字重叠、箭头指向错误或节点截断时不得作为正式成果；
- 图形无法可靠生成时允许降级，但必须保留文本安全版和图源。
