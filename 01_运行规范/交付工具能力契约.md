# 交付工具能力契约

## 一、原则

爽律 Skill 规定交付内容、结构、引用、版本和法律专业质量，不重新实现 Word、Excel、PPT、PDF 等通用引擎。

## 二、调用前检查

根据用户要求确认当前运行环境是否真实支持：

- 新建/编辑 DOCX；
- 原生 Track Changes；
- 批注；
- Redline/对比稿；
- XLSX 公式、格式和多 Sheet 保留；
- PPTX 编辑；
- PDF 生成；
- 文件内引用和页码；
- 其他用户明确要求的格式能力。

## 三、降级

若用户只需要“体现修改”，原生 Track Changes 不可用时，可以在用户接受的情况下使用：

> Redline + Clean Copy + Change Summary

并标明 `DOWNGRADED`。

若用户明确要求必须为原生修订模式，则能力不足时进入 `BLOCKED`，不得输出普通文档后声称“已开启修订”。

## 四、正式交付

正式交付前同时检查：

- 内容上游分析是否已完成；
- 引用和来源是否可回查；
- 文件格式是否符合要求；
- 实际生成文件能否正常打开；
- 声称的工具能力是否与真实文件一致；
- 降级和限制是否已经向用户披露。
