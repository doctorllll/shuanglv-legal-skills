# artifact-output-specification（交付物输出规范） V0.1

## 1. 核心边界

本规范只定义**交付要求**，不实现 Office/PDF。

业务技能 输出：
> 业务语义内容 + 输出契约（OutputContract）

当前 Agent 再调用自身或用户已有的 Documents / Spreadsheet / Presentation / PDF 技能 完成实体文件。

## 2. 输出Contract 应表达

```text
primary_format
delivery_formats
document_type
house_style
edit_mode
version_required
parent_version
track_changes_required
comments_required
clean_copy_required
diff_copy_required
citation_style
confidentiality_marking
artifact_qa_required
```

## 3. 编辑模式

- NEW_DRAFT（新稿）
- CLEAN_REWRITE（清洁改写）
- REDLINE（差异稿）
- TRACK_CHANGES（原生修订）
- COMMENT_REVIEW（批注审阅）
- FORMAT_ONLY（仅格式）

## 4. 能力真实性

如用户要求 `TRACK_CHANGES`：

### 运行环境 支持
调用 Agent 自带 Word/Office 技能 实现。

### 运行环境 不支持
不得声称完成原生修订。根据任务重要性：
- `DOWNGRADED`：差异稿 + 清洁稿 + 修改说明；
- `BLOCKED`：用户明确要求必须原生修订且无可用实现能力。

任何降级必须显式告知。

## 5. 版本

推荐：

```text
v0.x = 草稿/内部
v1.0 = 第一正式版
v1.1 = 小幅实质调整
v2.0 = 重大结构调整
```

正式文件至少保留：
- 文书编号
- 版本
- 父版本
- Status
- Created / Modified
- 修改说明

禁止：
> 最终版、最终最终版、最终版2。

## 6. 交付物 质量检查

实现 技能 输出文件后，应至少检查与任务相关的：
- 文件可打开；
- 内容完整；
- 无截断/重叠/乱码；
- 标题/段落/表格符合规范；
- 引用和来源定位未丢；
- 修订/批注真实存在（如要求）；
- 清洁稿 无残留修订/批注（如要求）；
- XLSX 无明显公式错误；
- PDF 与可编辑源内容一致；
- 版本链正确。

## 7. 实现所有权

> `implementation_owner = CURRENT_AGENT_OR_USER_SKILL`

法律技能系统 不维护 Office SDK。
