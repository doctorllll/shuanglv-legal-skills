# artifact-output-specification（交付物输出规范） V0.1

## 1. 核心边界

本规范只定义**交付要求**，不实现 Office/PDF。

业务技能 输出：
> 业务语义内容 + 输出契约（OutputContract）

当前 Agent 再调用自身或用户已有的 Documents / Spreadsheet / Presentation / PDF 技能 完成实体文件。

## 1A. 复杂材料任务的阅读入口

复杂/正式材料任务原则上先提供《事项快速理解包》，再进入详细分析。事项存在主体、时间、交易、资金、履行、证据或问题关系时，原则上至少提供一项图形化示意。最终普通用户格式优先 PNG；无 PNG 渲染能力时使用自包含响应式 HTML；真正只能文本时交付 DiagramSpec/图源并明确未实际生成图片。详见《事项快速理解与图形化交付规范》《图形化交付能力契约》。

## 1B. 合同任务交付硬规则

- DRAFT：必须有完整合同文本；
- REVISE：必须有实际修改后的合同文本；
- REVIEW：默认审查并实际修订，用户明确只要报告/意见时例外；
- 审查报告和风险清单不得冒充已经修改合同。

## 1C. 模板与成套交付

用户存在适用模板时，模板解析优先遵循《模板资产与成套交付规范》，系统默认模板不得静默覆盖用户模板。同一任务需要多份配套成果时，可建立 DeliverableBundle，并用 SharedMatterFields 复用已核验/已标状态的共同信息；共享不等于自动 VERIFIED。

## 3. 编辑模式

- NEW_DRAFT（新稿）
- CLEAN_REWRITE（清洁改写）
- REDLINE（差异稿）
- TRACK_CHANGES（原生修订）
- COMMENT_REVIEW（批注审阅）
- FORMAT_ONLY（仅格式）

## 4. 能力真实性

如用户要求 `TRACK_CHANGES`：

### 运行环境 支持
调用 Agent 自带 Word/Office 技能 实现。

### 运行环境 不支持
不得声称完成原生修订。根据任务重要性：
- `DOWNGRADED`：差异稿 + 清洁稿 + 修改说明；
- `BLOCKED`：用户明确要求必须原生修订且无可用实现能力。

任何降级必须显式告知。

## 5. 版本

推荐：

```text
v0.x = 草稿/内部
v1.0 = 第一正式版
v1.1 = 小幅实质调整
v2.0 = 重大结构调整
```

正式文件至少保留：
- 文书编号
- 版本
- 父版本
- Status
- Created / Modified
- 修改说明

禁止：
> 最终版、最终最终版、最终版2。

## 6. 交付物 质量检查

实现 技能 输出文件后，应至少检查与任务相关的：
- 文件可打开；
- 内容完整；
- 无截断/重叠/乱码；
- 标题/段落/表格符合规范，包括正文与结构层次小标题的缩进规则；
- 引用和来源定位未丢；
- 修订/批注真实存在（如要求）；
- 清洁稿 无残留修订/批注（如要求）；
- XLSX 无明显公式错误；
- PDF 与可编辑源内容一致；
- 版本链正确。

## 7. 实现所有权

> `implementation_owner = CURRENT_AGENT_OR_USER_SKILL`

法律技能系统 不维护 Office SDK。


## 重要命题的溯源要求

正式对外交付前，事实认定、法律依据、案例引用和核心专业判断同时适用《全链路溯源规范》。对外文书可以使用自然的脚注、引证、证据编号或附件索引，不必暴露内部对象 ID；但内部执行记录应能够把重要交付命题反向关联到对应的 `Finding`、`ArgumentRecord`、`FactRecord`、`LegalRule`、`CaseCard`、`EvidenceItem` 和来源定位。
