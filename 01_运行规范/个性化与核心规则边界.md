# 个性化与核心规则边界

## 一、可个性化内容

通常可以个性化：

- 文书篇幅倾向、段落密度、标题密度；
- 结论是否优先展示（在不影响特定文种强制结构时）；
- 是否默认生成事实概要、时间线、关系图等辅助成果；
- 输出格式偏好；
- 用户自有术语、称谓、文件命名习惯；
- 合法且不降低核心质量门的工作流展示习惯；
- 用户自有模板、检查清单和项目规则。

## 一A、模板资产保护

用户自有模板属于用户资产。新版 Core 可以提供新的默认模板或默认结构，但**新版系统模板不得静默覆盖用户已有模板**。用户在当前任务明确选择新版默认或停用某个用户模板时，可以按该次明确决定执行；不得把一次选择自动推断成长期放弃用户模板。

模板使用仍受事实核验、法律准确性、来源真实性和人工决定等 Hard Guardrails 约束。

## 二、不可被个性化关闭的核心边界

以下内容属于 `Hard Guardrails`：

1. 不得把 `ALLEGED / INFERRED / UNKNOWN` 静默写成 `VERIFIED`；
2. 需要现行法核验时，不得以模型记忆或旧材料代替实际核验；
3. 不得伪造法条、案例、证据、来源或已完成的工具动作；
4. 敏感材料进入第三方外部处理前必须满足风险提示与授权要求；
5. 重大权利处分、不可逆策略选择和需要律师判断的节点不得被“自动化偏好”绕过；
6. 不得以用户偏好关闭必要的来源追溯、冲突披露或关键不确定性说明；
7. 不得把“写得更像用户”解释为复制第三方受保护文本或冒充特定律师本人。

任何与上述边界冲突的个性化，保留记录但状态改为 `BLOCKED_BY_GUARDRAIL`。

## 三、旧版直接改 Core 的处理

以后不建议用户直接修改 Core。如果检测到旧安装中存在 Core 文件改动：

- 先列为“历史自定义候选”；
- 仅提取真正改变行为的部分；
- 能结构化成个性化设置的，迁入 `UserProfile/MatterProfile`；
- 不能安全迁移的，保留原文件副本并要求人工决定；
- 不允许把整个旧文件覆盖到新 Core 上，否则会把 Bug 修复和新能力一并回滚。
