# 能力降级与失败处理规范

## 一、状态

统一使用：

- `VERIFIED_SUPPORTED`：当前环境已实际验证支持；
- `SUPPORTED_BUT_UNVERIFIED`：有能力声明，但本次尚未验证；
- `PARTIAL`：只能满足部分要求；
- `UNSUPPORTED`：不支持；
- `DOWNGRADED`：已采用可接受替代方案；
- `BLOCKED`：核心要求无法满足。

## 二、不可静默降级

发生降级时应记录：

- 原要求；
- 实际采用能力；
- 为什么降级；
- 对事实、来源、格式或结论的影响；
- 哪些部分需要人工复核。

## 三、典型处理

| 原要求 | 可接受情况 | 不可接受情况 |
|---|---|---|
| 当前有效法律 | 官方原始来源或可核验专业信源 | 只凭模型记忆给出“现行法” |
| 用户私有知识库 | 用户授权的连接器/本地检索 | 无权限仍声称“已结合知识库” |
| 扫描件读取 | 可靠 OCR/视觉读取并保留定位 | OCR 大量缺失仍当作完整卷宗 |
| 原生 Track Changes | 真实原生支持 | 普通修改稿冒充原生修订 |
| PDF 正式交付 | 实际生成并能打开 | 只描述“已生成 PDF”但没有文件 |

## 四、失败后的继续条件

只有当替代方案仍能满足当前任务的核心法律质量时才允许继续。若失败会导致关键事实不可读、法律依据无法核验、重要来源不可回查或用户明确要求无法实现，应停止对应步骤并说明需要什么输入或能力才能继续。
## v0.43 增强层失败的特殊处理

对 AutoActivation、Router v2、多 Skill 协同、主动建议等 v0.43 新增增强能力，优先适用 `Legacy Compatibility Contract`：

- 增强能力失败但 v0.42 旧路径可完成核心任务：记录失败回退，继续执行；
- 仅损失增强体验：可标记 `LOSS_OF_ENHANCEMENT_ONLY`，不得把整个任务判为 BLOCKED；
- 回退后核心专业要求下降：按 `DOWNGRADED` 披露；
- 连旧路径也无法满足核心要求：才 `BLOCKED`。

任何回退不得覆盖用户个性化与模板资产。
