# 外部能力适配规范

## 一、目的

爽律 Skill 不自建法律数据库、用户知识库、OCR、Office 或其他通用工具。它负责在当前 Agent 已具备或用户已经接入这些能力时，判断**什么时候需要调用、应优先调用哪一类能力、结果必须满足什么质量、能力不足时怎样降级或阻断**。

核心原则：

> **Skill 规定工作方法和质量契约；运行环境提供实际工具能力。**

## 二、统一能力解析流程

```text
当前任务
→ 识别能力需求
→ 读取当前运行能力档案
→ 按任务目的选择可信能力
→ 检查数据边界与授权
→ 调用并记录能力调用
→ 把结果转成爽律公共对象
→ 检查来源定位、完整性和限制
→ 满足要求则继续
→ 可接受替代则 DOWNGRADED 并披露
→ 核心要求无法满足则 BLOCKED
```

不得因为某个工具“理论上支持”就假定当前实例一定可用；不得因为 API Key、连接器或账号存在就假定当前案件材料已经获准外发。

## 三、外部能力类型

爽律 Skill 至少区分：

- **法律权威信源**：现行法律、司法解释、规范性文件及效力信息；
- **案例信源**：裁判文书、指导/典型案例及案例元数据；
- **用户知识库**：用户自有文档、历史工作成果、内部制度、模板和知识库；
- **公开 Web**：官方网站、公开资料和其他网络信息；
- **文件读取与多模态**：PDF、图片、OCR、表格、音频、视频；
- **交付工具**：DOCX、XLSX、PPTX、PDF、批注、修订模式等；
- **通用计算/代码工具**：数据处理、计算、批量转换和机器校验。

具体工具或厂商不是 Skill 的固定依赖。

## 四、选择原则

### 法律依据

优先满足“权威、现行、可定位、可复核”。通常优先：

1. 可确认身份的官方原始来源；
2. 能回到原文、效力和来源定位的专业授权法律数据能力；
3. 其他可靠二级来源，用于发现线索或交叉核验；
4. 一般网络信息，仅作辅助；
5. 模型记忆不得单独承担现行法核验。

### 用户知识

用户知识库用于补充事实、内部制度、历史工作产品、模板和经验，但不得仅因“知识库里写过”就自动升级为现行法律或已核验案件事实。

### 文件处理

优先：当前 Agent 原生能力 → 用户已有工具 → 本地能力 → 用户控制基础设施 → 第三方云服务。进入第三方云服务前执行外部处理风险门控。

### 正式交付

正式文件能力必须实际验证。原生修订模式、批注、公式保留等能力如果不可用，不得通过文字声称已经实现。

## 五、能力调用结果的统一落地

外部工具结果不能只以“工具回答文本”留在聊天里。根据任务转换为已有公共对象：

- 法律/案例 → `SourceCard / SourceLocator / LegalRule / CaseCard / ResearchResult`；
- 用户知识库 → `SourceCard / SourceLocator`，并标记来源类型和权限范围；
- 文件/OCR → `MaterialRecord / SourceLocator / LegalObjectCandidate`；
- 交付工具 → `OutputContract / DeliveryMetadata / CapabilityInvocationRecord`。

重要结果继续受《全链路溯源规范》约束。

## 六、能力不足的处理

能力不足分三类：

- **可等价替代**：换用同等可信能力，正常继续；
- **可降级完成**：使用次优方案，明确 `DOWNGRADED`、影响范围和需要人工复核的部分；
- **不可接受**：核心资料无法读取、指定原生文件能力无法满足、现行法无法可靠核验等，标记 `BLOCKED`，不得假装已经完成。

## 七、禁止模式

- 工具未调用却声称“已检索数据库”；
- 检索摘要没有回到原文却标记为已核验；
- 用户知识库内容与现行法冲突时静默采用知识库；
- OCR 文本未经回查即升级为 VERIFIED；
- 本地处理失败后静默切换第三方云；
- 没有原生 Track Changes 却声称已生成原生修订模式；
- 某 Agent/某版本曾经支持某能力，就推定所有环境永久支持。

## 八、与工程执行层的关系

支持脚本时，可用 `capability-check` 对执行计划与运行能力档案做一次解析。脚本只判断已声明能力是否满足任务要求，不替代对第三方服务当前政策、法律数据库内容、实际文件质量和律师专业结论的人工核验。
