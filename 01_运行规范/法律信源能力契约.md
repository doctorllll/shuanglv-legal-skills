# 法律信源能力契约

## 一、适用

当任务涉及现行法律、司法解释、规范性文件、案例、效力沿革、法域、时间适用、司法实践、理论解释或专业实务资料时使用。

本契约采用**渠道中立（channel-neutral）**原则：数据库、官网、微信公众号、普通网页、知识库等只是“发现和承载内容的渠道”，不得仅凭渠道名称预设法律权威性。真正需要评价的是发布主体、内容性质、是否原始、可核验程度、时间状态以及该材料在当前问题中的用途。

## 二、输入要求

法律研究调用前至少明确：

- `issue_id` 或研究问题；
- 法域；
- 关键事实时间/适用时间；
- 需要解决的信息角色：正式规范、案例、官方解释、司法实践信号、理论观点、专业实务分析或检索线索；
- 是否要求当前有效性核验；
- 是否需要案例比较；
- 本次研究最终用于何种交付或业务判断。

## 三、Source Discovery 与 Source Evaluation 必须分开

### 1. Source Discovery｜来源发现

搜索引擎、数据库、公众号搜索、站内检索、知识库、引文追踪等均可用于发现候选材料。发现渠道本身不决定来源等级。

### 2. Source Evaluation｜来源评价

候选材料进入正式研究前，应尽可能形成 `SourceCard / SourceProfile`，至少评价：

- 发布主体及其身份；
- 发布渠道；
- 内容性质；
- 是否官方账号/官方页面；
- 是否原创或原始发布；
- 是否能够回到稳定原文；
- 时间、法域与当前问题的相关性；
- `SourceRole`；
- 专业权威性；
- 规范拘束力/法律效力；
- 本次允许承担的证明或论证功能；
- 是否仍需要回到其他原始来源核验。

**权威性、法律效力、事实证明力是不同维度，不得混写。**一篇最高司法机关发布的解释性文章可以具有很高的专业权威性，但如果它不是正式规范，就不能写成“法律规定”。

## 四、SourceRole｜信息角色

同一发布渠道可能承载完全不同性质的材料。建议至少使用以下角色：

| SourceRole | 含义 | 典型用途 |
|---|---|---|
| `FORMAL_NORM` | 正式法律规范 | 证明现行规则、效力、构成要件、程序要求 |
| `OFFICIAL_CASE` | 官方发布案例 | 指导、典型、案例库等官方案例研究 |
| `JUDGMENT` | 裁判文书 | 比较裁判理由、决定性事实和适用路径 |
| `OFFICIAL_INTERPRETATION` | 官方解释性资料 | 理解规则、司法政策、适用口径、答疑 |
| `PRACTICE_SIGNAL` | 司法/执法实践信号 | 审判白皮书、官方实务总结、辖区审判思路等 |
| `SCHOLARLY_VIEW` | 理论观点 | 理论争议、解释方法、学理支撑 |
| `PROFESSIONAL_ANALYSIS` | 专业实务分析 | 律协、专业机构、资深实务作者的分析与经验 |
| `RESEARCH_LEAD` | 检索线索 | 二次转载、出处未明、摘要、待追溯材料 |

角色不是永久标签，而是针对当前研究用途的功能性分类；同一材料可能同时承担两个角色，但必须说明各自用途。

## 五、公众号与网页材料

不得把“公众号/网页”整体降级为低权威来源。

以下材料即使发布在公众号或普通网页，只要主体、原始性和内容得到核验，也可以直接作为正式研究资料：

- 最高司法机关、地方高级法院/中级法院、检察机关、政府部门等官方账号发布的原创案例、白皮书、解释、答疑和实务总结；
- 律师协会、法学研究机构、高校等专业机构的原创研究；
- 身份明确、专业背景可核验、论据和引证透明的高质量法官、检察官、学者、律师专业文章。

但必须区分：

- **正式法源效力**；
- **官方/专业解释价值**；
- **司法实践参考价值**；
- **事实证明力**。

二次转载、截屏、无法确认作者/机构、无法回到原始文本的内容，默认进入 `RESEARCH_LEAD`，优先追溯原始来源。

## 六、合格结果

合格法律信源结果应尽可能保留：

- 来源身份和 `SourceRole`；
- 发布/裁判机关或作者/机构；
- 发布渠道及原始性状态；
- 文号、案号或稳定记录标识；
- 发布/裁判时间；
- 当前效力或核验状态；
- 原文或可回查原始文本；
- 条、款、项、段落或裁判理由等精确定位；
- 本来源具体支持、限制或反对什么命题；
- 本来源不能证明什么；
- 核验时间。

## 七、现行法核验

`VERIFIED_CURRENT` 不得仅基于：

- 模型记忆；
- 搜索结果标题；
- 二手文章对法条的转述；
- 无效力信息的静态知识库；
- 未打开原文的数据库摘要。

解释性文章可以帮助理解规则，但需要声称“现行法律规定”为何时，仍应回到正式规范文本核验。

## 八、案例能力

案例检索结果应进入 `CaseCard` 和必要的 `CaseMatrix`，至少比较：

- 决定性事实；
- 法律问题；
- 裁判理由；
- 与本案相似点；
- 与本案区别点；
- 支持、反向、区别或边界用途。

“关键词相似”不等于类案可比。官方公众号发布的典型案例如果原始发布身份已经核验，可以直接作为 `OFFICIAL_CASE` 使用；如文章只摘录其他裁判，应继续追溯对应裁判或官方案例原文。

## 九、信源冲突

不同来源出现冲突时：

1. 先确认是否为不同时间、地域、层级、文本版本或不同 `SourceRole`；
2. 对正式法源效力问题，优先适用法律位阶和现行有效性规则；
3. 对解释/实践问题，比较发布主体、原始性、适用辖区、时间、新旧实践和论据质量；
4. 保留实质分歧，不通过“多数票”或简单来源排名自动消解；
5. 说明冲突对当前结论的影响和需进一步核验事项。

## 十、能力降级

如果专业数据库不可用，但官方原始来源、法院/检察院官方发布、其他可核验高质量来源足以完成当前研究，可以继续，不应仅因“没有商业数据库”而降低全部法律可靠性等级。

如果无法取得足以确认现行效力、原文或关键案例真实性的来源，则应降低结论强度或进入 `INCOMPLETE / HUMAN_REVIEW_REQUIRED / BLOCKED`。
