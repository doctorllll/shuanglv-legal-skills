# Civil｜民商事争议 Domain Extension

`unit_id: unit.domain.civil`

**Scope：** Civil-dispute-specific delta only.

## Trigger
- Directive/goal concerns a civil/commercial dispute requiring claim/defense, burden, jurisdiction, limitation, procedure, preservation or enforcement method.

## Negative Trigger
- Document merely is a civil pleading but task is formatting only.

## Essential Procedure
1. Build claim/defense structure.
2. Apply civil burden/proof consequences.
3. Add jurisdiction/limitation/procedure/preservation/enforcement only when material.

## Deepening Conditions
- Procedural path changes outcome.
- Special path such as retrial/enforcement matures.

## Exit Sufficiency
- Civil-specific issues necessary for requested decision/deliverable are complete.

## Professional Results
- civil claim/defense/procedure delta


## Domain-Specific Professional Method

## 一、这个技能解决什么问题

这个技能站在律师代理立场组织民事、商事诉讼和仲裁。核心不是“自动写起诉状”，而是把一个纠纷拆成：客户真正要什么、有哪些法律路径、每条路径需要哪些事实、双方真正争什么、谁承担证明风险、现有证据够不够、程序上怎么走、最后选择什么策略。

## 二、主流程

```text
确定争议解决渠道、代理位置、程序阶段和任务
→ 明确客户目标与希望获得的法律效果
→ 接管材料并建立事实时间线、主体关系和交易关系
→ 为原告构建请求权基础，为被告构建否认/抗辩/反抗辩
→ 把每条法律路径拆成要件
→ 将双方相反主张映射到要件，形成真正争议焦点
→ 为每个待证命题配置证明责任、证据和缺口
→ 并行处理管辖、仲裁、时效、保全和执行可实现性
→ 形成诉讼/仲裁策略
→ 文书、庭前、庭审
→ 和解、裁判后、二审、再审和执行
```


## 三、执行步骤速查表

| 步骤 | 要做什么 | 主要方法 | 阶段产物 |
|---|---|---|---|
| 1. 路由 | 确认渠道、代理位置、阶段和任务 | 四维路由 | 诉讼/仲裁路线 |
| 2. 客户目标 | 明确真正想取得的法律效果 | 法律效果先于诉讼动作 | 目标与约束清单 |
| 3. 事实建模 | 整理人物、时间、交易和事件 | 时间线、主体关系、法律关系 | 事实模型 |
| 4. 请求/防御 | 为双方建立法律路径 | 请求权基础、否认、抗辩、反抗辩、备选路径 | 请求抗辩矩阵 |
| 5. 争点形成 | 找出真正影响结果的分歧 | 要件×双方相反主张 | 要件—主张—争议矩阵 |
| 6. 证据 | 让证据服务于待证命题 | 证明责任、证据支持/反向/缺口 | 举证责任与证据矩阵 |
| 7. 程序 | 尽早处理可能改变局面的程序事项 | 管辖、仲裁、时效、保全、执行前置 | 程序问题清单 |
| 8. 策略 | 选择最可执行的推进方式 | 实体、证据、程序、成本、商业关系综合 | 阶段策略 |

| 10. 和解/救济 | 比较继续诉讼与可履行方案 | 履行能力、担保、时间、执行分析 | 和解/二审/执行方案 |

## 四、客户目标先于诉讼动作

“我要起诉”“我要解除合同”“我要让他赔钱”只是表面表达。应继续确认：最终要钱、财产、履行还是确认某种法律状态；是否更关心止损、保全或商业关系；即使胜诉是否能执行；时间成本和和解空间如何。诉讼动作服从客户目标。

## 五、请求与防御架构

原告侧按“请求目标 → 可能请求权基础 → 积极要件 → 对方抗辩 → 反抗辩 → 主位/备位路径”构建。不能因为用户一开始说“这是违约”就停止其他法律路径审查。

被告侧要区分“否认”和“抗辩”：否认是原告事实或要件本身不成立；抗辩是即使原告基本事实成立，仍有阻止、消灭或延缓请求的理由。还要预判原告对抗辩的回应。

## 六、要件—主张—争议矩阵

真正争议焦点通常同时满足：双方主张不同；差异对应某个请求权、抗辩或程序要件；差异可能影响案件结果。普通背景差异不自动成为争点。

可以借用请求权基础、要件和裁判结构帮助分析，但**不得把法官“应如何裁判”的步骤机械复制成律师行动清单**；律师还必须考虑客户目标、举证、程序、谈判、保全和执行等行动变量。

矩阵应把法律路径、要件、双方主张、争议状态、证明责任、现有证据、反向证据、缺口和下一步连接起来。

## 七、证据方法

证据围绕“待证命题”组织，不只是按证据类型归类。每条法律路径要分别判断：法律上是否可能成立；事实是否满足；证据能否证明；证明责任和风险在哪里。

内部分析必须保留对方有利证据、我方矛盾材料和可能改变结论的反向事实。对外文书可以策略取舍，但内部模型不能删掉不利信息。

## 八、程序与实体并行

管辖、仲裁协议、诉讼时效、财产/证据保全、反诉、鉴定、第三人、送达、调查取证和执行可实现性应尽早进入分析。特别是保全和执行，不能等实体意见全部完成才第一次考虑。

## 九、策略形成

策略综合胜诉路径、证据强弱、程序机会、对方行为、资产、时间成本、商业关系、谈判空间和客户风险承受。最终要形成可执行的阶段计划，而不是抽象的“建议积极应诉”。

## 十、文书、庭前和庭审

正式文书应来自已经完成的请求/抗辩、事实、证据和程序模型，而不是直接把原始材料交给模型写起诉状。

庭前应整理争议焦点、待证命题、证据、对方证据预判、发问目标、程序申请、重点法律问题和和解授权。庭审发问与质证都要服务于争点。

## 十一、和解和执行

和解不能只比较名义金额，还要看付款时间、担保、履行条件、违约后果、可执行性和继续诉讼成本。执行可实现性应尽量前置。

## 十二、人工决策点

是否起诉/仲裁、撤诉、放弃请求、承认对方重要主张、接受和解、改变核心诉讼目标等重大处分原则上由客户和律师决定，Agent 负责比较方案和风险。

## 十三、主要产出

事项核心概要、核心关系/时间/资金/流程示意图（按事项选择）、客户目标与路线图、事实时间线、主体关系图、请求权/抗辩矩阵、要件—主张—争议矩阵、待证命题与举证责任矩阵、证据矩阵、程序问题清单、保全/执行分析、诉讼策略、文书内容基础、庭前和庭审材料、和解比较、二审/再审/执行分析和Resume Capsule（续接/交接摘要）（仅续接/交接/归档需要时）。

## 04-要件与争议焦点矩阵

## 律师端适配
九步法来自法官裁判组织方法，本项目只吸收：

```text
固定请求/救济
→ 找请求权基础
→ 找抗辩基础
→ 分解要件
→ 对照当事人陈述
→ 形成真正争点
→ 确定待证事实
→ 证据/证明责任
→ 涵摄与方案
```

## 争点规则
真正事实争点通常满足：
1. 双方陈述不一致；
2. 该事实对应请求权/抗辩要件；
3. 对裁判结果有实质意义。

普通背景差异不自动升级为“争议焦点”。

## 11-二审再审与执行

## 二审/上诉
重新分析：
- judgment reasoning
- fact omissions/errors
- 证据 evaluation
- 法律 application
- 程序 问题
- new 证据
- requested appellate 请求目标

## 再审
当前支持范围：提供通用再审问题识别和研究入口；不将其表述为完整再审专项工作流。
必须执行专用 现行法 研究。

## 执行
先作为大型模块：
- executable obligation
- asset clues
- 保全-to-执行 交接
- 执行 settlement
- 变更/add party
- objections/remedies
- closure/restart 状态

不单独拆分为顶层技能；执行阶段按当前程序、财产和救济问题调用相关规则与现行法研究。

根据当前阶段和 Directive，可形成或向 Composition 提供内容基础：起诉状、答辩状、反诉状、上诉状、代理意见、证据目录/质证意见、保全申请、仲裁申请/答辩、庭后意见等。是否属于当前机关/程序的**必需提交材料**必须另行核验，不因本清单自动认定为必交。
