## Domain-Specific Professional Method

## 一、这个技能到底是什么

这不是“自动写辩护词”的技能，而是一套**刑事律师从接案到阶段交付的办案工作流**。它先判断律师角色、案件阶段和本次任务，再决定会见、阅卷、证据、罪名、程序和策略应当怎么推进。

核心原则是：会见陈述不能自动变成事实；阅卷不能只做摘要；证据不能只做“三性打分”；罪名分析不能先定结论再挑事实；认罪认罚不能替代证据和法律审查；重大策略由律师或客户决定。

## 二、主流程

```text
确认律师角色、案件阶段和本次任务
→ 接案与紧急事项检查
→ 建立材料、事实和程序状态
→ 按角色进入独立分支

DEFENSE：
会见/阅卷 → 控方证明体系 → 证据 → 罪名与出罪/罪轻 → 阶段策略 → 庭审/救济

VICTIM_REPRESENTATION / ACCUSATION_REPORTING：
损害与行为事实 → 刑事路径与民刑边界 → 控告待证命题 → 证据包/保全 → 管辖与受理 → 立案/监督 → 被害人代理与追赃挽损

其他刑事代理：
根据具体角色、程序阶段和任务重新配置分析路径

→ 独立处理涉案财物、程序与其他专题
→ 形成阶段策略和正式文书
→ 输出Resume Capsule（续接/交接摘要）（仅续接/交接/归档需要时）
```

## 四、第一层方法：角色 × 阶段 × 任务

### 1. 角色

至少区分犯罪嫌疑人/被告人辩护、被害人代理、控告报案、立案监督、自诉或附带民事等角色。不能把辩护侧方法无条件套给其他角色。

### 2. 阶段

侦查、审查逮捕、审查起诉、一审、二审、申诉再审、执行财产等阶段的目标和可用动作不同。阶段必须根据真实程序状态判断，不能根据“用户想做什么”臆测。

### 3. 任务

会见、阅卷、证据分析、罪名分析、非羁押意见、不起诉意见、认罪认罚、非法证据排除、庭前准备、发问、质证、辩论等可以并存，但应确定主任务和依赖关系。

## 五、被害人代理与刑事控告

被害人/控告侧不是辩护流程的镜像。核心任务是把客户叙述转化为可核查的事实—证据—法律结构，同时主动检验民刑边界、证据充分性和替代解释。

该分支重点处理：客户目标、损害/交易/行为事实模型、控告待证命题、结构化材料审阅、证据包和证据保全、管辖/受理、控告报案材料、立案状态、立案监督或其他救济、追赃挽损以及立案后的被害人程序参与。

详细执行规则已经合并在本文件下文“被害人代理与刑事控告”专节，不再依赖旧版独立文件。

## 六、会见方法

会见首先产生的是“待核信息”。应区分当事人陈述、已由其他材料核验的事实、与卷宗冲突的内容、需要进一步核实的问题和可能改变法律评价的关键细节。

会见通常先让当事人较完整陈述，再围绕时间线、人物关系、行为过程、主观认知、资金财物流向、关键文件、证据来源和程序问题追问。阅卷发现新矛盾后应生成下一轮会见问题，会见的新线索又要回到卷宗中验证。

## 七、阅卷方法

### 1. 全卷输入，重点分析

即使当前只关注一个辩点，也不能只读支持这个辩点的材料。先掌握控方整体证明结构，再决定重点。

### 2. 多轮阅卷

第一轮理解控方指控故事；第二轮重构“指控事实—待证命题—证据—来源”；第三轮寻找矛盾、缺口、同源信息、反向材料和应出现但未出现的证据；之后围绕成熟辩点复核。

### 3. 控方证明地图

应回答：控方要证明哪些关键事实；每个事实依赖什么证据；证据之间是否真正独立；哪些环节只有口供；哪些事实有反向证据；哪些预期证据缺失；哪些推理依赖隐含假设。

## 八、证据分析方法

先确定待证命题，再看证据。单项证据至少审查来源、取得过程、相关性、可靠性、完整性、保管移送、上下文、能够证明到什么程度以及与其他证据的矛盾。

“内容一致”不当然等于相互印证，还要检查信息是否同源、证人是否交流、后一份材料是否受前一份影响、数据是否来自同一原始系统。

如果控方叙事为真，按常理本应存在某种客观材料而卷宗没有，应把它作为独立问题记录。间接证据案件要拆分每个基础事实和每一步推理，检查是否存在其他合理解释。

## 九、罪名分析方法

先形成能够被现有证据支持的案件事实模型，再与罪名规范比较，不允许先认定罪名再裁剪事实。

每个可能罪名建立要件矩阵：构成要件、支持事实、支持证据、反向事实、反向证据、证据缺口、出罪或限缩路径。

任何扩大入罪的解释都要经过罪刑法定门控：是否超出法律文字可能涵义；是否实质上使用不利类推；是否只凭政策目的入罪；是否忽略时间效力；是否把旧规则直接当现行规则。

同时使用“证实与证伪”：每个辩护假设既找支持材料，也主动问“如果这个辩点是错的，最可能出现什么反证”。

## 十、阶段策略

强制措施阶段不仅看罪名，还分析证据强度、社会危险性、替代措施、证据是否固定、串供毁证风险和程序合法性。

审查起诉阶段要把控方证明地图、辩护事实模型、证据缺口、罪名分析、程序问题和量刑/认罪认罚整合起来。

发现控方缺口不等于马上披露。是否现在提出，要考虑辩点成熟度、检方补强空间、阶段目标、对不起诉或变更罪名的价值、对后续庭审的影响。此类决定默认人工复核。

认罪认罚也不能停止事实、罪名、量刑和程序审查。

刑事证明中的“相互印证”还必须检查来源独立性：多份材料若实质派生自同一原始来源，只能按其真实来源链评价，不能机械按文件数量累计为多份独立印证；通用 independence 判断仍由 Evidence Capability 负责。

## 十一、职业伦理门控

Agent 服务于合法委托目标，但不能教唆伪造、隐瞒或毁灭证据，不能执行明显违法指令，也不能为迎合客户篡改事实或法律判断。律师专业判断与客户意愿发生重大冲突时，应记录冲突、解释和客户决定。

## 十二、主要产出

事项核心概要、核心关系/时间/资金/流程示意图（按事项选择）、会见提纲和记录、待核事实表、卷宗目录、阅卷报告、控方证明地图、事实时间线、证据矩阵、矛盾矩阵、罪名要件矩阵、调查取证计划、强制措施意见、审查起诉意见、庭前问题清单、发问/质证/辩论方案、认罪认罚分析、非法证据或涉案财物专题意见、二审救济分析和Resume Capsule（续接/交接摘要）（仅续接/交接/归档需要时）。

正式文书还要经过“Composition / Review Capability”。

## 05-罪名与刑法分析


## 流程
1. 构建可被证据支持的案件事实；
2. 明确拟适用规范及版本；
3. 解释构成要件；
4. 建 要件矩阵；
5. 涵摄；
6. 检查出罪/阻却/不归责事由；
7. 检查共同犯罪、单位犯罪、罪数等；
8. 检查法益、刑民边界等实质争点（仅在法理上允许范围内）；
9. 对扩张解释/类推风险进行罪刑法定检查；
10. 形成主方案 + 备选方案。

## 规则
刑法解释不得以“实质合理”为由越过罪刑法定边界。

## 现行法
所有罪名、司法解释、追诉/入罪标准：
> 必须调用 Research Capability。

## 09-庭前与庭审


## 庭前材料包
- trial issue 图
- 客户 preparation
- questioning outline
- cross-examination outline
- 抗辩 证据
- applications
- 非法证据问题
- case 研究
- 抗辩 argument architecture

## 发问
从核心辩点倒推：
> 需要证明/削弱什么事实 → 谁能回答 → 如何设计问题。

不要：
- 不知道答案却无策略地贸然问；
- 与证人/被告人争辩；
- 用法律结论代替事实问题。

## 庭审论证
按：
> 事实 → 证据 → law
建立主轴。

## 14-被害人代理与刑事控告

### 独立路由

适用于 `VICTIM_REPRESENTATION / ACCUSATION_REPORTING`，并根据 `REPORTING / FILING_SUPERVISION / PROPERTY / CASE_UPDATE` 等任务进一步路由。

### 核心工作链

```text
客户目标与角色
→ 损害/交易/行为事实模型
→ 刑事路径与民刑边界
→ 控告待证命题
→ 结构化材料审阅
→ 证据包、缺口与保全
→ 管辖/受理/提交
→ 立案状态与补充材料
→ 监督/救济
→ 追赃挽损与被害人程序参与
```

### 证明方法

每个核心犯罪事实连接：`FactRecord → EvidenceItem → SourceLocator`。客户陈述默认 `ALLEGED`。对主观要件、资金流、损失、主体身份等关键命题主动寻找客观材料和反向解释。

### 反向分析

正式控告前必须检查最强非犯罪解释，包括民商事纠纷、行政违法、主体不符、证据不足或其他合理事实模型，并说明哪些证据能够区分不同解释。

### 程序与财产

具体管辖、立案监督、被害人程序权利和追赃退赔规则运行时核验。财产问题单独建模，不以“立案”替代挽损路径分析。

### 详细执行

见本文件下文“被害人代理与刑事控告”专节。

## 罪名分析罪刑法定门控

## 0. 合法性 门控（罪刑法定门控）
检查：
- 是否已核验当前有效法律来源？
- 是否已明确罪名规范的文字范围？
- 是否已核验时间效力？
- 解释是否处于文字可能涵义范围内？
- 是否存在对被追诉人不利的类推？
- 是否仅依政策理由扩大入罪？

存在不利类推、纯政策入罪、超文义不利扩张时，不得作为定罪 规则。

## 1. 案件事实构建
从 证据 分析结果 构建有来源、有证据支持且具有刑法评价意义的事实；保留原始 来源定位、被排除事实及理由、冲突和未知事实。禁止为目标罪名裁剪事实。

## 2. 要件 矩阵
element / 法律 meaning / supporting fact / supporting 证据 / counter / unknown / interpretation issue。

## 3. 主观/客观要件
主客观要件分开，禁止由结果倒推故意。

## 4. 出罪/限缩路径
检查要件不符、阻却/不归责、事实认识、因果/归责、罪数/共犯/单位、刑民边界、目的性限缩及有利解释。

## 5. 政策/后果复核
仅在法律解释完成后作实质复核，不得创造新构成要件。

## 6. 输出
ElementMatrix / InterpretationReview / AlternativeCharacterization / ExculpatoryPath / Provisional 分析结果 / 人工复核 Points。

## 审查起诉辩点披露策略

## 1. 进入 门控
必须已有最新会见、全卷/缺口状态、证据 分析结果、罪名分析、现行法 研究。

## 2. 意见 矩阵
逐罪/逐问题/争点记录：issue / desired result / 事实 / 证据 / law / counterarguments / 来源 locator / maturity。

可组合结果：不起诉、变更定性、减少罪名、事实/数额缩减、非法证据、罪轻/量刑、强制措施、财产。

## 3. 时机 门控
- **法律解释争议：** 默认可更早、更反复沟通。
- **事实/证据缺口争议：** 先评估补侦可能、控方可否补强、披露是否泄露辩方独有线索、阶段目标和未来庭审价值。
可能帮助补强控方 → `HUMAN_REVIEW_REQUIRED`。

## 4. 提交
重大辩点保留：明确结论、证据原文/准确摘要、卷页、法律依据、类案法律用途、反向材料、来源缺口。

## 5. 沟通
书面 + 正式沟通；记录提交时间、接收、承办人关注点、反馈和后续任务。

## 6. 认罪认罚
是否认罪认罚由当事人最终决定；律师提供 证据 / offense / current law / consequence / options / uncertainty。

- 专业法律判断由律师独立形成；认罪、辩护基本立场等重大个人决定记录当事人真实意思。

- 保密、退出、披露义务等具体边界不硬编码旧版本或二手资料，动态核验现行法与职业规范。

## 会见检查清单

## 0. 输入门控
Role / 阶段 / Urgent 期限 / Known offense / 当前-law pack / Prior meeting / File 审阅 状态。

## 1. 信息状态
- **无卷宗：** 会见目的为获取 ALLEGED 事实 + 程序事实 + 权利风险 + 证据线索；不得最终定性/刑期预测。
- **已有卷宗：** 对照卷宗核实差异、遗漏、证据解释和策略选择。

## 2. 提问顺序
1. 先自由陈述；
2. 程序/强制措施；
3. 指控核心行为；
4. 主观认识/目的（问事实，不直接问法律结论）；
5. 人员/时间/地点/资金/通信/物品；
6. 提审与笔录形成；
7. 有利/不利证据线索；
8. 陈述变化及原因；
9. 当前需求和重大决策。

## 3. 事实 状态
- 新信息：`ALLEGED`
- 独立核验：`VERIFIED`
- 与卷宗冲突：`DISPUTED`

## 4. 预测门控
信息不完整时只允许条件性法律解释、风险范围和补证事项；禁止结果承诺或精确刑期。

## 5. 风险门控
涉及传递案件信息/物品、隐匿证据、串供、秘密/隐私、诱导虚假陈述时，触发 人工复核 / 人工升级。

## 6. 输出
MeetingRecord / 事实记录（FactRecord）[] / Contradiction[] / EvidenceLead[] / Procedural问题/争点[] / 现行法 Questions[] / Follow-up Tasks。

## 证据分析检查清单

## 1. Proof 对象
先分：定罪 / 量刑 / 涉案财物 / 程序 / 证据合法或真实性事实。

## 2. 单项证据 Validator
来源 / 来源定位 / Authenticity / Collection Legality / Relevance / Reliability / Completeness / Chain / Proposition / Contradictions。
**不合并成总分。**

## 3. Confirmation + Falsification
每个关键命题必须记录：confirming 证据 / falsifying 证据 / missing expected 证据 / 备选 hypothesis。

## 4. Corroboration
声称“相互印证”前检查：
- 来源独立性；
- 是否同源转述；
- 形成时间；
- 先验知情/诱导；
- 关键一致点；
- 关键冲突点。

## 5. Statement Validator
供述/证言检查：形成条件、自愿性/合法性、前后变化、大段逐字重复异常、横纵比较、客观印证、提及但未调查线索。

## 6. Indirect 证据
`evidence → atomic fact → intermediate inference → intermediate fact → ... → ultimate proposition`
每一箭头都问：为什么成立？有无现实替代解释？

## 7. Reasonable Doubt
必须基于 证据 / logic / experience，并产生现实的无罪或罪轻可能性。

## 8. 输出
Proof Proposition 图 / 证据 矩阵 / Contradiction 矩阵 / Inference Chain / 应出现但缺失的证据 / Alternative Hypothesis / 证据 分析结果。

## 阅卷检查清单

## A. Completeness（完整性）
- 全卷或完整目录；
- 缺卷/缺页/不可读记录；
- 卷号—材料—页码索引；
- 与前一阶段版本做 Diff；
- 所有缺失形成 来源缺口。
**禁止：** 因预设辩点选择性不复制。

## B. First Pass（控方地图）
起诉意见/起诉书 → 指控事实 → 罪名/要件 → 控方命题 → 关键证据 → 程序来源。

## C. Second Pass（全面证据）
每项进入 证据对象（EvidenceItem）：来源 / locator / proposition / authenticity / legality / relevance / reliability / 完整ness。

## D. Focus Pass（辩护假设）
每个假设必须有：支持材料 / 反向材料 / 证据缺口 / 备选 explanation / current-law issue。

## E. Comparison（比对）
按需建立：
- 同一人口供纵向表；
- 同案人员横向表；
- 时间线；
- 金额/资金流；
- 通信/位置；
- 证据发现时间链。

## F. 会见回路
卷宗与会见不一致 → 回会见核实；新会见信息 → 回卷宗/调查/研究核实。

## G. 停止条件
只有全卷状态、控方证明链、支持/反向证据、关键矛盾/缺口、现行法 问题/争点 均显式，才允许进入较稳定 Defense 分析结果。

## 一、适用范围

本工作流适用于：
- 被害人或近亲属的刑事代理；
- 刑事控告、报案；
- 不予立案、立案后久拖未决等情形下的程序核验与救济分析；
- 立案监督相关工作；
- 刑事程序中的追赃、退赔、涉案财物和附带民事衔接；
- 进入审查起诉或审判后的被害人参与和代理。

它与辩护工作流共享事实、证据、法律研究和论证能力，但**证明目标、程序位置和策略方向独立**，不得把辩护逻辑机械反转后使用。

## 二、主流程

```text
确认委托角色与客户目标
→ 建立损害、交易和行为事实模型
→ 识别可能的刑事法律路径及民刑边界
→ 构建控告待证命题
→ 结构化审阅现有材料并建立证据包
→ 识别证据缺口、保全需求和调查路径
→ 核验管辖、受理和程序前提
→ 形成控告/报案材料与附件索引
→ 跟踪立案/受理状态并分析补充材料需求
→ 必要时进入立案监督或其他救济路径
→ 立案后转入被害人代理、追赃挽损和程序参与
→ 形成阶段交付和Resume Capsule（续接/交接摘要）（仅续接/交接/归档需要时）
```

## 三、客户目标与案件目标

控告侧不能默认“立案”就是唯一目标。开始前至少确认：
- 客户主要目标是追究刑事责任、制止持续侵害、挽回损失、追赃退赔，还是保存证据；
- 是否存在民商事、行政、劳动、执行或其他并行路径；
- 是否存在紧急财产、证据灭失、人身安全或持续侵害风险；
- 客户是否有不可逆或高风险诉求，需要律师明确提示边界。

## 四、事实模型

从客户陈述和材料中重构：
- 主体、身份、关系和控制结构；
- 行为过程、交易过程或侵害过程；
- 时间、地点、金额、财物和沟通；
- 主观认识与目的的事实基础；
- 财产流向、获利、损失和结果；
- 前后行为及后续处置；
- 已有民事、行政、仲裁或其他程序；
- 已向公安、检察或其他机关提交过什么材料、收到什么文书或口头反馈。

客户陈述默认 `ALLEGED`。材料能够支持到什么程度，应逐项记录，不允许把“客户认为被骗/侵占/敲诈”等法律评价直接写成已证实的犯罪事实。

## 五、刑事路径与民刑边界

对每个拟主张罪名或刑事法律路径建立：
- 构成要件；
- 需要证明的核心事实；
- 当前支持材料；
- 反向事实和材料；
- 证据缺口；
- 与民商事争议、行政违法或一般违约的边界；
- 是否存在其他竞争性定性。

必须执行反向检查：

> 如果不成立犯罪，现有事实最可能被解释成什么？

并说明哪些事实或证据能够区分不同解释。

## 六、控告待证命题

控告材料不能只有“事情经过”。应把案件拆成可被侦查机关核查的命题，例如：
- 某主体实施了什么行为；
- 行为对象和结果是什么；
- 哪些事实支持主观方面；
- 财产或利益如何流转；
- 损失如何形成；
- 共同参与者之间如何分工；
- 哪些事实目前只有陈述，哪些已有客观材料支持。

每个重要命题连接：`FactRecord → EvidenceItem → SourceLocator`。

## 七、证据包与结构化审阅

材料较多时必须加载 `references/capabilities/facts.md`（Facts Capability）并使用结构化审阅。控告侧至少形成：
- 材料目录；
- 时间线；
- 主体/关系表；
- 资金或财物流转表（如适用）；
- 待证命题—证据矩阵；
- 有利/不利材料；
- 矛盾和信息缺口；
- 需要机关调取而当事人难以取得的证据线索；
- 证据保全事项。

不得以“材料很多”为由把全部附件无结构地堆给办案机关。

## 八、证据保全与调查

对可能灭失、变化或被覆盖的电子数据、监控、平台记录、资金记录、物流记录、鉴定对象等，及时识别保全必要性。

律师自行调查、申请调查或建议当事人保存材料前，应检查合法性、隐私、商业秘密、个人信息和其他职业风险。

## 九、管辖、受理与提交策略

具体管辖、受理标准和程序规则必须运行时核验。分析时至少记录：
- 拟提交机关及理由；
- 犯罪行为地、结果地、主体所在地等与管辖有关的事实；
- 是否已经向其他机关提交；
- 是否存在重复、移送或程序衔接问题；
- 提交时需要的核心材料和附件索引；
- 当前尚未取得但可说明线索的材料。

控告材料应围绕可核查事实和证据组织，不用情绪化、结论先行或夸大措辞替代证明。

## 十、立案状态与监督/救济

提交后区分：
- 已接收材料；
- 是否有受案/接报案记录；
- 是否作出立案、不予立案或其他程序处理；
- 是否要求补充材料；
- 是否存在程序期限或后续救济问题。

需要立案监督或其他救济时，重新分析：
- 原提交的事实和证据是否足以支持调查必要性；
- 机关不立案或不处理的理由；
- 是否存在新的证据或法律问题；
- 当前最有效的程序路径。

不得把“没有立案”直接等同于“案件不构成犯罪”，也不得把“客户坚持”当作继续升级程序的充分理由。

## 十一、立案后的被害人代理

立案后根据程序阶段切换工作重点：
- 继续补充、核验被害人侧事实和证据；
- 关注程序性权利和信息获取；
- 对定性、证据、损失、涉案财物和追赃退赔形成意见；
- 对可能影响被害人利益的程序决定进行分析；
- 审查起诉和审判阶段准备代理意见、质证或财产主张；
- 需要时与附带民事、另行民事或执行路径协调。

## 十二、追赃挽损与财产路径

财产问题独立建模。至少记录：
- 损失项目和计算基础；
- 涉案财物流向；
- 已查封、扣押、冻结或控制的财产；
- 第三方权利；
- 追缴、退赔、返还、附带民事或其他路径；
- 事实和法律依据状态；
- 仍需核验或调查的财产线索。

## 十三、对抗性审查

正式提交重要控告材料前，至少反向检查：
- 该事项最强的“民事纠纷/行政违法/证据不足/主体不符”解释是什么；
- 是否把推断写成事实；
- 是否只有客户单方陈述；
- 关键主观要件是否只有结果倒推；
- 损失、资金流、主体身份是否有客观来源；
- 是否存在明显矛盾或对客户不利材料未处理；
- 是否为了追求立案而扩大或错误解释罪名；
- 当前还缺什么材料才能让机关有效核查。

## 十四、主要产出

- 客户目标与程序路线图；
- 事实时间线和主体关系；
- 通用结构化审阅表；
- 控告待证命题—证据矩阵；
- 民刑边界与竞争定性分析；
- 证据缺口与保全计划；
- 控告/报案材料及附件目录；
- 立案状态与补充材料清单；
- 立案监督/救济分析；
- 被害人阶段代理意见；
- 追赃挽损与涉案财物分析；
- Resume Capsule（续接/交接摘要）（仅续接/交接/归档需要时）。
