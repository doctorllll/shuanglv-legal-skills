# 爽律skill｜安全更新说明（v0.51）

> 本文件适用于安装、升级、更新、迁移或替换爽律skill正式运行层。  
> **核心原则：只替换已确认属于官方程序层的文件；用户资产和归属不明文件默认保护。**

## 1. 先区分程序层与用户层

### 官方程序层（CORE_OFFICIAL）
只有能够由当前正式版本清单、Manifest、正式仓库路径或可信安装记录确认属于爽律skill官方发布内容的文件，才可以作为程序层处理，例如：

- `SKILL.md`；
- 官方 `references/`；
- 当前版本明确列入正式运行层的许可、Manifest 与运行资源；
- 当前正式成果包明确列出的官方用户文档。

### 用户层（PRESERVE_USER）
以下内容默认属于用户资产，不得因版本升级被静默删除、覆盖或重置：

- 用户模板、House Style、格式习惯；
- 默认法域、信源偏好、核验强度、敏感材料处理边界；
- AUTO / CONFIRM / MANUAL 等激活偏好；
- 用户自行创建或修改的配置；
- Matter State、Resume / 续接信息、案件或事项资产；
- 用户知识、用户自建文件及其他用户长期工作资料。

### 归属不明（UNKNOWN）
**Unknown = Preserve。** 无法证明属于官方程序层的文件，不得按“旧文件”直接删除。应当保留、迁移，或在无法安全处理时阻断更新。

## 2. 禁止默认“整目录删除后重装”

不得在尚未完成资产识别和保护之前，把以下方式作为默认更新流程：

```text
递归删除整个爽律skill安装目录
→ 重新下载新版
→ 覆盖完成
```

只有在已经实际核验该目录完全由官方程序文件组成、没有用户资产且没有 UNKNOWN 文件时，才允许整体替换该程序目录。

## 3. 标准安全更新流程

1. **识别安装位置和当前版本。** 找到真实安装目录、运行入口与当前 Manifest；不能确定时先停止破坏性动作。
2. **读取官方文件清单。** 以当前正式版本的 Manifest / 正式包清单识别已知程序文件。
3. **扫描现有安装目录。** 将文件分成 `CORE_OFFICIAL / PRESERVE_USER / UNKNOWN`，形成 `UserAssetInventory`。
4. **确定替换边界。** 只把已确认官方程序层纳入替换集合；用户资产和 UNKNOWN 不得进入删除集合。
5. **先保护再修改。** 用户资产若位于待替换路径内，必须先备份或迁移到独立安全位置，并验证备份真实存在、可读取。
6. **执行程序层更新。** 删除或覆盖仅限已确认的官方程序文件；再安装最新正式版运行层。
7. **迁移/恢复用户资产。** 按新版路径恢复模板、偏好、配置、Matter/Resume 和用户文件；新版改变目录结构时只改变程序映射，不得顺手清除用户资产。
8. **验证新版程序。** 核对版本号、`SKILL.md`、Manifest、必要 references 与运行入口真实存在且可读取。
9. **验证用户资产。** 至少核验模板、偏好/配置、Matter State/Resume、用户自建文件仍存在且可访问。
10. **通过后才报告成功。** 只有程序与用户资产两类校验均通过，才可以表述“更新完成”。
11. **最后再清理临时备份。** 用户资产验证未通过、仍需人工确认或回滚窗口尚未关闭时，不得提前删除备份。

## 4. 失败、权限不足与回滚

- 无法区分程序层与用户层：**BLOCKED，禁止删除。**
- 无法建立或验证用户资产备份：**BLOCKED，禁止进入破坏性修改。**
- 写权限不足：在任何删除/覆盖动作之前停止，不得“先删后报错”。
- 新版安装成功但用户资产恢复或验证失败：保留升级备份，优先回滚；无法自动回滚时明确报告人工恢复路径，不得声称成功。
- Host 不具备真实文件读写、备份、校验能力：说明限制并停止在可验证边界，不伪造更新结果。

## 5. 用户明确要求“全删重装”时

用户的更新目标不等于授权丢失未知用户资产。若目录中发现用户资产或 UNKNOWN 文件，应先告知保护结果并转为安全迁移；除非用户在已知具体风险和具体文件范围后再次明确授权删除，否则不得把模糊的“重装”解释成删除全部用户文件。

## 6. 更新完成后的最小报告

向用户至少说明：

- 原版本与新版本；
- 实际替换的官方程序范围；
- 检测到的用户资产和 UNKNOWN 类型；
- 是否发生备份、迁移、恢复或回滚；
- 模板、偏好/配置、Matter/Resume 与用户文件的验证结果；
- 是否存在仍需人工处理的异常。

“已经下载新版”“已经解压”“版本号变了”均不足以单独证明更新成功。

## 7. 与其他爽律skill规则的关系

- 用户资产的长期偏好/模板语义继续由 `references/preferences/legal-work.md` 与 `references/guards/migration-assets.md` 管理；
- 删除、覆盖、写入等具有状态改变的动作仍受 `references/guards/side-effect-authorization.md` 约束；
- 本文件专门拥有**爽律skill自身安装/更新时的资产识别、保护、迁移、校验和成功声明条件**；
- 更新任务不得因为追求速度而绕过上述保护规则。
