# 外部能力适配示例

> 本示例只说明爽律 Skill 如何与外接数据库、用户知识库和文件工具协同，不代表任何具体产品或 Agent 的真实能力。

## 任务

> 代表被告处理一宗多文件合同争议；需要核验现行法、检索类案、结合用户自己的历史合同知识库，最终输出 DOCX。

## 爽律 Skill 应识别的能力需求

1. **法律权威信源**：现行法和效力核验；
2. **案例信源**：类案检索与比较；
3. **用户私有知识库**：历史合同、内部模板或既往工作成果；
4. **文件读取能力**：多份合同、聊天、流水等结构化审阅；
5. **DOCX 输出能力**：最终正式交付。

如果文件中存在扫描件，再增加 OCR 能力需求；如果用户明确要求原生 Track Changes，再增加原生修订模式能力需求。

## 调用逻辑

```text
执行计划
→ 读取 RuntimeCapabilityProfile
→ capability-check
→ 法律信源满足：继续现行法核验
→ 案例信源满足：形成 CaseMatrix
→ 用户知识库满足：检索并保留文档定位
→ 文件能力满足：进入结构化审阅
→ DOCX 能力满足：正式交付
```

## 关键边界

- 历史合同中写过某条款 ≠ 当前法律要求；
- 用户知识库里的旧法律意见 ≠ 当前有效法律；
- 数据库搜索摘要 ≠ 已核验原文；
- OCR 抽取的日期和金额 ≠ VERIFIED；
- “能够导出 DOCX” ≠ “能够原生 Track Changes”；
- 任何能力若实际不可用，应降级或阻断，而不是通过文字假装完成。

## 推荐的公共对象落地

```text
数据库 / 官方来源
→ SourceCard + SourceLocator + LegalRule / CaseCard

用户知识库
→ SourceCard + SourceLocator

文件 / OCR
→ MaterialRecord + LegalObjectCandidate

正式输出
→ OutputContract + CapabilityInvocationRecord
```

这样外部产品只负责提供数据或工具，爽律 Skill 继续负责法律分析方法、工作流、质量门控和全链路溯源。
