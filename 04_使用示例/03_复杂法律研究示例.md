# 使用示例三：复杂法律研究

## 用户怎么说

> 调用爽律研究这个问题。我不需要只支持我的观点，要把现行法、权威案例、反向案例、例外和争议都查出来，并告诉我哪些地方还不能确定。

## 爽律 Skill 内部怎么路由

```text
爽律 Skill入口
→ 主技能：法律研究与多源资料融合
→ 正式研究报告需要时：辅助法律文书质量与格式控制
```

## 核心工作步骤

1. 把用户的宽泛问题拆成可验证的子问题；
2. 确定法域、时间、关键事实和研究目标；
3. 根据事实设计多条独立检索路径；
4. 先核验现行法律规范及时间效力；
5. 检索案例并比较法律争点、决定性事实、法律版本和裁判理由；
6. 检索专业观点，但不把观点代替法源；
7. 主动进行反向检索：反向案例、例外、边界、不同解释；
8. 发现关键事实缺口时返回业务问题，明确还需要什么事实；
9. 判断研究是否达到当前任务所需的充分程度；
10. 形成初步结论后执行统一对抗性审查；
11. 对仍然存在的来源缺口或冲突降低确定性，不强行给唯一答案。

## 预期产物

- 研究问题树；
- 当前有效法律规范；
- 重要案例及比较；
- 支持观点；
- 反向观点；
- 例外和适用边界；
- 关键事实需求；
- 来源定位；
- 尚未解决的研究缺口；
- 当前结论及其确定程度。

## 爽律 Skill 与普通“联网搜索”的区别

爽律 Skill 不是“搜到几个结果就总结”，而是把问题拆解、信源分层、现行法核验、类案区分、反向检索和研究停止判断串成一个完整研究工作流。
