# 跨模块执行与回写示例

本示例只演示爽律 Skill 如何把**业务问题 → 法律研究 → 论证 → 策略选项 → 对抗性审查 → 人工决定 → 回写**串起来，不表达任何真实案件的实体法律结论。

## 一、为什么需要跨模块执行

如果各模块彼此独立，常见问题是：

- 业务技能提出一个问题，法律研究另写一篇报告，但没有回填原争点；
- 对抗性审查发现问题，只在末尾增加“风险提示”，原结论仍不变化；
- 用户已经选择策略，但后续文书仍沿用选择前的旧方案；
- 新材料改变事实状态，旧 `Finding` 仍继续被引用。

因此，本示例使用稳定对象 ID 交接，并用 `WriteBackEvent` 记录结论变化。

## 二、示例链条

```text
IssueRecord ISSUE-01
    ↓
ResearchRequest RR-01
    ↓
ResearchResult RES-01
    ↓
发现初步论证需要修订
    ↓
WriteBackEvent WB-01
    ↓
ARG-01 → ARG-02
FIND-01 → FIND-02
    ↓
OptionRecord OPT-01 / OPT-02
    ↓
AdversarialReviewRecord ADV-01
    ↓
修订后的策略比较
    ↓
DecisionRecord DEC-01
    ↓
用户明确决定后继续正式交付
```

## 三、研究不是孤立报告

`RR-01` 明确绑定 `ISSUE-01`。`RES-01` 返回后标记 `writeback_required = true`，因为研究结果改变了初步论证所依赖的法律条件。

因此，不能简单把研究报告附在案件分析后面，而应修订：

- 原 `ArgumentRecord`；
- 原 `Finding`；
- 后续策略选项；
- 需要时的最终交付命题。

## 四、对抗性审查必须产生后果

`ADV-01` 不是“再写一个反方段落”。它冻结 `FIND-01` 和 `ARG-01`，建立最强反方路径，然后形成 `ARG-02` 和 `FIND-02`。

如果审查后仍维持原结论，则应使用 `COMPLETE_UNCHANGED_WITH_REASON` 并留下明确理由；不能无记录地保持不变。

## 五、策略推荐不等于用户决定

示例形成两个选项：

- `OPT-01`：优先路径；
- `OPT-02`：备选路径。

由于该选择被设定为 C 级事项，系统再建立 `DEC-01`。只有用户明确决定后，`DecisionRecord` 才进入 `RESOLVED`。

## 六、机器检查

支持 Python 的环境可运行：

```bash
python "05_工程执行层/工具/爽律 Skill执行器.py" chain-check \
  --bundle "04_使用示例/07_跨模块执行与回写示例.json"
```

该检查只检查：

- 研究请求和研究结果是否能回到问题；
- 选项和决定是否引用有效对象；
- 对抗性审查是否真正修订或说明维持理由；
- 需要回写的研究结果是否存在 `WriteBackEvent`；
- 是否仍有未解决的 C 级决定或开放回写事件。

它不判断示例中的法律观点是否正确。
