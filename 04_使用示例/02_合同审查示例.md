# 使用示例二：合同审查

## 用户怎么说

> 调用爽律审查这份合作协议。我代表甲方。重点不是给我列风险，而是把合同改到可以谈、可以履行、发生争议时也能执行。最后要修订稿和清洁稿。

## 爽律 Skill 内部怎么路由

```text
爽律 Skill入口
→ 主技能：合同与交易工作
→ 如涉及现行监管/特别法：辅助法律研究与多源资料融合
→ 正式输出：辅助法律文书质量与格式控制
```

## 核心工作步骤

1. 确认代表甲方、交易目的、谈判地位和最终交付形式；
2. 先理解交易结构，不直接从第一条开始改；
3. 还原履行流程：谁、何时、做什么、交付什么、如何确认、如何付款；
4. 建立权利义务闭环和责任闭环；
5. 模拟对方违约、我方违约、第三方失败、审批失败、验收争议等场景；
6. 把风险映射到具体条款功能；
7. 核验适用的强制性法律和特别规则；
8. 逐条修改，必要时给首选文本与备选文本；
9. 做合同对抗性审查：假设自己是对方律师，寻找最容易利用的定义、单方权利、不可执行责任和证明漏洞；
10. 根据对抗结果重新修改；
11. 做宏观—中观—微观质量检查；
12. 按当前 Agent 的文档能力生成原生修订/差异稿、批注、清洁稿；如能力不足必须披露降级。

## 预期产物

- 交易结构和履行流程；
- 主要风险场景；
- 关键条款问题；
- 修改理由；
- 首选/备选条款；
- 修订稿；
- 清洁稿；
- 需要客户决定的商业事项；
- 签署与履行交接提醒。

## 爽律 Skill 与普通“合同风险提示”的区别

爽律 Skill 不把合同理解成风险清单，而是从交易结构、履行闭环、双向失败场景和可执行性反推条款。
