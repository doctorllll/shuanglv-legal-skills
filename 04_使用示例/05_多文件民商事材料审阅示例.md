# 使用示例五：多文件民商事争议材料审阅

## 用户怎么说

> 调用爽律处理这个合同纠纷。附件有主合同、三份补充协议、几十页聊天记录、付款流水和两版对账单。我方准备起诉，先不要直接写起诉状。

## 爽律 Skill 怎么路由

```text
主技能：民商事争议解决
→ 通用结构化审阅
→ 事实建模
→ 请求/抗辩与要件争点
→ 证据和证明责任
→ 必要的法律研究
→ 策略
→ 最后才进入文书
```

## 结构化审阅不是逐份摘要

每份材料至少记录：来源、时间、主体、关键事项、事实贡献、不利内容、冲突、来源定位、关联问题和下一步动作。

随后横向比较：
- 合同与补充协议的版本关系；
- 聊天内容与书面条款是否冲突；
- 付款流水与对账单是否一致；
- 哪些事实由多份独立材料支持；
- 哪些所谓“印证”其实来自同一信息源；
- 哪些关键履行事实仍没有材料支持。

## 后续分析

结构化审阅结果进一步进入：

> 事实记录 → 请求/抗辩矩阵 → 要件—争点矩阵 → 举证责任与证据矩阵 → 程序与保全 → 诉讼策略。

这样正式起诉状来自已经形成的案件模型，而不是让模型直接从大量附件中自由发挥。
